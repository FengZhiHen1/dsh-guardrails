# dsh-guardrails 部署与安装

本文规定插件的交付形态、通用安装契约和发布前置验证门禁。配置键的定义不归本文拥有，见[规则模型](规则模型.md)「配置模型」节。本文是设计文档：它描述目标交付与验收判据，不记录过去某次安装的现场命令或结果。

## 交付形态

插件按 DSH 官方「组合包（bundle）」范式交付。组合包是一个附带配置层的 npm 包，其 `package.json` 在 `dsh.bundle` 下声明 patch 文件（`dsh.bundle.patch`），patch 是插入或覆盖插件行的 YAML 数组。本包应插入一行 `{ id: guardrails, name: dsh-guardrails }`；该行**不带 config**，默认值属于插件 config boundary（导出的 Schemastery `Config` schema 的 `.default()`）。

- 库代码与客户端：Host 经根入口载入，浏览器半侧由 `dsh.client` 声明并通过 `./client` 导出。
- 包的实际导出与文件清单以发布的 `package.json` 为准。
- 组合包支持的 DSH 版本用 `engines.dsh` 的 SemVer 范围声明；未声明时按 `@deepseek-ai/dsh*` peer 依赖范围判定。目标宿主版本见[技术栈设计](../技术栈设计.md)「运行时与关键库」。

以上 bundle manifest、patch 形式、`engines.dsh` 与 peer 回落规则来自 DSH 0.2.2-rc.2 官方《打包与安装插件》文档。

## 引入方式

`dsh plugin --profile <name> <args>` 在 profile 内转发给 pnpm，最终把包追加进 `dsh.profile.bundles`。按交付来源区分：

- **registry 包**：安装已发布、已构建的版本（`dsh plugin --profile <name> add dsh-guardrails`）。发布物应携带构建好的入口，用户无需在安装时执行构建。
- **`github:` 依赖**：钉 commit/ref 的 git 依赖（`github:<owner>/<repo>#<sha>`）。git 安装拉取的是源码而非构建产物；若包需要构建，作者须提供自包含的 `prepare` 脚本，用户须在 profile 的 `pnpm-workspace.yaml` 中显式授权该包的构建脚本（`allowBuilds`）。此项授权等同允许该包代码在安装时于本机执行，只对可信来源授予并锁定 commit。
- **本地 checkout**：用于隔离试验，安装的是源码 checkout。与宿主共享实例的 DSH 包须同时声明在 `peerDependencies` 与 `devDependencies` 中；该形式不作为发布与稳定环境的分发方式。
- **tarball**：`pnpm pack` 打包后直接安装 tarball，无需构建授权，也不依赖 registry。

发布与稳定环境使用 registry 预构建包、`github:` 钉 ref 加构建授权，或 tarball；不把源码 checkout 直挂当作交付。

## 通用安装契约

1. **满足运行时前置**：目标 profile 使用的 DSH 版本满足组合包的 `engines.dsh`（或 peer）范围。具体版本锚点见[技术栈设计](../技术栈设计.md)。
2. **安装插件行**：`dsh plugin --profile <name> add <spec>`，其中 `<spec>` 为 registry 包名、`github:owner/repo#sha`、tarball 路径或（仅隔离试验）本地 checkout。
3. **核对层**：用 `dsh --profile <name> --dump-config` 查看该 profile 的生效配置，确认出现本包的 patch 层、来源正确、无重复行、无 `disabled`、无源码解析残留。`--dump-config` 是 DSH 官方的层检视入口，后应用的层按行胜出并替换整行 `config`，因此用户覆盖某键时须按 id 重述该行。
4. **配置（可选）**：在 profile 层的 `cordis.patch.yml` 中按 `id: guardrails` 覆盖配置键。键名、语义与非法值处置见[规则模型](规则模型.md)「配置模型」，本文不复述。

层叠加顺序（组合包 patch 按列表顺序，然后是 profile 自己的 `cordis.patch.yml`，再是 home 级与 `--patch` overlay）由 DSH 官方规定；本包不假定其他层的行为。

## 配置页面

配置页使用 DSH 官方设置入口与 `form.state`/`form.mutate` 状态契约读写运行期活值；复制官方 `SettingsForm`/`fields` 的字段几何与保存语义，未修改或输入非法时禁用保存，样式只用主题 token。本插件不 import 任何 Harness Client 包。

## 发布前置验证门禁

发布或更新稳定环境前，须通过以下通用判据。这些判据是发布的前提；构造与单元测试通过不等于部署完成。

1. **交付物自洽**：发布包内容与 `package.json` 声明一致，含构建入口、`cordis.patch.yml` 与随包分发的解析器资产及其校验元数据；`engines.dsh`（或 peer）范围与目标宿主实际版本相符。
2. **组合层正确**：目标 profile 的 `--dump-config` 恰有一行 `id: guardrails`、来源为发布物形态（registry / `github:` 钉 ref / tarball），无重复行、无源码解析残留、无 `disabled`。
3. **启动无静默禁用**：实例启动期无未激活告警或加载失败，guardrails 行确实达到激活状态。
4. **功能冒烟**：用合成目标验证数据破坏、凭据与敏感信息、不可控执行三面的可观察结果，与[需求](../需求.md)和[规则模型](规则模型.md)（DSR-025 三档、DSR-027 统一分析契约）一致。可验证的删除按删除分档处置；受保护文件的内容操作触发限时确认并列出范围；执行面按目标策略验证等价操作、带已知范围的风险候选、无风险证据的覆盖缺口，以及必检调用缺少有效结果时的拒绝；MCP 等未接入工具沿用 DSH 权限流程放行。危险命令只用模拟或隔离 fixture。
5. **平台覆盖**：在声明的交付平台上实跑并记录；文件存在或打包成功不代表该平台已运行通过。平台清单见[技术栈设计](../技术栈设计.md)「平台与交付约束」。

门禁结果是发布的前提。真实实例冒烟属现场操作，须在具备授权与隔离条件的环境中进行，并单独记录失败、跳过与覆盖限制。
