# dsh-guardrails 部署

## 权威范围

本文唯一拥有 `dsh-guardrails` 的包形态、部署红线、安装与验证命令、生效流程、测试体系与发布路径。需求归 `../需求.md`，规则机制归 `规则模型.md` 与 `命令文本分析.md`。

## 结论先行

按 DSH 官方 Bundle 范式交付：包内声明 `dsh.bundle.patch` 并携带 `cordis.patch.yml` 安装层，profile 用官方 CLI（`dsh plugin add`）安装并自动对账 `dsh.profile.bundles`。部署红线（AGENTS.md）：**test 源码直挂，web 只吃发布包**；任一 profile 禁止 bundle 层与用户 patch 层重复 insert 同一行（重复 id 导致整个 profile 启动失败）。

## 包形态

`plugins/dsh-guardrails/`（仓库内唯一源码，submodule）：

- `package.json`：`name: dsh-guardrails`，`dsh.bundle.patch: ./cordis.patch.yml`，`dsh.client`（platform web，inject runtime/ui-settings/ui-primitives），`exports["./client"] → ./src/client/card.js`，`files: [index.js, src/, cordis.patch.yml]`，`engines.node: ^22.19.0 || >=24`；核心包**一律不写 `dependencies`**（v1.4.0 起，此前 `@deepseek-ai/schemastery` 曾挂在 deps，会在 profile 落一份冗余物理副本）：`peerDependencies` 声明 `@deepseek-ai/cordis` + `@deepseek-ai/dsh-settings` + `@deepseek-ai/schemastery`，其中装载期真正 import 的 `schemastery` 另列同版本 `devDependencies`（`src/adapter/host.js` 需要，裸 node 单测才能解析；profile 侧因自身 `autoInstallPeers: false` 不会装回）。前两者不在装载期 import，故无需 devDeps。危险等级分类见知识库 `04` §7。
- `cordis.patch.yml`：随包分发的安装层，`insert` 一行 `{ id: guardrails, name: dsh-guardrails }`——**行不带 config**：默认值属于插件 config boundary（导出的 Schemastery `Config` schema 的 `.default()`，DSH 官方范式，见 DSR-006/规则模型.md 配置模型）；用户覆盖在该行基础上按 `id: guardrails` 合并。行 `name` 与包名一致供 Node 模块解析，行 `id` 是稳定身份供 profile 层覆盖。
- `index.js`：包根薄转发（`export * from src/adapter/host.js`）。适配层 `src/adapter/host.js` 是官方插件形态——具名导出 `name` / `inject` / `Config` / `apply(ctx, config)`（无 default export），注册 `ctx.tools.guard` 钩子；settings 命名空间经官方 `installSection` 接线（行 config 为 base 层，用户设置覆盖并热生效，provider detach 回落行配置，v1.4.0 起）。
- `src/client/card.js`：浏览器半侧（`dsh.client` 声明，`exports["./client"]` 直指）——DSH client 模块系统的惰性 CJS bundle，向 `settings.plugin.item` 注册配置卡片，与同名 settings 命名空间配对（官方"新增设置卡片"范式，v1.3.0 起；v1.4.0 迁入 `src/client/`）。
- `src/core/`：功能层六模块（纯领域逻辑，禁 `@deepseek-ai/*` import，仓库分层门禁强制）；目录与职责详表见 `工程结构与测试体系.md`。
- `test/`（`*.test.mjs`）：规则矩阵、命令解析、生命周期、settings seam 与基准目录（DSR-007）测试。

## 部署红线（AGENTS.md 固化）

- **web（稳定）profile**：绝对拒绝源码直挂——插件只能来自已发布 npm 包（registry 版本）。禁止 `link:`/`file:` 指向源码、junction/symlink 指向源码（含 `profiles/node_modules` 共享解析层）、patch 层用源码路径引用插件行。流程：修改插件 → 打包发布 → `dsh plugin --profile web add <已发布包>`。
- **test（试验）profile**：允许源码直挂（`link:` 依赖，符号链接实时可见），用于快速验证；源码改动重启即生效。
- **任一 profile**：同一插件禁止在 bundle 层与用户 patch 层重复 insert（同 id 重复行 → `duplicate loader entry id`，profile 启动失败）。覆盖 bundle 行配置用 id-targeted override，不再 insert。

## 安装与验证

CLI 一律用**实例版本二进制**（AGENTS.md 跨代红线）：`node tools/dsh-launcher-cli/cli.mjs env --json` 现查 `instances[].version_bin`（下文 `$DSH_BIN`）；实例 HOME 现查 `instances[].home`（test 实例与 stable-dev 实例分属不同 HOME，校验时以 `DSH_HOME=<对应 home>` 前缀调用）。

```sh
# test：源码直挂（link: 依赖 + bundles 自动对账；在 test 实例 HOME 下执行）
$env:DSH_HOME='<test 实例 home>'; node $DSH_BIN plugin --profile test add E:/Project/DSH_Plugins/plugins/dsh-guardrails

# 部署后必查（AGENTS.md）：无重复插件行、无源码解析残留
$env:DSH_HOME='<test 实例 home>'; node $DSH_BIN --profile test --dump-config
$env:DSH_HOME='<stable-dev 实例 home>'; node $DSH_BIN --profile web --dump-config
```

预期结果：test 与 web 的 dump 各出现 `# == dsh-guardrails` 层且恰一行 `id: guardrails / name: dsh-guardrails`，解析自 `dsh-guardrails` 包；web 依赖为发布物形态（当前 `github:` git 依赖，lockfile 承载 resolution；发布后切换 registry）。test 的 `node_modules/dsh-guardrails` 为符号链接指向仓库。

## 生效流程

- test：编辑源码 → 重启 test profile 即加载（符号链接直挂，无需重装）。
- web：当前以 `github:` git 依赖挂载（源码仓库 `FengZhiHen1/dsh-guardrails`，pnpm 克隆进 store 的只读快照，lockfile 的 resolution 钉 commit）；源码更新须先 push 到该仓库再重新 add（推荐钉新 commit ref）；发布后切换 `dsh plugin --profile web add <registry 版本>`。

## 测试体系

`node --test test/*.test.mjs`（Node `^22.19.0 || >=24`）用 mock ctx 直接驱动 guard 钩子：

- 不触碰文件系统、不 spawn 进程（`node --test` 的运行器需子进程，沙箱内需提权运行）。
- 覆盖：误伤消除（列举 .dsh/.git/.env 放行、`.dsh` 读/写放行）、防护保持（凭据/破坏性全拦）、列举模式边界（重定向、混合命令）、配置开关、R0/W0 新增类别用例、生命周期（mount/dispose/remount、HMR 重放、非法配置挂载失败）、settings seam（installSection 语义）、基准目录来源（DSR-007 调用形状与降级）。

## 发布路径（web 启用前置步骤）

发布前置门禁（AGENTS.md 硬性）：**先过 test 实测**（`verify/run-verify.mjs` 全绿 + test profile 启动与功能冒烟），实测结果记入提交说明。

1. `npm publish`（或 `pnpm pack` 交付 tarball；本包无 `private` 标记）。
2. `dsh plugin --profile web add dsh-guardrails`（registry 版本，替换 `github:` 依赖）。
3. `--dump-config` 复查恰一行。
