# dsh-guardrails 规则模型

## 权威范围与来源

本文拥有**规则契约**：规则 schema、规则目录、判定顺序、删除分档的计数口径与豁免接口、配置模型、确认语义、凭据防泄露、失败分类与提示格式。

产品定位：拦截灾难性操作、对敏感文件与高风险执行请求单次确认、遮罩可识别凭据。

输入包含归一化操作事实、目标证据、风险候选和分析状态。策略统一处理这些证据，语言和工具名用于来源解释。

规则组织参考两个成熟项目：[Destructive Command Guard（DCG）](https://github.com/dicklesworthstone/destructive_command_guard) 的 pack 化规则号、severity、规则号放行、默认放行与一次性放行；[CC Safety Net（CCSN）](https://github.com/kenryu42/cc-safety-net) 的规则元数据（`intent`、`catastrophic`、`activationCapability`）、`tighten-only` 项目覆盖与 metadata-only 豁免。本文只借用其元数据与规则组织，判定顺序以本文「判定顺序」节为准。

## 规则 schema

| 字段 | 含义 |
|---|---|
| `id` | 稳定规则号，命名 `类别.<对象>[.<动作>]`（如 `catastrophic.device`、`credential.file.read`、`data.delete.bulk`）；规则号放行、审计与 `allowOnce` 都按它 |
| `category` | `catastrophic` / `data` / `credential` / `execution` |
| `intent` | `hard_stop` / `use_alternative` / `scope_down` / `manual_only` / `stop_and_explain`，驱动拒绝与确认文案的「下一步」 |
| `action` | `deny`（拒绝）/ `confirm`（确认）/ `allow`（放行或豁免） |
| `catastrophic` | `true` 时不可被配置关闭，不可被确认或 `allowOnce` 覆盖 |
| `evidence` | 触发所需证据（灾难身份、计数、受保护命中、可重建证明、数据-执行位置） |
| `severity` | `critical` / `high` / `medium` / `low`，用于排序与文案 |
| `overridable` | 可否被 per-rule 关闭、是否受 `tighten-only` 约束 |

字段值使用代码符号；面向用户的正文与提示文案使用「拒绝 / 确认 / 放行」。

| data | `data.delete.rebuildable` | 可证明可重建（证据） | 豁免计数（不单独产判定） | — | — | R-14 |
| data | `data.delete.ordinary` | 非豁免条目在放行阈值内 | 放行 | low | — | R-07 |
| data | `data.delete.bulk` | 非豁免条目超过放行阈值 | 确认（列范围） | high | scope_down | R-07 |
| data | `data.delete.dynamic` | 目标不可枚举，或删除发生在非宿主执行域与远端资源（按域或命令范围确认） | 确认（列已知范围） | high | scope_down | R-07 / R-16 |
| data | `data.move.source` | `move`/`mv` 的源删除，按前述删除分档 | 拒绝 / 确认 / 放行 | — | — | R-07 |

| data | `data.git.clean` / `.restore` / `.worktree` | git 清理类与工作树状态丢弃类（`restore`、`checkout -- <path>`/`--force`、`switch --force`/`--discard-changes`、`reset --merge`、`branch -D`），证据计数后按删除分档；`git tag -d`/`--delete` 与 `git push --delete refs/tags/*` 放行（引用删除≠历史销毁，见 [DSR-036](../decisions/DSR-036-输出面契约与文案分层.md)） | 确认 / 放行 | high | scope_down | R-06 / R-15 |
| credential | `credential.file.read` | 读受保护文件正文 | 确认（列文件） | high | manual_only | R-04 |
| credential | `credential.file.mutate` | 写、清空、删、移受保护文件 | 确认（列文件） | high | manual_only | R-04 |
| credential | `credential.metadata-only` | 仅列举、统计、存在性或忽略检查 | 放行 | — | — | R-04 |
| credential | `credential.inline` | 命令行内联真实凭据且可扩散 | 拒绝（纠正型） | high | use_alternative | R-11 |
| credential | `credential.output` | 工具结果含高置信凭据 | 打码（非判定动作） | — | — | R-10 |
| execution | `execution.dynamic-command` | 已识别的执行入口将运行未能确定的程序或代码载荷 | 能列可核对范围则确认，否则拒绝 | high | stop_and_explain | R-17 |
| execution | `execution.unverified-effect` | 已有具体的破坏性操作线索，但分析没有证实足以进入常规操作分档的事实 | 能列可核对范围则确认，否则拒绝 | high | stop_and_explain | R-17 |
| execution | `execution.check-failed` | 检查故障：分析器崩溃、协议损坏、必检调用缺少可信结果、关键身份或计数取证失败等检查故障统一命中该规则 | 拒绝 | high | stop_and_explain | R-17 / R-18 |

默认启用的规则以已确认条目为准。内部细化条目在需求追溯及取舍确认后启用。

`catastrophic.git-history` 覆盖销毁 git 历史的子命令：`stash clear`、`stash drop`、`gc --prune=now`/`--prune=all`、`filter-branch`、`filter-repo`、`push --force`/`-f`/`--force-with-lease`/`--mirror`、无路径的 `reset --hard`、`reflog expire --expire=now --all`。`git push -d`/`--delete refs/tags/*` 放行（引用删除≠历史销毁）；当 `push --delete`/`-d` 仅针对 `refs/tags/*` 时，`--force`/`-f`/`--force-with-lease` 不影响放行结论，`--mirror` 仍为灾难；其余 `--delete`/`-d`（裸名、`refs/heads/*`）仍按灾难或确认处理。其余 git 子命令按 `data.git.*` 或放行处理。

`catastrophic.git-metadata` 规则号保留（reserved）但不再产生：完整 Git 仓库（`.git` 主体、bare 仓库、包含 `.git` 目录的树）的删除自 DSR-033 起改为**确认（ask）**，走 `data.delete.bulk`/`data.delete.dynamic`；Git worktree（`.git` 文件指针）不触发该审批，按普通删除计数。

`data.redirect.truncate` 是内部细化候选，需求追溯未定，尚未启用；须补需求条目或按决定移除，该事项登记在 [TODO](../TODO.md)「`data.redirect.truncate` 需求追溯」。在决定前不产生该规则的确认动作。

## 判定顺序

1. **灾难身份**（`catastrophic.*`）→ 拒绝：最先判定，短路其余全部判定；不因可重建豁免或放行结论而改变。
2. **可重建豁免只减计数；非豁免条目在放行阈值内 → 不阻断**：两者都只作用于删除计数，不掩盖同一次调用内的确认或拒绝命中。
3. **需要确认的规则命中**（`data.delete.bulk`、`data.delete.dynamic`、`data.git.*`、`credential.file.*`、已识别且影响无法判定的执行风险）→ 在能说明具体范围时确认。
4. **未命中任何规则** → 放行。

同一次调用按 **拒绝 > 确认 > 放行** 汇总。灾难身份拒绝优先，其他拒绝保留各自的触发原因。多个确认命中合并为一次请求，范围包含各项已知目标、删除计数、受保护命中及不可枚举部分。只有覆盖诊断时仍返回放行，并附相应诊断。

### 操作到规则的映射

| 证据输入 | 规则处理 |
|---|---|
| 已确定删除动作与可盘存目标 | 用身份、目录项与边界证据确定适用规则。按有效非豁免计数处理普通和批量删除 |
| 已确定删除动作，目标表达为 `unknown`，通配无法静态枚举，或递归范围不可证 | 进入 `data.delete.dynamic`，使用已证范围。目录内容不得作为未知目标的替代清单 |
| 已确定删除动作，发生在非宿主执行域（如 `wsl -e`） | 进入 `data.delete.dynamic`，范围列「执行域 + 字面目标」；不做宿主盘存 |
| 已确定删除动作，目标是远端资源（云、数据库、K8s、容器、IaC 的最高危子命令） | 进入 `data.delete.dynamic`，范围列命令中的资源标识；命令文本不按本地路径解释 |
| 未证实破坏性动作，但有明确线索与源位置 | 进入 `execution.unverified-effect`。可核对范围/无法核对范围分别进入确认/拒绝 |
| 已识别动态执行入口，实际程序或载荷未知 | 进入 `execution.dynamic-command`。已接入且可确定的普通脚本入口依实际分析结果分档 |
| 部分覆盖且没有候选、受保护命中或其他风险证据 | 放行，呈现经脱敏的覆盖诊断 |
| 故障结果、必检调用无结果、关键身份取证失败 | 以检查失败拒绝，统一报告规则号 `execution.check-failed`，提示故障阶段及可行修复；不使用实现内部的 `ANALYSIS_UNAVAILABLE`、`GUARD_*` 等非契约编号。保留已确认的灾难身份或其他直接拒绝证据 |

同一规则可关联多个操作。诊断归并按固定规则目录顺序和来源顺序进行，与并行分析回包顺序无关。有效配置只作用于对应规则，不影响同一调用的其他命中。

## 删除分档细节

- **计数对象**：未命中可重建豁免的常规文件与链接条目；目录条目按路径去重后单列报告。
- **计数范围**：工作区之外的目标同样计数；`move`/`mv` 的源删除计入；命令行字面量目标与语言层求出的目标合并去重计数。
- **计数的完成状态**：完整盘存后报告精确值。非豁免数超过阈值时可以停止精确计数，并以「至少 21」表述。继续完成受保护对象、灾难身份及确认所需范围的检查。超时或读取失败时，如果只能确认部分计数且还不能可靠取得范围或关键身份，按盘存失败处理。
- **豁免接口**：只有形态候选与归属、再生证据同时成立才不计入；证据不足一律照常计数，方向保守。豁免判据本身不归本文拥有。
- **不因名字豁免**：目录名相同不构成豁免；伪装成可重建的用户数据照常计数。
- **预览**：真实的 `-WhatIf`/`--dry-run` 为纯预览，不进确认与计数，但仍做路径与凭据扫描；混合调用中真实删除的部分仍全量分档。
- **挂载边界**：Linux 依 `/proc/self/mountinfo` 的有效快照拒绝挂载点内与跨挂载删除；Windows 保留 metadata 与 junction 语义。
- **不可表示文件名**：含 U+FFFD 或非 well-formed 的目录项无法可靠定位，整次转确认或拒绝，不漏计。

## 配置模型

配置模型只有**配置 A（per-rule 规则级配置）**一种。配置真相归 Profile 的插件行；敏感标记不从工作树文件读取；volatile 字段在判定时读活值；配置非法按 R-20 降级，不整体停摆。

| 字段 | 契约 |
|---|---|
| `sensitiveFiles` | 默认 `[]`，只接受精确绝对路径，不接受通配或相对路径；不扩展为目录许可配置 |
| `builtinSensitiveAsk` | 默认 `true`；控制内置敏感文件名单的内容操作确认，名单覆盖 SSH 私钥、工具凭据文件、系统凭据库、分页与休眠文件四类 |
| `askTimeoutMs` | 默认 `120000` ms；`0` 映射为 `120000`，不提供无限等待；非整数或越界值在配置边界拒绝 |
| `alwaysAsk` | 默认 `true`，可热改。宿主有效审批策略为 `never`（或审批 seam 缺失）时，改用官方问答 seam 弹单问题确认，而不是自动拒绝；`false` 时退回自动拒绝；无客户端应答方的无人值守会话仍拒绝。只在插件自有确认的 `never`/缺 seam 分支生效，不改变 `ask` 策略下的 `approval.request` 通道，也不改变 `askTimeoutMs` 预算（问答通道同样受其约束）；展示见「确认展示与模型可见记录」 |
| `rules.<id>.enabled` | 按规则号的开关；`catastrophic` 规则不可关闭 |
| `rules.<id>.allowlist` | 按规则号放行；项目级生效 |
| `allowOnce` | 一次性放行，只作用于当前调用 |
| `tightenOnly` | 项目层覆盖只能收紧、不能放松；灾难身份与受保护项始终生效 |

内置敏感名单只覆盖高置信 basename、精确文件与精确尾段组合（如 `.aws/credentials`、`.kube/config`、`.docker/config.json`）；用户 Profile 的精确路径经 `sensitiveFiles` 补充；不按扩展名或目录段整类拦截。本文只承认本节列出的配置项，其余键不是配置契约。

## 确认语义

本文的「确认」指本插件发起的一次性、限时确认；它只约束本插件发起的请求，不改变其他来源的确认行为。

- **通道优先级**：每次确认按序选通道。① 审批 seam `ctx.get('approval')` 存在且会话有效策略为 `ask` → 走官方 `approval.request()`（保留 `approval/asked`、`approval/decided` 审计，兼容 ACP 等应答方）。② 否则（有效策略为 `never`，或审批 seam 缺失）且 `alwaysAsk = true` → 走官方问答 seam `userQuestions.ask()` 的单问题确认（`intent.kind = 'approval'`；展示见下节）。③ `alwaysAsk = false`，或问答 seam 不可用/无应答方 → 拒绝，fail-closed。详见 [DSR-034](../decisions/DSR-034-插件自有确认通道与never策略回退.md)。
- **范围**：每次确认必须列出具体范围——文件或目录清单、计数、受保护命中，以及无法枚举的部分（R-09）；不列范围视为不合格。
- **一次性**：批准只作用于当前调用；重复调用重新确认。
- **限时**：等待上限由 `askTimeoutMs` 决定，默认 120000 ms；超时即不执行，并按拒绝处理。
- **不执行项**：未获一次性批准即不执行——拒绝、超时、取消、通道不可用都是未获批准；策略 `never` 下未获问答批准同样不执行；迟到的批准不能复活已终止的确认。
- **不构成删除授权**：确认通过后重新盘存目标与计数，再执行。
- **生命周期**：每次请求绑定独立的取消与卸载信号；调用方取消映射为取消，插件计时器到点映射为拒绝。

## 确认展示与模型可见记录

本节只规定确认的展示与模型可见输出；判定、通道与拒绝码仍归上文与 [DSR-034](../decisions/DSR-034-插件自有确认通道与never策略回退.md)，展示层扩展见 [DSR-035](../decisions/DSR-035-确认卡外观与模型可见确认记录.md)。

- **问题请求形状**：问答通道的请求带 `intent.kind = 'approval'` 与 `intent.display = { question: { en, zh }, detail: { en, zh }, approve: { en, zh } }`。`en` 必填、`zh` 为小写键；`approve` 覆盖「允许一次」标签。
- **文案来源（两条通道一致）**：`ask` 官方审批卡与 `never`/缺 seam 的问答卡都用同一个 `confirmSummary(scopeText, ruleIds)` 生成用户可见摘要；`ask` 通道经公开字段 `ApprovalRequestEvent.displayReason` 传入，问答通道经 `AskUserQuestionIntent.display.detail` 传入。`reason` 保留英文原文，供审计与模型。
- **说明格式**：共享卡说明区是纯文本，不渲染换行或 Markdown；摘要采用**单段、分号分隔、字段人话化**（删除类按目标 / 涉及目录 / 另将销毁 / 其他标记，非删除类按已知字段人话化）。长列表只列前若干项并补「等共 N 项」，整段超长时收缩列表上限并按长度截断；scope 解析失败时回退原始 `reason` 原文。
- **用户可见文本约束**：摘要不出现 `non-exempt`、`entries`/`directories`/`roots` 等内部字段名或内部标记 token；未知内部标记只保留在 `reason`，不展示给用户；规则号仍以括号形式保留。
- **专用句式与 notes**：`data.git.worktree` 用「移除工作树」专用句式，`data.move.source` 用「移动后源位置不再保留」专用句式；`notes` 必须渲染——已知标记按映射转写，未知标记标注「原文：…」。中文卡片中的动作 token 全部中英映射，不混未标注英文。
- **问答通道的 Web 展示**：插件客户端半区的 `selectGuardrailsApproval` 只接管 `id === 'guardrails-confirm'` 且 approval 意图的待答问题，经共享工厂 `conversation.approval.card` 渲染标准审批卡（标题/说明/「拒绝」「允许一次」）。中英界面按 `intent.display` 显示本地化标题/说明/允许标签；非中英界面回退英文标题/说明与英文允许标签，拒绝等固定操作按客户端语言包本地化。无共享卡工厂时经 `renderFactorySlot` 的 `fallback` 渲染最小卡片，仍保留一次确认语义。
- **模型可见记录**：只对**经确认应答方（可能是用户）放行**的调用，在 `tools/post-execute` 通过 `additionalContexts` 附一条 `source.kind = 'dsh-guardrails'`、`form: 'notice'` 的 user 消息；首行为人话说明，随后为 `rule=`、`confirmed_by=answerer`、`channel=approval-card` 或 `channel=question-card`、`scope=`（人话摘要并截断）、`this_call_only=yes`。仅当该调用被接受且结果非错误时注入，下游 block 或错误结果不注入；同一调用最多一条。规则直接放行不注入；拒绝侧不改（`APPROVAL_*` 留在拒绝文案）。
- **契约边界**：审批通道经公开字段 `ApprovalRequestEvent.displayReason` 传同一份摘要，问答通道经公开字段 `AskUserQuestionIntent.display`；`PostToolDecision.additionalContexts` 也是公开契约。`additionalContexts` 的消息对象是手搓 `UserMessage` 形状（插件不能 import `dsh-llm`），属半内部构造，由插件自身的形状校验与回归测试覆盖 `role`/`id`/`content`/`source` 与 `notice.summary`。

## 凭据防泄露

- `credential.output`（旧号 R-M1）：受管工具结果中的高置信真实凭据默认遮罩为 `[REDACTED:<kind>]`（`kind ∈ pem/bearer/jwt/provider`），不保留前后缀；打码不额外增加确认或拒绝；非秘密诊断与成功/失败语义保持。受约束 schema 或非纯字符串的结果按「遮罩应用策略」withhold。
- `credential.inline`（旧号 R-M2）：命令或 HTTP 参数直接内联真实凭据、且有扩散风险与可行替代时，按纠正型拒绝；变量引用、示例、占位符与正常间接认证不因关键词被拒绝。
- **凭据文本扫描**（R-04）：命令文本、`terminal_send` 文本，以及经已识别执行入口读入的脚本正文，在本次调用存在未解析动态操作数时，按凭据基名与私钥头匹配；命中即升级为确认，只升不降。`write` 与 `edit` 的正文不扫描，其目标路径仍由受保护文件判定负责。

## 输出面与文案分层

| 输出 | 读者 | 语言与形态 |
|---|---|---|
| 拒绝块（`DENY`/`CONFIRM` 固定块：Why/Trigger/Effect/Scope/Next，空字段省略） | agent | 英文、准确、可执行、信息充分；`Trigger` 用真实 stage/gap 码 |
| 确认通知（`additionalContexts` 的 notice） | agent | 首行人话说明 + 中性字段 `rule`/`confirmed_by`/`channel`/`scope`/`this_call_only` |
| 拒绝码 `APPROVAL_*` | agent | 英文，明确是否有人参与、是否执行 |
| 确认卡、设置页、插件元数据 | 用户 | 中英、人话、单段；不出现内部字段名与标记 token |
| 遮罩标记 | 机器/审计 | `[REDACTED:<kind>]`，`kind ∈ pem/bearer/jwt/provider` |

同一事实可复用，但措辞按读者分层：用户文案不显示内部 token；agent 文案不牺牲准确性换本地化。

### 遮罩应用策略

- **原位替换**：仅当值是纯字符串且输出 schema 无约束（无 enum/const/pattern/format/length 等）时，替换为 `[REDACTED:<kind>]`（`kind ∈ pem/bearer/jwt/provider`）。
- **withhold（block）**：其它类型或受约束 schema 的值若含可遮罩内容，不替换，整体 withhold 该结果，返回一条不含原值的说明（`This result was withheld…`），避免运行时 `invalid output` 回显原文。
- **错误结果**：`result.error.message`、`result.error.info`、`result.meta` 命中或 `unknown` → 整条 withhold，模型/PTC 只见固定说明。
- **block.info**：命中 → 替换为 `{ name: 'Guardrails', code: 'REDACTED' }`，保留 block 渲染与错误身份。
- **meta 类**：`result.meta` / `presentationMeta` 命中或 `unknown` → withhold（`PostToolDecision` 无 meta 字段，不能原位替换）。
- **content 分支**：`decision.content` 分支同时扫描 `value`、`result.value`、`meta`，命中即 withhold。
- **additionalContexts**：`decision.additionalContexts` 任一条消息 `scan !== 'clean'`（含 text 块含凭据）即整条丢弃该条 context，不做局部遮罩；工具自身 `result.additionalContexts` 的非 text 块（image/file）深扫 clean 即放行，命中/`unknown` → 整条结果 withhold。
- **非 text 字段与块**：除 `text`/`name`/`attachment.name` 外，`reasoning` 的 `text`、`tool-call` 的 `arguments`、contexts 消息的 `source.summary` 等非 content 字符串字段都参与遮罩；未知块类型整块深扫，命中/`unknown` → withhold。
- **presentationMeta**：只投影一次，避免重复调用产生副作用。
- **取舍**：安全优先；结构化结果可能被整体 withheld，调用方会失去该结果。`result.isError` 的 `value`：运行时通常会拒绝替换失败结果的 value；插件仍做防御性 withhold（纵深防御），并有 hook 级测试。
- **containsMaskable 三态**：`hit|clean|unknown`；越过 depth 32、单数组 65536、对象键 65536、单字符串 8MB，或 `Map`/`Set`/`Buffer`/`Date`/类实例 → `unknown` → 按不安全处理并 **withhold**；clean 的超大但未越界对象/数组正常放行（与 EX-04 一致）。
- **PTC durable log（`tools/ptc-dispatch-log`）专用遮罩**：对日志中每个 JSON 字符串值遮罩（覆盖 `id`/`payload`/`arguments`/自定义字段，不依赖字段白名单）；已知块类型且 clean → 原样；未知块类型、非 JSON、循环、超上限（depth 32 / 数组键 65536 / 8MB）→ **整块占位**（比结果面更严格）；`next()` 返回非数组或抛错 → 单条固定占位，防止 PTC runtime 失败回退把原始 content 写入日志。

## 失败分类与提示格式

| 情形 | 处置 |
|---|---|
| 无分析器、局部不可读或局部分析未完成，且本次取得有效结果 | 保留已有证据并记录覆盖缺口。其他检查无风险证据则放行。有风险候选则按已知目标及范围处置 |
| 已识别风险候选，目标不可枚举或副作用仍无法判断 | 已有信息足以说明具体范围时确认，并标明未知部分。范围不可说明时拒绝。普通参数未知、只读命令的未知选项以及无相关执行语义的文本不单独构成风险候选 |
| 已接入的分析器崩溃、协议损坏、内部异常，或整次必检调用未在期限内交付可信结果 | 拒绝并记录阶段与原因。本次结果存在覆盖缺口的情况有独立处置 |
| 已进入目标盘存，计数或关键身份取证失败 | 拒绝。可重建证据缺失仅撤销计数豁免 |
| Git 专用证据不可用 | 按 R-15 拒绝该删除 |
| 确认通道不可用、超时、取消或迟到 | 停止执行本次调用 |
| 配置非法或含未知键 | 降级为保护性默认，守卫与打码保持生效（R-20） |

所有检查故障（分析器崩溃、协议损坏、必检调用缺少可信结果、关键身份或计数取证失败）对外统一报告规则号 `execution.check-failed`；`ANALYSIS_UNAVAILABLE`、`GUARD_*` 等实现内部编号不是契约规则号，不进入对外输出。

### 确认通道拒绝码（归因）

下列码出现在拒绝文案中，用于区分「没人参与」与「真的有人拒绝」。它们不是规则号，不参与 `rules.<id>` 配置。

| 码 | 触发 | 是否有人参与/展示 |
|---|---|---|
| `APPROVAL_REJECTED` | 审批应答方返回 `rejected`，或用户在问答卡里选了拒绝项 | 有真实人类拒绝，已展示 |
| `APPROVAL_POLICY_NEVER` | 策略/开关禁止，从未询问（`alwaysAsk` 关闭） | 没有人参与，没有交互应答方接受该确认 |
| `APPROVAL_UNAVAILABLE` | 无确认通道或无人应答（无 UI、seam 缺失、`NO_PROVIDER`、`CALLER_NOT_LIVE`） | 没有人参与，没有交互应答方接受该确认 |
| `APPROVAL_DELEGATED` | 委派子会话（宿主固定 `never`、问答 seam 抛 `DELEGATED_CALLER`） | 没有人参与，没有交互应答方接受该确认 |
| `APPROVAL_TIMEOUT` | 超过 `askTimeoutMs` 预算（含预算已用尽） | 没有人拒绝；自动拒绝 |
| `APPROVAL_CANCELLED` / `APPROVAL_FAILED` | 调用取消 / 确认无法记录 | 没有人拒绝；fail-closed |

所有拒绝文案都显式声明 `nothing was executed` /「未执行任何操作」。只有 `APPROVAL_REJECTED` 可以表述为「用户拒绝」；`APPROVAL_POLICY_NEVER`（策略/开关禁止）、`APPROVAL_UNAVAILABLE`（无通道）、`APPROVAL_DELEGATED`（子代理限制）都表示「无法询问用户」，不得混为同一原因。`APPROVAL_TIMEOUT` 按规则类别给下一步：目标可枚举类建议收窄字面目标重试，其他类建议等用户可响应或手工处理。详见 [DSR-034](../decisions/DSR-034-插件自有确认通道与never策略回退.md) 与 [DSR-036](../decisions/DSR-036-输出面契约与文案分层.md)。

覆盖诊断与操作判定同时保留。诊断仅记录未覆盖的范围和原因，经脱敏后报告。执行风险的范围应来自能核实的目标或执行约束。脚本路径和工作目录本身无法证明其删除范围。

### 拒绝块字段规则

- `Trigger` 使用真实 stage/gap 码（分析、盘存、Git 证据、解析等阶段），不使用 `not captured` 占位；无证据时不输出该占位、按需省略或给出可解释原因，不产生空行。
- 已知 stage 由 `STAGE_META` 提供专用 `Effect`/`Next`；未知 stage 使用通用文案。
- `Why` 说明为何拦截，`Scope` 列出具体范围，`Next` 给出可执行下一步；`Why`/`Trigger` 输出前经打码。
- 所有 `deny` 的 `Next` 统一带 `Nothing was executed.`（含 catastrophic、未知 stage、`execution.check-failed` 与 guard fault）。

### 保守拒绝与替代策略

保守拒绝必须在 `Next` 写明可执行的替代路径：

| 拒绝/码 | 替代策略 |
|---|---|
| `catastrophic.git-history`（含 `git push --delete <裸名>`） | 用 `git tag -d <name>` 或 `git push origin --delete refs/tags/<name>`；删除分支同样会被拒绝，不提供替代 |
| `GUARD_INVALID_SHELL_INPUT` | 把命令作为单个字符串传入；从文件读取后传原文 |
| `GUARD_WORKDIR_UNRESOLVED` | 使用绝对工作目录/绝对路径 |
| `APPROVAL_TIMEOUT`（credential 类） | 请用户打开文件并粘贴脱敏片段，或改用凭据注入/环境变量 |
| `credential.file.mutate` | 请用户手工修改 |
| `APPROVAL_POLICY_NEVER` / `APPROVAL_UNAVAILABLE` / `APPROVAL_DELEGATED` | 启用提示、换桌面/Web 会话、回父会话 |
| `data.delete.dynamic` | 改写为字面可枚举路径 |

所有拒绝与确认渲染为固定块：

```text
[GUARDRAILS] DENY|CONFIRM <RULE-ID> (<category>)
Why:     <原因>
Trigger: <触发证据>        # 空或 not captured 时整行省略
Effect:  <后果>
Scope:   <具体范围>        # 空时整行省略
Next:    <可行的下一步>    # 所有 deny 统一含 Nothing was executed.
```

`Scope` 列出具体删除或涉及范围；`Trigger` 与 `Why` 输出前经打码。`Trigger`、`Scope` 为空或 `not captured` 时整行省略，不输出占位行。
