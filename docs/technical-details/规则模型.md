# dsh-guardrails 规则模型

## 判定与对象

本文定义当前规则契约（严格删除门禁为源码实现，live 激活已在验收环境复验，UI 与跨平台部署待验证，见文末）。执行结果优先级为 `Deny > Ask > Allow`。绝对 Deny 与纠正型 Deny 都由最终同步 guard 阻断，拒绝原因必须区分政策与基础设施故障；**所有工具返回 reason 为英文**，并按 v6 五段式块渲染（RULE-ID/Why/Trigger/Effect/Next，见下）。

| 类别 | 可靠触发条件 | 语义 |
|---|---|---|
| 绝对 Deny | 真实宿主物理磁盘/分区底层灾难破坏；真实宿主 OS 根/核心结构整体毁坏；真实 Git 共享 common-dir 主体整体破坏 | 不允许本次审批覆盖；命令名与 `.git` 字面本身不足以触发 |
| 纠正型 Deny | AST/结构化参数证明真实高后果危险机制，同时有任务可达、具体可执行的安全替代 | 拒绝当前方法，解释证据、目标和替代；不自动执行改写命令 |
| 删除数量门禁（L2） | 单次调用内未命中白名单的常规文件 + 链接条目 > 20（含工作区之外的目标、`move` 源删除）| 拒绝（`DEL-01`/`DEL-14`），要求核实预期并分批删除；`<=20` 需完整枚举；见下「删除计数」 |
| 执行通道拒绝 | 目的是执行任意命令文本且无法分析：无法分析的 shell 脚本、动态命令文本、`env/xargs/sudo/start/source`、WSL 包装、`run_code`（载荷是程序） | 英文拒绝并要求更清晰、受支持的命令；一律附统一删除强提示 |
| 灾难模式（L1） | 物理设备/卷、宿主系统树、`.git` 元数据路径、销毁 git 历史的 git 子命令 | 即使程序名未知也拒绝；带 doctrine |
| L3 放行 | 未建模程序、`copy`、`create_worktree`、`terminal_open`、全部 `plugin_manager` 动作、常规 git 操作 | 放行、不进删除门禁 |
| git 分级 | `assessGit`：销毁历史 → `DI-GIT-REFUSE`；`clean`/`restore`/`worktree remove` → `git-evidence` 计数；证据不可用 → `DEL-GIT-UNKNOWN` | allow 命令不进文件扫描；>20/工作树不干净拒；证据缺失 fail-closed |
| 语言运行时放行 | `node/python/perl/ruby/php/deno/bun/uv` 等作为不透明脚本运行器（脚本参数/`-m`）| 直接允许、不计数；**内联代码开关**（`-e/--eval/-p/--print/-c/-r/-E/-i/--interactive`、stdin `-`）仍 `DI-INLINE-CODE` 拒绝 |
| shell 脚本文件分析 | `bash/sh/zsh/dash <文件>`、`pwsh/powershell -File <文件>`：字面/存在/常规/≤1MiB/编码可判定 | 读文件文本按该方言分析并计数；缺失/非常规/过大/编码未知/`source`/`eval`/动态→unknown 拒绝；不支持 `./x.sh` 路径限定可执行 |
| 敏感文件 Ask（S-F1） | 精确 Profile 文件或内置敏感文件名单中的文件被直接读正文、导出/复制、写/覆盖/清空、删或移动 | 单次、限时审批；元数据列举与正常间接认证 Allow |
| Worktree（S-F2） | 正常非强制 `git worktree remove` | 见 git 分级：干净工作树 + 非分离 HEAD + 可重建外忽略条目 ≤20 才计数放行 |

## 灾难性删除标准（v4：L1/L2/L3）

插件只防**灾难性删除**，不再声称覆盖所有删除。准确声明：**可识别的命令行删除被计数；无法分析的执行通道被拒绝；其余操作放行。** 详见 [DSR-020](../decisions/DSR-020-灾难性删除标准.md)。要点：

- **L1 直接拒绝**：物理设备/卷、宿主系统树、`.git` 元数据、销毁 git 历史的 git 子命令。
- **L2 计数**：可识别的命令行删除（含工作区之外目标、`move` 源删除）；≤20 放行、>20 拒绝。**边界外同样计数，不因“在边界外”本身拒绝**（系统树/设备/.git 的 L1 除外）。
- **L3 放行**：未建模程序、`copy`、`create_worktree`、`terminal_open`、全部 `plugin_manager` 动作、常规 git 操作。
- **执行通道保持“可分析否则拒绝”**：`run_code` 一律拒绝（载荷是程序）；`terminal_send` 的 `text` 就地按平台方言分析（Windows PowerShell / 其他 POSIX），可识别删除照常计数、无法分析则拒绝。语言运行时是显式例外。
- **未知程序名不再拒绝**：只有 adapter 无法解析的**执行语义**（且与删除意图相关）仍拒绝（`DI-UNKNOWN-SEMANTICS`）；非删除语义噪声见下「v6 触发收敛」。未知程序名按 L3 放行。

## v6 触发收敛与定向提示

误报治理：`DI-UNKNOWN-SEMANTICS` 不再把解析层的所有 unknown 一律升级为拒绝。仅**与删除意图相关**的 unknown 拒绝；与删除无关的展示/状态噪声在**无真实删除**时放行。详见 [DSR-021](../decisions/DSR-021-非删除unknown放行.md)。要点：

- **放行（无真实删除时）**：PowerShell/Bash 变量与环境变量赋值标记；通用动态参数（脚本块/属性参数；`Dynamic command or argument` 只保留给命令名为 null 的执行通道）；已知只读命令的动态操作数。
- **始终拒绝**：动态目标的删除/移动（`Remove-Item $p` 且 `$p` 非字面量）、动态命令名（`& $cmd`/`iex`）、通配/不可枚举目标、执行通道不可分析（动态内联脚本、不可读脚本文件、WSL/cmd、路径限定可执行）、`>20`（`DEL-01`/`DEL-14`/`DEL-GIT-*`）、L1 灾难拒绝。
- **字面量 `cd` 跟踪**：顶层 script scope、单字面参数、经 `lstat` 确认为真实目录（非链接）时更新后续命令的 `cwd`；动态/多参/`pushd`/`popd` 仍 unknown 且其后删除 fail-closed。
- **成员/类型能力分级**：属性/索引访问放行；仅纯字符串/格式化实例方法白名单（目标须为变量/属性链/字符串字面量）放行；静态 `::` 调用、`.Delete()`/`.Invoke()` 等非白名单方法与自定义类型转换仍拒绝；基元类型约束放行。
- **字面量常量传播（仅 PowerShell）**：顶层单一字面赋值在早于使用处恢复为字面量；多次赋值/命令结果/控制流内赋值仍动态（fail-closed）；bash 不做。
- **凭据静态文本扫描**：命令文本/`terminal_send` 文本/被当脚本读入的文件源命中凭据基名或私钥头时升级 `S-F1` 审批（只升不降）；不扫 `write`/`edit` 正文。
- **定向提示**：所有 tool-return 拒绝与 ASK 渲染为五段式块 `[GUARDRAILS] DENY|ASK <RULE-ID> (<layer>)` / `Why` / `Trigger` / `Effect` / `Next`（删除类末句保留 `DELETION_DOCTRINE`），`Trigger`/`Why` 经打码；见 [命令文本分析](命令文本分析.md)。

## 严格删除门禁（沿用要点）

用户已确认把可识别的删除收紧为「执行前计数 + 超 20 硬拒绝」。要点：

- **默认拒绝未审查工具**：只有与框架协调、经审查的 `tools` 走 allow-list 放行（含 `create_worktree`、`terminal_open`、全部 `plugin_manager` 动作）。不隐式信任 agent 自报或预览（dry-run）。
- **`run_code` 一律拒绝**（载荷是程序，副作用不可排除）；`terminal_send` 文本就地分析、无法分析则拒绝。真正边界是「不经 `ctx.tools` 直接调用 runtime service」，本插件不覆盖该直连路径。
- **WSL 删除无法在宿主枚举时拒绝**：不假设 `/mnt/X` 映射；Windows 上的 bash 删除域无法对应到 Node 路径时，要求改用 literal 的受管宿主命令（如 `Remove-Item -LiteralPath`）。
- **计数不可靠即拒绝**：未知目标、预算/权限不足、歧义、链接祖先、挂载跨越、根目录、`..`、单根/`~` 目标均拒绝。
- **不把审批当授权**：审批后需重新计数；检查与执行间的 FS 并发竞态是已知边界，本插件不声称 `<=20` 执行原子；同调用中先于删除的变更由 intent 层作为 unknown 交门禁拒绝。

## 删除计数与白名单

- 统计**未命中白名单的常规文件 + 删除的链接条目**；目录条目去重（按路径）并单独报告目录数。`<=20` 完整枚举；`>20` 早停于「至少 21」，不声称精确总数。
- **内置白名单规则需「形态匹配 + 证据」双重通过**（见 [批量删除白名单](批量删除白名单.md)）：核心匹配器给出的只是候选；只有再经证据适配器证明归属/再生（项目边界精确段包含、非归档域、非链接逃逸、Git 未跟踪且状态可证、配对源存在）才减少计数。任一不满足照常计数。当前有效规则：Python `__pycache__/*.cpython-<ver>[.opt-N].pyc`（需配对 `.py`）；pytest `.pytest_cache/v/cache/{nodeids,lastfailed,stepwise}`；mypy `.mypy_cache/<major.minor>/**/*.{data,meta}.json`；Maven `target/{classes,test-classes}/**/*.class`（需对应 `src/{main,test}/java` 源）；TypeScript `*.tsbuildinfo`（有限子集）。
- **Cargo 已取消自动豁免**：`target/*/deps/*.{rlib,rmeta,d}` 照常计数；`Cargo.toml` 仅保留为项目边界 marker，存在本身不授权豁免。
- **TS 有限子集**：显式 `tsBuildInfoFile` 覆盖、以及 `rootDir+outDir` 官方公式支持；仅 `outFile` 无显式覆盖时因命名歧义照常计数；不运行 `tsc`/不引入依赖。
- 白名单是**计数-only 证据**：受保护文件与绝对 Deny 始终生效；不做不检查保护/链接的整树跳过。不认识 `dist/build/tmp/node_modules/backup/.git` 等宽泛目录的整树，不读内容、不整树豁免。
- **不支持用户自加任意白名单**；识别集合内置固定。不构成「全语言语义完整」承诺。
- **预览删除**：真实 `Remove-Item -WhatIf`（无 `-Confirm`）为纯预览，`-WhatIf` 不作为文件名参数误判；预览命令不进入删除清单/数量门禁，但仍做路径与凭据扫描，混合调用中真实删除部分仍全量计数并受门禁约束。
- **挂载边界**：Linux 用 `/proc/self/mountinfo`（有界一次快照）拒绝删除目标处/内部的挂载点（含同设备 bind 挂载）与 boundary→target 间的跨越；Windows 保留既有 metadata/junction 行为。
- **不可表示的文件名**：目录项若含 U+FFFD 或非 well-formed 字符串（UTF-8 解码丢失原始字节），无法可靠定位真实条目，整次清单拒绝而非漏计；合法 Unicode（中文/emoji）正常计数。

## 配置模型

配置真相归对应 Profile 的插件行；标记不从工作树文件读取。目标采用 schema 自动设置页，volatile 字段在判定时读取活值。

| 字段 | 当前契约 |
|---|---|
| `sensitiveFiles` | 默认 `[]`，只接受精确绝对文件路径，不接受通配符/相对路径；不扩展成目录许可配置 |
| `builtinSensitiveAsk` | 默认 `true`；控制内置敏感文件名单（私钥、工具凭据文件、系统凭据库、分页与休眠文件）的内容操作审批；不关闭 Profile 明确标记保护 |
| `askTimeoutMs` | 默认 `120000` ms；legacy `0` 映射为 `120000` ms，不再无限等待；非法值在配置边界拒绝 |

普通未标记 `.env` 不自动加入保护。内置名单须精确、高置信；不恢复旧凭据整目录/任意 `.pem`、`.key` 后缀全禁，也不因旧文件列举过某载体而自行扩展默认名单。

## Guardrails 自有审批

插件主动调用原生 Approval，并为每次请求绑定独立超时、执行取消与卸载生命周期。只有本次 `allowed-once` 授权；`rejected`、`cancelled`、`unavailable`、异常、身份缺失及 `approval: never` 均不执行。超时终止底层请求，迟到批准不能复活工具；所有出口清理计时器和监听器。审批通过**不等于**删除授权——仍需通过数量门禁与未知拒绝。

## 凭据防泄露

R-M1：对受管工具结果中的高置信真实凭据默认完整遮罩，不保留密钥前后缀，不增加 Ask/Deny；保持非秘密诊断和原有成功/失败语义。不使用任意高熵全禁、全盘扫描或外部 DLP。

R-M2：受管 Shell/结构化 HTTP 参数直接内联真实凭据，且有明确扩散风险和可行替代时使用纠正型 Deny；变量引用、示例、占位符和正常间接认证不因关键词拒绝。建议现有 Secret Manager、环境变量引用或可信认证机制，不迁移或改写 `.env`。

## 不默认启用的候选与失败分类

Git clean/reset/restore/强推/强删引用、云/数据库/容器/系统及厂商 Secret CLI 的逐命令矩阵仍为候选，需逐条批准；本轮的收紧是「删除一律计数」，不是自动启用上述矩阵。必检调用的解析器/协议/关联故障采用 fail-closed，明确是检查不可用；解析层只报告 Unknown，**策略层只对与删除意图相关的 Unknown 拒绝**（非删除语义噪声在无真实删除时放行，见 [DSR-021](../decisions/DSR-021-非删除unknown放行.md)）。不存在旧「判定异常全局 fail-open」的兜底授权。

## 历史的 DSR 与冲突

本模型取代 DSR-017 中与「删除数量门禁、未知默认拒绝、文件级白名单、WSL 计数缺失拒绝、`<=20`/`>20` 语义」相冲突的条款；历史 DSR-001…018 原文不改，见 [DSR-019](../decisions/DSR-019-删除计数与不确定执行拒绝.md)。v6 对「非删除语义 unknown 一律拒绝」的收窄见 [DSR-021](../decisions/DSR-021-非删除unknown放行.md)，与 DSR-019/020 的删除计数、L1 拒绝、动态删除拒绝不冲突。

严格删除门禁与文件级白名单为**源码实现**，源码与隔离 Runtime 验证通过，详见[验证记录](../verification/2026-11-14-delete-gate.md)。live 激活已在验收环境复验；**UI 显示、稳定环境门禁、Linux/跨平台实跑与并发竞态仍待完成**；旧语料回归不代表新策略全部通过。以验证记录为最终依据。
