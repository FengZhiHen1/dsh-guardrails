# dsh-guardrails 规则模型

## 判定与对象

本文定义当前规则契约，实际验证范围见本轮验证记录。执行结果优先级为 `Deny > Ask > Allow`。绝对 Deny 与纠正型 Deny 都由最终同步 guard 阻断，但拒绝原因必须区分政策与基础设施故障。

| 类别 | 可靠触发条件 | 语义 |
|---|---|---|
| 绝对 Deny | 真实宿主物理磁盘/分区底层灾难破坏；真实宿主 OS 根/核心结构整体毁坏；真实 Git 共享 common-dir 主体整体破坏 | 不允许本次审批覆盖；命令名与 `.git` 字面本身不足以触发 |
| 纠正型 Deny | AST/结构化参数证明真实高后果危险机制，同时有任务可达、具体可执行的安全替代 | 拒绝当前方法，解释证据、目标和替代；不自动执行改写命令 |
| 敏感文件 Ask（S-F1） | 精确 Profile 文件或内置高置信凭据载体被直接读正文、导出/复制、写/覆盖/清空、删或移动 | 单次、限时审批；元数据列举与正常间接认证 Allow |
| Worktree（S-F2） | 正常非强制 `git worktree remove` | 默认 Allow，让 Git 自查；仅高置信确认待删树内存在实际受保护文件才因该删除 Ask |
| 正常 Allow | 普通文件、缓存、生成目录、局部 Git 清理、正常状态/提交/暂存、独立复制/移动 | 不要求生成物白名单或可靠副本跨调用证明；仍适用独立保护目标 |

HOME、项目根、普通数据卷、镜像文件、容器根和 Linked Worktree `.git` 指针不得仅按词面升级成绝对 Deny。高影响操作的具体 Ask 子类须经批准；上表不是旧 Git/云/DB 研究矩阵的启用许可。

## 配置模型

配置真相归对应 Profile 的插件行；标记不从工作树文件读取。目标采用 schema 自动设置页，替代旧 client 自绘，volatile 字段在判定时读取活值。

| 字段 | 当前契约 |
|---|---|
| `sensitiveFiles` | 默认 `[]`，只接受精确绝对文件路径，不接受通配符/相对路径；不扩展成目录许可配置 |
| `credentialsReadAsk` | 默认 `true`，保留旧名称；控制内置高置信凭据的内容操作审批，已不限读取；不关闭 Profile 明确标记保护 |
| `askTimeoutMs` | 默认 `120000` ms；legacy `0` 映射为 `120000` ms，不再无限等待；非法值在配置边界拒绝 |

普通未标记 `.env` 不自动加入保护。内置名单须精确、高置信；不恢复旧凭据整目录/任意 `.pem`、`.key` 后缀全禁，也不因旧文件列举过某载体而自行扩展默认名单。

## Guardrails 自有审批

插件主动调用原生 Approval，并为每次请求绑定独立超时、执行取消与卸载生命周期。只有本次 `allowed-once` 授权；`rejected`、`cancelled`、`unavailable`、异常、身份缺失及 `approval: never` 均不执行。超时终止底层请求，迟到批准不能复活工具；所有出口清理计时器和监听器。

业务上“超时拒绝”可能在原生审计中记为 `cancelled`，不能伪造 `rejected`。解析超时、审批超时与工具执行超时是不同故障；本计时器不覆盖其他插件或 Auto Review 发出的审批。

## 凭据防泄露

R-M1：对受管工具结果中的高置信真实凭据默认完整遮罩，不保留密钥前后缀，不增加 Ask/Deny；保持非秘密诊断和原有成功/失败语义。不使用任意高熵全禁、全盘扫描或外部 DLP。

R-M2：受管 Shell/结构化 HTTP 参数直接内联真实凭据，且有明确扩散风险和可行替代时使用纠正型 Deny；变量引用、示例、占位符和正常间接认证不因关键词拒绝。建议现有 Secret Manager、环境变量引用或可信认证机制，不迁移或改写 `.env`。

`tool/call` 可能先于预审持久化，拦截不能撤销此前参数。Native/PTC 的 content、value、错误、meta、额外上下文、子调用日志与顶层输出必须逐出口验收；Hook 的某个字段已打码不等于所有出口净化，更不能清除历史 transcript。当前真实出口范围待验证。

## 不默认启用的候选与失败分类

Git clean/reset/restore/强推/强删引用、直接删除已注册 Worktree、复制后高价值源删除、云/数据库/容器/系统及厂商 Secret CLI 的逐命令矩阵仍为候选。不能将 `&&` 或 `-ErrorAction Stop` 当成可靠副本证明，也不按旧关键词清单一律 Ask/Deny。

文件数量仅可补充独立规则已命中的 Ask/纠正型 Deny；不为普通大量缓存清理设门，1000 是研究起点。计数未知或失败不独立升级判定。

必检调用的解析器/协议/关联故障采用 fail-closed，明确是检查不可用；有效语法的 Unknown 不自动 Deny。不存在旧“判定异常全局 fail-open”的兜底授权。
