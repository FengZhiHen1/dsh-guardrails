# dsh-guardrails 可重建豁免

**状态：目标契约（未编码）。** 本文定义可重建豁免的判据；当前实现覆盖哪些判据不归本文拥有。

## 权威范围

本文拥有**可重建豁免的判据**：豁免成立的必要条件、文件级与目录级的证据形态、不予豁免的范围，以及豁免与删除计数的接口。

相邻事实的归属如下：删除分档的动作与阈值归需求（R-07、R-14）；计数口径归规则模型；证据的采集由证据适配器负责。本文不重复这些内容。

豁免只影响计数，绝不是删除许可：受保护文件、灾难身份、挂载边界与链接逃逸规则始终生效。

## 豁免判据总则（证据而非名字）

**两条同时成立才算豁免**：形态候选（路径、文件名与所在项目符合可重建产物的形态）与归属、再生证据（能证明它属于该项目且可由项目重建）。任一缺失即照常计数。

- **候选不等于豁免**：匹配到形态只进入证据校验，本身不减计数。
- **名字不授予豁免**：目录名或文件名相同不构成豁免；`node_modules`、`dist`、`build`、`target` 等常见名只是候选，仍需证据。
- **保守方向**：无法证实即照常计数；不因无法判断而放行。
- **链接不豁免**：符号链接与链接条目不被跟随、不被豁免，作为删除条目计数。
- **项目根定位**：项目根由精确 marker 文件名确认（如 `pyproject.toml`、`Cargo.toml`）；marker 只用于定位边界，存在本身不授予豁免；嵌套项目不继承外层 marker。
- **路径形态限制**：产物路径用 `/` 分隔、相对已确证的项目根；出现绝对路径、盘符、UNC 根或 `..` 段一律不豁免。
- **边界包含**：产物必须位于「可信工作区边界 → 已确证项目根 → 产物」的精确段前缀之内；比较区分大小写，仅大小写别名不算包含（NTFS 可存在大小写敏感目录，无法证实即计数）。
- **归档与依赖域**：从工作区边界到项目根、以及项目根到产物的相对段中，出现 `backup`、`archives`、`snapshot`、`vendor`、`third_party`、`node_modules`、`.git` 等归档或依赖段即不豁免（该比较不分大小写）。目录级判定时，被判定目录自身不套用本条，其上级路径仍受约束。`vendor` 等依赖目录是否改按工具约定证据豁免待确认，见 TODO「可重建豁免的工具约定证据」；在此之前不豁免。
- **Git 归属**：已跟踪索引条目不豁免；Git 状态不可证（证据不可用）不豁免。Git 比较允许大小写折叠——折叠只会撤销豁免，方向安全。

## 文件级可重建证据

文件级豁免要求：常规文件、位于项目根内、不在归档或依赖域、Git 未跟踪且状态可证、存在配对的再生源。

| 产物形态（项目根相对） | 证据要点 |
|---|---|
| `__pycache__/<stem>.cpython-<ver>.pyc`（可带 PEP 488 `.opt-N`；stem 须为严格 Python 标识符） | `__pycache__` 所在目录内存在配对的 `<stem>.py` 源文件 |
| `.pytest_cache/v/cache/{nodeids,lastfailed,stepwise}` | 存在 pytest 配置 marker，且位于项目或 VCS 域内 |
| `.mypy_cache/<major>.<minor>/…/<module>.{data,meta}.json` | 存在 mypy 配置 marker，且位于项目或 VCS 域内 |
| `target/classes/**/<Name>.class`、`target/test-classes/**/<Name>.class` | 对应 `src/main/java` 或 `src/test/java` 下的 `.java` 源；嵌套 `$` 内部类映射到外层 `.java`；支持默认包 |
| `<name>.tsbuildinfo` | 由有界、严格解析的 `tsconfig.json` 按官方公式推出该路径 |

TypeScript 是有限子集，不追求全配置支持：

- 支持显式 `tsBuildInfoFile` 覆盖，以及官方公式 `rootDir` + `outDir`（buildinfo 位于 `<outDir>/<config 相对 rootDir 的路径>/<config 名>.tsbuildinfo`）。
- 配置仅含 `outFile` 且无显式 `tsBuildInfoFile` 时不豁免：官方文档对命名有歧义，两种猜测名都不做猜测豁免。
- `extends`、`references` 以及子串型选项无法有界解析时不豁免。
- 不运行 `tsc`、不加载 TypeScript SDK、不新增依赖来推断；未知一律照常计数。

## 目录级可重建证据

目录可整体豁免，但判据仍是证据而非目录名。以下条件必须全部成立：

1. 已确证的项目根内，按精确段前缀包含。
2. 真实路径解析后仍在项目内；目录本身不是符号链接，也不跨挂载点。
3. Git 归属可证且未被跟踪：目录整体处于被忽略或未跟踪状态。
4. 存在可重建证据：目录由项目声明的包管理器或构建工具生成，且归属与再生方式可证实——依赖声明与包目录内容对应（如锁文件与 `node_modules` 的包目录）、构建配置声明的输出目录与产物对应、工具专属的目录结构可识别。只有可证实的生成方式构成证据，目录名本身不算。
5. 目录内不含受保护文件、凭据或用户数据；无法确认即不放行。

- **候选范围**：`node_modules`、`dist`、`build`、`target` 等是常见候选，同判据同样适用于其它构建输出与缓存目录；名字本身不豁免。
- **子树覆盖**：目录级豁免覆盖其整棵子树，清单中以目录为单位单列该豁免目录，不逐个展开。
- **混合目录的回退**：目录内出现任一不满足项（受保护文件、用户数据、无法证实的子项）时，整目录不豁免，改按条目逐项计数；其中能单独命中文件级证据的条目仍可豁免。
- **与文件级的关系**：文件级证据独立成立，不依赖目录级；目录级不成立不影响文件级已命中的条目。

## 不予豁免的范围

- 用户数据、源码、配置、锁文件、`.env`、凭据与私钥：即使位于可重建目录内或伪装成产物形态，也不豁免。
- 链接条目与挂载跨越。
- Cargo 依赖产物（如 `target/<profile>/deps/*.{rlib,rmeta,d}`）：无法在不执行工具链的情况下证明依赖来源，不自动豁免；`Cargo.toml` 只作项目边界 marker，不授予任何豁免。
- 无法证实归属或再生证据的构建输出与依赖目录：不因目录名或工具名相同而豁免，照常计数。
- 缓存目录内的其它文件（如 `CACHEDIR.TAG`、非版本目录、非 `.json` 文件）。
- Maven 的其它产物（如 `maven-status/`、`surefire-reports/`、`site/`、`*.jar`）。
- 证据缺失或证据预算耗尽的条目。
- 用户自加名单：不接受外部配置注入；识别集合内置固定。

## 与删除分档的关系

- 豁免只减计数、不加权限：受保护文件、灾难身份、挂载边界与链接逃逸不受豁免影响。
- 计数口径（目录去重单列、工作区外同样计数、早停表述）不归本文拥有。
- 阈值与动作归需求 R-07：非豁免条目在阈值内放行、超过阈值确认。
- 命中可重建不等于放行：它只改变计数，最终动作仍由单一决策点按判定顺序给出。
