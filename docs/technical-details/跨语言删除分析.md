# dsh-guardrails Python 与 JavaScript/TypeScript 语法接入

本文拥有 Python、JavaScript 和 TypeScript 的运行器入口、符号绑定、操作映射、目标计算与子进程转发。分析输入来自 PTC 或内联源码；解释器脚本文件（`python`、`node`、`tsx`、`deno`、`bun` 等）正文不读取，按[执行分析](执行分析.md)的覆盖边界处理，追溯 R-17、R-19 及 DSR-023、DSR-026、DSR-027、DSR-028。

本文只填充[执行分析](执行分析.md)定义的输入与返回结果，不新增返回结构：`operations`（操作事实）保留动作、目标、执行域（`domain`）、源码位置、执行条件与来源（`origin`）；`candidates`（风险候选）、`status`（完成、部分覆盖、检查故障）与 `gaps`（缺口）沿用同一契约；目标种类只有 `exact`、`pattern`、`subtree`、`unknown`。判定动作、阈值、确认与配置归[规则模型](规则模型.md)与[需求](../需求.md)；前门分类与调用关联归[架构重构设计](架构重构设计.md)；解析器选型、版本与交付形态归[技术栈设计](../技术栈设计.md)；符号解析限定为该文档声明的有界别名与局部摘要范围，不扩展为完整符号引擎。

全部规则只读源码与项目声明。分析期间不执行待审程序，不导入或加载其模块，不求值用户函数、`eval`/`exec`、动态导入与命令替换，不运行包管理器生命周期，也不启动被调程序。

## 运行器和内联源

前门交来已证实的解释器身份、参数向量、工作目录与执行域。本层按运行器解析出与[执行分析](执行分析.md)「输入与来源」同形的输入单元，不重复前门的分类。

| 入口形态 | 识别前提 | 产出单元 | 前提不成立时 |
|---|---|---|---|
| `python`、`node`、`tsx`、`deno`、`bun` 后接脚本 | 解释器身份已证实；脚本在已证执行域内可定位 | 不读取脚本正文，记录覆盖缺口 `script-file-body-not-analyzed`；语言按运行器与扩展名记录 | 覆盖缺口，保留已知来源 |
| `python -c <text>`、`node -e <text>` | 选项语义已证实为内联源码 | `source=inline` | 不把未知选项后的值当源码 |
| `uv run <inner>` | 内层命令语义未改变 | 递归交回本入口，内层单元进入本文 | 覆盖缺口 |
| `npm run`、`pnpm run`、`yarn run` `<script>` | 已定位 `package.json`，脚本存在且为字符串 | 脚本文本交[Shell 语法接入](命令文本分析.md)；其中的运行器调用再递归回本层 | 脚本缺失、非字符串或需执行生命周期均记覆盖缺口 |
| `run_code`（PTC） | `ctx.ptcRuntime.language` 可证为 TypeScript 或 Python | `source=inline`，来源记录 PTC 程序位置 | 语言不可证记覆盖缺口 |
| 已识别但未接入分析器的运行器（如 `ruby`、`perl`、`php`） | 已证实为解释器入口 | 只产覆盖缺口 | — |

- 语言按运行器与扩展名共同判定：`.py` 为 Python；`.js`、`.mjs`、`.cjs` 为 JavaScript；`.ts`、`.mts`、`.cts`、`.tsx`、`.jsx` 按 TypeScript/JavaScript 语法；`tsx` 按 TypeScript。运行器与扩展名冲突时以运行器为准并记缺口。内联源不按扩展名判定。
- 除已证实的脚本位置与内联选项外，其余参数原样保留给该源码单元，不改变入口语义；参数只影响目标计算，不改变语言判定。
- 相对路径只用已证工作目录做词法拼接。链接解析、文件身份、大小写折叠与卷比较归证据层。链接无法验证、文件缺失、读取失败、编码不可判定或超过单文件读取上限 时记覆盖缺口并保留来源。
- 同一（来源、执行域、语言）只解析一次；嵌套回环不重复解析，也不重复产出操作事实。
- 标准输入载入（`python -`、无脚本参数的 `node` 等）不在首批覆盖，记覆盖缺口。
- 项目脚本只读取 `package.json` 的 `scripts` 文本，不执行 `pre`/`post` 生命周期、不安装依赖、不推导包管理器配置。脚本文本进入 Shell 层后若再出现语言运行器，递归回本层并沿用同一预算与来源链。

**PTC 输入边界。** `run_code` 的载荷按运行时声明语言进入本层，程序正文按对应语言解析。`tools.<name>` 是 SDK 子调用，不当作删除 sink；其派发另走各自执行关联与守卫，本层不重复裁决。程序文本不是 Shell 文本，不按 Shell 方言解析。运行时能力声明可证明不提供某模块（如 `node:fs`、`subprocess`）时，不产操作事实并记录来源；能力无法证明时不据此丢弃已识别 sink，操作事实照常产出，能力未证记覆盖缺口。

## 符号绑定与别名

本层只解析模块与名称绑定，不做类型推断、控制流敏感分析或跨包追踪。

| Python 语法 | 绑定结果 | 首批 |
|---|---|---|
| `import os`、`import os as o`、`import shutil`、`import pathlib` | 模块绑定 | 是 |
| `from os import remove`、`from os import remove as rm`、`from shutil import rmtree`、`from pathlib import Path` | 属性或类绑定 | 是 |
| `f = os.remove`、`f = shutil.rmtree`、`f = Path` | 名称转发，进入别名链 | 是 |
| `def purge(p): ...`、`lambda p: ...` 及其直接调用 | 单层摘要，按调用点展开 | 是 |
| `from .helpers import purge` | 一层跨文件，模块须可读且在域内 | 可证时 |
| `getattr(os, name)`、`__import__`、`importlib`、`from os import *` | 绑定未知 | 否 |

| JavaScript/TypeScript 语法 | 绑定结果 | 首批 |
|---|---|---|
| `import { rm } from 'node:fs'`、`import { rm as del } from 'node:fs'` | 具名绑定 | 是 |
| `import * as fs from 'node:fs'` | 命名空间绑定 | 是 |
| `import fs from 'node:fs'` | 默认绑定；仅在模块契约可证时当命名空间 | 可证时 |
| `const fs = require('node:fs')`、`const { rmSync: del } = require('node:fs')` | 命名空间或解构绑定 | 是 |
| `fs['rmSync']` 等字符串字面量成员 | 成员绑定 | 是 |
| `import type`、`import { type A, rm }` 中的类型项 | 类型位置，不产生运行时绑定 | 是 |
| `export { rmSync as removeTree } from 'node:fs'` | 重导出，一层跨文件 | 可证时 |
| `const purge = (p) => fs.rmSync(p, ...)`、`function purge(p) {...}` 及其直接调用 | 单层摘要 | 是 |
| 计算键、`Object.assign` 注入、原型改写、类方法与 `this` 接收者、依赖注入容器 | 绑定未知 | 否 |

- 重新赋值、解包、增强赋值、条件赋值、同名形参与局部变量遮蔽都终止该名称的已知绑定；终止后的使用按未知处理，不沿用旧绑定。
- 别名与转发链合计最多 4 跳；调用摘要只展开一层局部函数；递归与互递归调用截断并记缺口。
- 跨文件只跟进同执行域内可读项目模块的一层导入或重导出；模块无法解析、路径越出域、读取失败或超预算时绑定未知并记缺口。
- 方法语义按接收者类型判断：`Path.unlink`、`Path.rmdir` 只在接收者可证为 `pathlib.Path` 时识别；`fs.rmSync`、`unlinkSync` 等只在 `node:fs`、`node:fs/promises` 命名空间或 `fs-extra` 已证契约下识别。名称相同不互相借用语义。
- 绑定只表示可调用身份。调用出现在数据位置（仅作为参数传递、写入字符串、文档示例）时不产操作事实。

下表是首批支持矩阵。语义目标按 API 契约定义；「首批」列为「否（需已证版本契约）」的行，在取得该库的已证版本契约前不得声明为已支持，交付前按覆盖缺口处理，证据登记见 [TODO](../TODO.md)。

| 语言 | 调用 | 动作 | 目标 | 首批 | 备注 |
|---|---|---|---|---|---|
| Python | `os.remove(path)`、`os.unlink(path)` | 文件删除 | 第 1 位置参数 | 是 | 出现 `dir_fd` 时目标记 `unknown`，基准不可证 |
| Python | `os.rmdir(path)` | 文件删除（目录条目，非递归） | 第 1 位置参数 | 是 | 删除非空目录在运行时失败，不改变动作 |
| Python | `shutil.rmtree(path)` | 递归删除 | 第 1 位置参数 | 是 | `ignore_errors`、`onerror`、`onexc` 不改变目标与动作 |
| Python | `pathlib.Path.unlink(self, missing_ok=False)` | 文件删除 | 接收者 | 是 | `missing_ok` 不改变目标与动作 |
| Python | `pathlib.Path.rmdir(self)` | 文件删除（目录条目，非递归） | 接收者 | 是 | — |
| Python | `os.rename(src, dst)`、`os.replace(src, dst)`、`shutil.move(src, dst)` | 移走源 | 第 1 位置参数 | 是 | 只产移走源操作事实；处置归规则模型 |
| Python | `os.removedirs(path)` | — | — | 否 | 逐级清理父目录，语义独立 |
| Python | `os.exec*`、`os.spawn*`、`posix_spawn` | — | — | 否 | 执行面记覆盖缺口 |
| JavaScript/TypeScript | `fs.rm(path[, options])`、`fs.rmSync`、`fs.promises.rm` | 文件删除。`recursive: true` 时为递归删除 | 第 1 位置参数 | 是 | `force`、`maxRetries`、`retryDelay` 不改变目标与动作。递归选项不可证时使用 `recursive=unknown` |
| JavaScript/TypeScript | `fs.unlink`、`fs.unlinkSync`、`fs.promises.unlink` | 文件删除 | 第 1 位置参数 | 是 | 对目录调用在运行时失败，不改变动作 |
| JavaScript/TypeScript | `fs.rmdir`、`fs.rmdirSync`、`fs.promises.rmdir` | 移除目录条目 | 第 1 位置参数 | 是 | 未传 `recursive` 时为非递归。传入该选项时，是否支持及实际递归语义按被调 Node 版本确认。版本或选项不可证时使用 `recursive=unknown` |
| JavaScript/TypeScript | `fs.rename`、`fs.renameSync`、`fs.promises.rename` | 移走源 | 第 1 位置参数 | 是 | 只产移走源操作事实 |
| JavaScript/TypeScript | `rimraf(...)`、`rimraf.sync(...)`、`rimraf.rimrafSync(...)` | 递归删除 | 第 1 位置参数 | 否（需已证版本契约） | 导出形态随主版本变化：v4 有默认导出，v5 起无默认导出，同步方法名 `rimrafSync` |
| JavaScript/TypeScript | `fs-extra` 的 `remove`、`removeSync`、`emptyDir`、`emptyDirSync` | 递归删除（`emptyDir` 为清空目录内容） | 第 1 位置参数 | 否（需已证版本契约） | 需已证版本契约 |
| JavaScript/TypeScript | `fs.cp`、`copyFile`、`copyFileSync` | — | — | 否 | 非删除 |
| JavaScript/TypeScript | `fs.glob`、`fs.promises.glob` | — | — | 否 | 版本契约未定，枚举不在首批 |

- 文件删除、递归删除和非递归目录移除使用 `action=delete`，递归语义由 `recursive` 表达。移走源使用 `action=move-source`。在可证目标上可能覆盖内容的移动还记录目标写。
- 每个识别到的调用产出一条操作事实。调用位于可静态判定为不执行的路径（如 `if False`）时不产操作事实。
- 未建模的第三方删除库不进入矩阵；相应调用记覆盖缺口，不按方法名或包名推断删除语义。
- 枚举与过滤不产生删除操作事实，只在被 sink 消费时参与目标表达；映射见下一节。

## 目标计算与静态小范围追踪

目标只做词法求值：基准 = 已证工作目录或字面量绝对路径，再加可求的路径片段。语言层不访问文件系统、不读环境变量、不解析链接、不探测存在性；这些事实归证据适配器。

| 可求值形式 | 说明 |
|---|---|
| 字符串、无替换模板字符串、已知常量的模板替换 | 每个替换表达式都必须可求 |
| 字符串拼接 | 两侧可求 |
| `path.join`、`path.resolve`、`path.dirname`、`path.basename`、`path.normalize` | Node 的纯词法运算；`resolve` 以已证工作目录补全 |
| `os.path.join`、`os.path.dirname`、`os.path.basename`、`os.path.abspath`、`os.path.normpath` | Python 的词法运算；`abspath` 以已证工作目录补全 |
| `Path(...)`、`Path / 'x'`、`Path.joinpath`、`Path.parent`、`Path.name`、`Path.cwd()` | Python 的词法构造与已证工作目录 |
| `__file__`、`__filename`、`__dirname`、`process.cwd()`、`import.meta.url`、`new URL(..., import.meta.url)` 与 `fileURLToPath` | 仅文件入口可证；内联源无这些绑定 |

- 不可求值的形式记 `unknown` 并保留原因：`Path.resolve()`、`os.path.realpath`、`fs.realpath`、`expanduser`、`Path.home()`、`os.environ`、`process.env`、用户输入、网络、时间、随机数、文件内容、不可无歧义解码的 `bytes` 路径。`__file__` 链上出现 `resolve()` 同样不可求。
- 名称绑定只接受单一可达赋值且值可求的情况。多次赋值、分支合并、循环更新不求解。
- 可静态枚举的字面量集合最多 8 项；超过上限或含非字面量项时目标为 `unknown`，保留基准路径与已证项数。
- 分支条件可折叠为真或假时只保留实际路径。不可折叠时保留各分支的可求目标，最多 4 支；超过上限记 `unknown`。
- 局部参数按位置与关键字名映射；默认值只在字面量时生效；`*args`、`**kwargs`、解包与展开不求解。
- 同一操作内重复求出的路径可以合并。不同调用点各自保留操作事实和来源，跨操作去重由证据适配器完成。
- 不展开目录内容。`pattern` 与 `subtree` 只是目标表达，实际盘存归证据层。

| 求值结果 | 目标种类 |
|---|---|
| 单个路径或字面量路径集合 | `exact` |
| 基准目录加通配模式，如 `glob.glob(os.path.join(d, '*.tmp'))`、`Path(d).glob('**/*.log')` | `pattern` |
| 已知根目录的一层枚举，如 `os.listdir(d)`、`Path.iterdir()`、`fs.readdir(d)` | `subtree`，附注「只展开一层」 |
| 一层枚举后由 `startswith`、`endswith`、`suffix`、`endsWith` 与字面量构成的单一过滤 | `pattern`（基准目录加模式） |
| 其余过滤、基准不明目标 | `unknown`，保留已证部分 |

执行条件按调用位置确定，取值沿用[执行分析](执行分析.md)的三档：

- **确定执行**：调用位于无条件路径，或所有支配条件的常量折叠结果均为真。
- **可能执行**：调用有可确定的调用点，但位于循环体、异常清理路径或不可折叠分支内，运行时可能跳过。
- **未知**：调用所在函数的调用点不可确定，或调用目标本身不可确定，导致该操作是否会被执行无法判断。

## 子进程与命令文本转发

| 语言与 API | 映射 |
|---|---|
| Python `subprocess.run`、`call`、`check_call`、`check_output`、`Popen` 的首个位置参数或 `args` | 列表或元组中，`argv[0]` 为程序身份，其余为参数向量。交共用分析入口处理 |
| Python 同类调用的字符串形式且 `shell=False`（默认） | POSIX 上表示单个程序路径；Windows 由系统命令行规则解析，无本方言语义时记覆盖缺口 |
| Python `shell=True` 的可求文本、`os.system`、`os.popen` | 文本单元；方言由执行域决定：POSIX 交[命令文本分析](命令文本分析.md)，Windows 的 `cmd.exe` 未接入时记覆盖缺口 |
| Python `asyncio.create_subprocess_exec`、`create_subprocess_shell` | 分别按参数向量与文本处理 |
| Node `spawn`、`spawnSync`、`execFile`、`execFileSync` | `command` 为程序身份，`args` 全为字面量时保留向量；`shell: true` 时按平台引用规则重建文本，仅当全部参数可求且引用规则已知 |
| Node `exec`、`execSync` | 可求文本单元，方言同上；Windows 的 `ComSpec` 未接入时记覆盖缺口 |
| Node `child_process.fork(modulePath)` | 视为 JavaScript 文件入口（`source=file`），`argv` 保留；`execArgv` 不改变入口；正文不读取（RR-5） |

- 文本与向量单元交回统一入口，沿用同一预算、执行域与来源链；同一（来源、执行域、文本或向量）不重复解析。
- 程序身份不可证（变量、拼接、条件表达式）时产风险候选（已识别执行入口、程序不可证）并保留来源，不产操作事实。不按文本关键词把内容升级为候选。
- 嵌套文本中的语言运行器调用递归回本层，其他命令由 Shell 层处理。
- 首批不覆盖：Python `os.exec*`、`os.spawn*`、`posix_spawn`；Node `worker_threads`、`cluster` 的代码加载；`deno`、`bun` 的子进程 API。相应单元记覆盖缺口。
- 分析期间不启动被调程序、不执行文本、不求值命令替换或管道。

## 不可判定边界

| 构造 | 本层记录 |
|---|---|
| 已识别 sink，目标不可求 | 保留操作事实，目标 `unknown`，附原因与已证范围（基准目录、绝对前缀、已证项数）；不产候选 |
| 目标依赖文件系统实况（链接、真实路径、存在性、跨挂载） | 目标 `unknown`，原因标明需要证据层 |
| 绑定来自未建模第三方、动态属性或反射 | 覆盖缺口；若调用形态是已识别 sink 但接收者不可证，同样记缺口 |
| 调用只出现在数据位置 | 无操作事实，无缺口 |
| 源码无法整体解析 | 覆盖缺口，该单元无操作事实 |
| 局部解析失败、未建模调用 | 部分覆盖，保留已取得事实 |
| 预算耗尽 | 停止展开，保留已取得操作事实与缺口；未求值目标保持 `unknown` |
| 运行器未接入、标准输入源、方言未接入、PTC 能力未证 | 覆盖缺口，无操作事实 |
| 动态程序身份或不可分析代码载荷 | 风险候选，附来源；无操作事实 |

不可判定不是放行结论。语言层只提交证据与状态；是否确认或拒绝由规则层与单一决策点按[规则模型](规则模型.md)判定。

## 失败分类只产证据

本层只产出 `operations`、`candidates`、`status` 与 `gaps`。下表列出本层产出与本层不做的处置。

| 情形 | 本层产出 | 本层不做 |
|---|---|---|
| 无分析器或运行器未接入 | 覆盖缺口（语言、入口、来源），状态为部分覆盖 | 不产操作事实，不产判定 |
| 源码不可读、超过单文件读取上限、编码不可判定、链接未解析 | 覆盖缺口与来源 | 不猜测源码内容 |
| 局部解析失败、未建模调用、预算耗尽 | 已取得操作事实加缺口，状态为部分覆盖 | 不丢弃已知事实 |
| 已识别 sink 且目标 `unknown` | 操作事实，目标 `unknown` | 不自行升级为确认或拒绝 |
| 动态程序身份或不可分析载荷 | 风险候选与来源 | 不按文本关键词扩展候选 |
| 解析器崩溃、协议损坏、内部异常、超时 | 状态为检查故障，附阶段与来源 | 不返回空结果冒充完成 |
| 完成且无操作事实 | 状态为完成，操作集为空 | 不主张「无副作用」或「已覆盖全部副作用」 |

- 原因词汇由本层使用，不改变[执行分析](执行分析.md)的字段：`no-provider`、`unreadable`、`too-large`、`encoding-unknown`、`link-unresolved`、`syntax-error`、`unsupported-syntax`、`unresolved-import`、`dynamic-binding`、`dynamic-target`、`budget`、`unmodeled-library`、`unmodeled-dialect`、`stdin-source`、`capability-unknown`、`fault`。
- 诊断只记录输入单元、原因码、来源与已证范围，不复制源码正文。
- 同一来源的重复嵌套只记一条缺口；同一缺口不重复累加。
- 状态取值与判定顺序归[执行分析](执行分析.md)与[规则模型](规则模型.md)，本层不新增状态值。

## 验收

用 Node 内置 `node:test` 与合成夹具。夹具只被读取，不被执行。断言对象是操作事实、目标种类、执行条件、来源、执行域、状态与缺口，不重复实现算法；失败注入与覆盖缺口分别断言。

| ID | 用例 | 期望 |
|---|---|---|
| A-01 | 同一删除源码分别以 `python a.py`、`python -c`、`run_code`（Python 声明）进入 | 动作与目标一致，`origin` 指向各入口，语言标识一致 |
| A-02 | `npm run clean` 的脚本文本为 `node clean.mjs`；`uv run python -c "..."` | 两层来源链保留，内层源码被分析，脚本正文与内联源产出同一操作集合 |
| A-03 | `ruby cleanup.rb`、`php cleanup.php` | 只产覆盖缺口（`no-provider`），状态为部分覆盖，无操作事实 |
| A-04 | `import os as o; o.remove(p)`、`from shutil import rmtree as rm; rm(d)`、三跳别名转发 | 各产出一条对应操作事实，目标为 `exact` |
| A-05 | `f = os.remove; f = log; f(p)`、形参遮蔽模块名、解包与条件赋值 | 无操作事实，缺省记 `dynamic-binding`，不沿用旧绑定 |
| A-06 | `def purge(p): os.remove(p)` 加字面量实参；`Path(root) / name` | 摘要展开产出操作事实；拼接目标为 `exact` |
| A-07 | `import { rm as del } from 'node:fs'`、`import * as fs`、`const { rmSync: d } = require('node:fs')`、默认导入 | 可证绑定产出操作事实；不可证默认导入记缺口 |
| A-08 | `import type` 与混合类型项、`fs['rmSync']` | 类型项不产操作；字面量成员可解析；计算键记缺口 |
| A-09 | 模块名称被重新赋值、使用 `fs.rmdirSync` 的递归选项、引用无已证版本契约的 `rimraf` | 重新赋值不沿用旧绑定。递归选项依被调版本确认，契约未知时保留 `recursive=unknown`。需已证版本契约的行按缺口处理 |
| A-10 | `path.join`、`os.path.join`、`Path /`、`path.resolve` | 目标为 `exact`，路径词法归一，大小写保持原样 |
| A-11 | `glob.glob(os.path.join(d, '*.tmp'))`、`os.listdir(d)`、枚举后 `endswith('.log')` 过滤、`fs.readdir` | 分别为 `pattern`、`subtree`（附注一层）、升级为 `pattern`、`subtree` |
| A-12 | `os.remove(os.environ['P'])`、`Path.home() / 'x'`、`Path(__file__).resolve()` | 目标为 `unknown`，原因分别为环境变量、身份、需证据层，已证部分保留 |
| A-13 | 无条件调用、循环体内调用、调用点不可确定的函数内调用 | 执行条件分别为确定执行、可能执行、未知 |
| A-14 | `subprocess.run(['rm','-rf',p])` 与 `rm -rf p` 命令行 | 等价操作事实，来源与执行域一致，目标按身份去重 |
| A-15 | `shell=True` 的 POSIX 文本、Windows 上的同类文本 | 前者按方言分析；后者记 `unmodeled-dialect` 缺口，无操作事实、无候选 |
| A-16 | 程序名由变量决定的 `subprocess.run([program, p])` | 产风险候选（动态执行入口），无操作事实 |
| A-17 | 文档字符串、注释、普通字符串、`if False:` 分支中的删除调用 | 均无操作事实；字符串只作为数据 |
| A-18 | 超出单文件字节上限、编码不可证、解析器异常、局部预算耗尽 | 前两者使用 `too-large` 或 `encoding-unknown`。异常为 `fault`。局部预算耗尽保留已证事实并报告 `partial` |
| A-19 | 夹具在被执行时会创建标记文件 | 分析后标记不存在；无子进程、无文件写入、无网络访问 |
| A-20 | 同一字面量路径分别从宿主与 WSL 执行域进入 | 执行域不同，操作事实不合并；嵌套来源链完整 |

- 脚本正文、内联源与 PTC 的等价源码必须产出相同操作集合，差异只允许出现在来源位置。
- 每个目标种类（`exact`、`pattern`、`subtree`、`unknown`）与每个执行条件至少一条正例和一条反例。
- 覆盖缺口与检查故障分别断言，不合并为同一结果；空操作集不等于无副作用。
- 改变语言映射、绑定规则或目标计算规则时，先补成对回归用例，再改实现。
