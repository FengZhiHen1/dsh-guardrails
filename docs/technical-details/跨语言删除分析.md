# dsh-guardrails 跨语言删除分析

> 实现状态：目标契约（未编码）。

## 权威范围与追溯

本文权威定义 Python 与 TypeScript/JavaScript 的删除分析：

- 入口识别。
- 语言与内联源识别。
- 删除 sink 识别。
- 有界目标求值。
- 动态目标转确认。
- 依赖选型与失败语义。

执行面载荷的语言事实只在本文定义一次：

- `run_code`（PTC）的载荷是 PTC 运行时语言（`ctx.ptcRuntime.language`，TypeScript 或 Python）的程序源码。
- 内联选项（`python -c`、`node -e` 等）把源码作为内联源。
- 语言运行时入口包括脚本文件、`uv run`、`npm` / `pnpm` / `yarn run`、`tsx`、`deno`、`bun`。

拦截前门分类与决策点顺序归[架构重构设计](架构重构设计.md)；规则号、分档阈值与确认语义归[需求](../需求.md)与[规则模型](规则模型.md)。它们引用上述载荷与语言事实，不重复定义。

追溯：[DSR-023](../decisions/DSR-023-语言层动态删除目标限时审批.md)（语言层动态目标转确认）、[DSR-024](../decisions/DSR-024-删除分析管线重构.md)（架构重构）、[DSR-025](../decisions/DSR-025-定位重定位与判定模型重构.md)（三档判定）、[DSR-026](../decisions/DSR-026-执行面尽力分析.md)（执行面尽力分析）；需求 R-17。

## 目标与边界

**目标**：把语言运行器入口与执行面载荷纳入与命令行删除相同的证据与判定链——识别脚本入口、识别删除 sink、静态求出目标、交单一决策点处置。分析只读源码，不执行待分析程序。

**非目标**：

- 不实现语言解释器，不在分析阶段执行待分析脚本或求值任意表达式。
- 不做全量数据流、类型推断或通用语义分析。
- 不覆盖远端、容器内、云 SDK 与内嵌 SQL 的副作用。
- 不追求对对抗性代码的完备性。
- 不重复定义拦截前门分类、决策顺序与删除分档阈值。

## 依赖选型

| 语言 | 选定 | 理由与重访条件 |
|---|---|---|
| Python | 标准库 `ast` 加 `Jedi` | 已有隔离试验佐证，外部依赖低。Astroid 未验证，作为备选；若 Jedi 的跨文件符号解析在真实项目上超出预算，重访 Astroid 或 Pyright |
| Node/TS | 官方 TypeScript Compiler API | 类型、别名与跨文件追踪已验证；不引入 ts-morph（未验证、依赖更重）。若 Compiler API 初始化开销不可接受，重访 ts-morph |
| 运行时 | 现有 Node 进程内分析，不新起长驻解释器进程 | 复用现有解析器池；Python 若需 `ast` 以外的能力再评估子进程 |

原则：每门语言只维护一套主分析能力，不堆叠 AST、LSP、类型服务器与扫描器；只在插件内维护与文件删除相关的定向抽象解释，不重写语言语义。

## 入口识别

输入结构化工具调用（命令、argv、cwd、方言、执行域），输出：

```text
EntryPoint {
  language: 'python' | 'node' | 'typescript' | 'ruby' | 'perl' | 'php' | ...,
  sourceKind: 'file' | 'inline' | 'run_code',
  sourcePath?: string,
  inlineSource?: string,
  argv: string[],
  cwd: string,
  provenance: 'direct' | 'uv' | 'npm-script' | 'pnpm' | 'tsx' | 'deno' | 'bun' | 'ptc-run-code' | ...,
  inspectability: 'readable' | 'missing' | 'unreadable' | 'too-large' | 'encoding-unknown' | 'no-provider'
}
```

- **脚本入口**：`python file.py`、`node file.js`、`tsx file.ts`、`deno`、`bun`、`uv run python …`、`npm run` / `pnpm` / `yarn run`。`run` 只读解析 `package.json` 或 `pyproject.toml` 得到脚本，绝不运行 npm lifecycle。
- **内联源**：`python -c`、`node -e` 等把源码放入 `inlineSource`，交对应 provider 分析。
- **`run_code`（PTC）**：按 `ctx.ptcRuntime.language` 取载荷语言，源码作为 `inlineSource` 交对应 provider，分析其直接删除副作用；`tools.<name>` SDK 子调用在派发时另走各自守卫，本层不重复裁决。
- **无 provider 的运行时**（ruby、perl、php 等）：识别脚本入口并标 `inspectability: 'no-provider'`，交失败语义转确认，不放行。
- **不可读入口**：脚本路径含链接、编码不可判定、超过 1 MiB、执行域跨越时记不可读，交失败语义分流。

## 删除 sink 识别

只读解析源码，用 AST、符号解析与已知框架函数语义识别删除汇点：

- **Python**：`os.remove` / `unlink` / `rmdir`、`shutil.rmtree`、`Path.unlink` / `rmdir`、别名与直接导入、小范围自定义清理函数（单层摘要）。
- **Node/TS**：`node:fs` 与 `node:fs/promises` 的 `rm` / `rmSync` / `unlink` / `unlinkSync` / `rmdir` / `rmdirSync`、`rimraf`、`fs-extra` 的对应方法（按明确版本的方法契约）。
- **子进程**：`subprocess` / `child_process` 直接传静态 argv 时，交回 Shell provider 递归分析；动态 argv 记为未知。

输出与核心删除意图对齐：

```text
DeleteSink {
  language, origin: { file, line, function },
  effect: 'remove-file' | 'remove-tree' | 'move-source',
  targetExpression: string,
  resolved: AbstractPath,
  condition: 'unconditional' | 'conditional' | 'unknown'
}
```

`AbstractPath` 的字段形状归[架构重构设计](架构重构设计.md)「删除 sink 识别」。`condition = 'conditional'` 标为可能删除，不声称必删。

## 有界目标求值

只解释明确许可的纯路径操作：字符串字面量、有限拼接、`Path(...)`、`path.join` / `resolve`、已知 cwd、静态赋值、局部函数形参与实参的定向传播、受限简单分支与循环、`glob` / `iterdir` / `readdir` 的只读枚举、常用 `startswith` / `endswith` / `suffix` / `endsWith` 过滤。

禁止：`eval` / `exec`、Python `import` 执行、Node `require` / `import` 执行、任意用户函数调用、Shell 命令替换求值，以防分析阶段产生真实副作用。求值预算耗尽时返回 `{ kind: 'unknown', reason: 'budget' }`。

## 动态目标转确认

已识别删除 sink 而目标为 `unknown` 时，统一转确认：

- 命令行字面量与语言层计算出的目标适用同一规则：目标不可枚举即产确认，附已知范围，并说明不可枚举部分（[DSR-025](../decisions/DSR-025-定位重定位与判定模型重构.md)；需求 R-07）。
- 范围要求与一次性语义归[需求](../需求.md) R-09 与[规则模型](规则模型.md)「确认语义」，本文不重复。
- 目标一旦命中灾难身份，直接拒绝，不因来自语言层而降级为确认。

## 失败语义

| 情形 | 处置 |
|---|---|
| 入口不可读、超限或编码未知 | 含删除候选语法时，能列范围则确认，否则拒绝；无候选则放行 |
| 解析器内部异常 | 拒绝本次调用 |
| 求值预算耗尽 | 已识别 sink 转确认；无 sink 放行 |
| 第三方不透明调用（未建模库） | 放行并声明可能漏报；不因调用未知函数整体拒绝 |
| 无 provider 的运行时（ruby、perl、php） | 识别脚本后转确认，不放行 |

## 与三档判定的关系

- **合并计数**：语言层能求出的目标与命令行删除在同一调用内合并去重计数，按删除分档处置（阈值与动作见[需求](../需求.md) R-07）。
- **受保护文件**：命中受保护文件不因来自语言层而豁免；内容级操作按凭据面确认。
- **灾难身份**：脚本计算出的目标一旦求值命中真实设备或卷、宿主根与系统树、真实 Git common-dir 主体，直接拒绝。
- **可重建豁免**：语言层目标同样按证据判据豁免，不因来自脚本而放宽（判据见[可重建豁免](批量删除白名单.md)）。
