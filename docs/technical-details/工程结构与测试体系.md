# dsh-guardrails 工程结构与测试体系

## 权威范围

本文唯一拥有 `dsh-guardrails` 的源码目录结构、模块边界、依赖方向、测试分层、覆盖率门禁与验证流程。规则机制归 `规则模型.md` 与 `命令文本分析.md`，部署归 `部署.md`，需求与验收归 `../需求.md`。

## 结论先行

- 源码结构（v1.4.0 起，对齐仓库 core/adapter 单包分层约定）：`index.js` 薄转发 + `src/core/` 六模块（纯领域逻辑，禁 import `@deepseek-ai/*`，裸 node 可测）+ `src/adapter/host.js`（DSH 接线）+ `src/client/card.js`（浏览器半侧自包含 lazy-CJS）；依赖单向 adapter→core，名单唯一维护点。
- 测试体系：六层（单元 / 生命周期 / 集成 / 组合 / 发布 / 名单驱动），零依赖 `node:test`；覆盖率报告 + 门禁阈值 80% 起步。
- 验证流程：`verify/run-verify.mjs` 一键全量（单测+集成+生命周期 → 覆盖率 → 组合断言 → tarball 干净安装冒烟）；冒烟为手动步骤。

## 源码结构

```text
plugins/dsh-guardrails/
├── index.js                  # 薄转发：export * from src/adapter/host.js（包名解析锚点）
├── src/
│   ├── core/                 # 功能层：纯领域逻辑，禁 import @deepseek-ai/*（分层门禁强制）
│   │   ├── rules.js          # 敏感名单数据 + 文本引用正则 + 类别开关求值（唯一同步维护点，无依赖）
│   │   ├── path-check.js     # 路径归一 + checkPath（按操作类型套规则）+ 系统区判定
│   │   ├── command.js        # 词法 tokenize + 动词集合 + 列举模式判定 + 字面量重建 + cd 链状态 + 系统区写检测
│   │   ├── destructive.js    # 破坏性命令分析：六子族函数（git/machine/eval/cli/bulk/target）与配置叶子同构
│   │   ├── deny-messages.js  # deny 消息文案渲染 + 操作叶子门控（leafEnabled）
│   │   └── check-command.js  # pwsh 判定管线：core 各 pass 的纯组合
│   ├── adapter/
│   │   └── host.js           # DSH 适配层：Config schema、installSection 接线、base 解析（DSR-007）、guard 装配
│   └── client/
│       └── card.js           # 浏览器半侧设置卡片（手写 lazy-CJS，自包含；exports["./client"] 直指此文件）
├── cordis.patch.yml
├── package.json
├── README.md
├── test/
│   ├── fixtures/             # 行为级样本：命令组合场景、路径边界
│   ├── rules.test.mjs        # 名单/正则单测（名单驱动，遍历数据表生成正反用例）
│   ├── path-check.test.mjs   # 路径规则单测
│   ├── command.test.mjs      # 词法/动词/列举判定/cd 链/system 写检测单测
│   ├── destructive.test.mjs  # 破坏性分析单测
│   ├── base-dir.test.mjs     # DSR-007：base 来源（sandboxPolicy.resolve 调用形状/缺席降级/fail-open）
│   ├── lifecycle.test.mjs    # mount/dispose/remount/HMR/双挂载/非法配置（mock ctx 记录 disposer）
│   ├── settings.test.mjs     # installSection 语义：entry 为 base、用户覆盖热生效、provider detach 回落
│   └── guard.integration.test.mjs  # mock ctx 驱动 guard 钩子的全矩阵（语义保存锚）
└── verify/
    └── run-verify.mjs        # 全量验证：单测+集成+生命周期 → 覆盖率 → composition 断言 → 干净安装冒烟
```

### 模块职责

| 模块 | 职责 | 不承担 |
|---|---|---|
| `index.js` | 包根薄转发（`export * from src/adapter/host.js`），承载包名解析 | 任何逻辑 |
| `src/adapter/host.js` | 官方插件入口（具名导出 `name`/`inject`/`Config`/`apply`）：`Config` 为 Schemastery schema（loader 在 apply 前验证并填默认值）、`installSection` settings 接线（entry 为 base、热生效、detach 回落）、`sandboxPolicy.resolve({ session })` 基准目录解析（DSR-007）、`ctx.tools.guard` 装配、钩子异常 fail-open | 任何规则判定逻辑 |
| `src/core/rules.js` | 名单数据（文件名/后缀/目录段/相邻段组合/系统区前缀与段组合）、文本引用正则、叶子级配置求值与校验（DSR-006） | 路径解析、命令词法 |
| `src/core/path-check.js` | 路径归一（`slash`/`segmentsOf`/`resolvePath`/`baseNameOf`）、`checkPath`（`metadataOnly` 分级 + 操作叶子）、`isSystemAreaPath` | 命令文本分析 |
| `src/core/command.js` | `tokenizePwsh`、动词集合、`isListingOnly`、`classifyVerb`/`assessContentClass`、敏感文本引用判定、`resolveCommandLiterals`（字面量重建）、cd 链状态、`assessSystemWrite`（W0 写检测）、`assessUnverifiable` | 破坏性判定 |
| `src/core/destructive.js` | `assessDestructive`：六子族函数（git/machine/eval/cli/bulk/target，与配置叶子一一同构）+ `$(...)` 递归 + eval 全文模式 | 敏感名单 |
| `src/core/deny-messages.js` | deny 消息文案（NO_BYPASS_GUIDANCE + escalateFor 统一形状）、`PATH_REASON_BY_CATEGORY`、`leafEnabled` 操作叶子门控 | 判定逻辑 |
| `src/core/check-command.js` | pwsh 判定管线：字面量重建 → 列举/内容分类 → 文本引用 → W0 系统写 → unverifiable fail-safe → 破坏性分析 | 名单数据 |
| `src/client/card.js` | 浏览器半侧设置卡片：读 settings scope 快照渲染叶子开关，写回用户设置文档；手写 lazy-CJS 自包含（纯净度门禁禁跨包值导入），子组件拆分（Chevron/CardHeader/CategoryRow/UnverifiableRow/GuardCard） | Host 判定 |

### 依赖方向

```text
src/adapter/host.js → @deepseek-ai/schemastery        # 配置 schema（运行时依赖）
src/adapter/host.js → src/core/{rules,path-check,check-command,deny-messages}.js
src/core/check-command.js → src/core/{rules,command,destructive,deny-messages}.js
src/core/destructive.js → src/core/command.js          # 词法、片段工具与共享 cd 链状态
src/core/destructive.js → src/core/path-check.js       # cd 链模拟的路径工具
src/core/command.js → src/core/{rules,path-check}.js
src/core/path-check.js → src/core/rules.js
src/core/rules.js、src/core/deny-messages.js（无依赖）
```

依赖方向单向 adapter→core；core 禁止 import `@deepseek-ai/*`、禁止反引 adapter——仓库分层门禁（`tools/plugin-layering-check.mjs`）实质生效（v1.4.0 起，core 文件 6 个）。`rules.js` 是名单与文本正则的唯一维护点，任何名单变更只改此文件。

## 测试体系

### 分层

| 层 | 载体 | 覆盖内容 | 运行条件 |
|---|---|---|---|
| 单元 | `test/{rules,path-check,command,destructive}.test.mjs` | 直接 import `src/core/*`：名单匹配、路径解析、词法、动词分类、列举判定、cd 链状态、system 写检测、破坏性分析分支 | 无（纯内存） |
| 生命周期 | `test/lifecycle.test.mjs` | mock ctx 记录 effect disposer：mount/dispose/remount ×20、HMR 重放、双挂载不静默去重、非法配置挂载失败（兼覆盖 sandboxPolicy 缺席分支） | 无（纯内存） |
| settings | `test/settings.test.mjs` | mock `installSection` 镜像官方语义：entry 为 base 层、用户文档覆盖热生效、provider detach 回落 entry、无 settings 服务按行配置工作 | 无（纯内存） |
| 基准目录 | `test/base-dir.test.mjs` | DSR-007：`sandboxPolicy.resolve({ session })` 调用形状、agentless 回落部署根、无服务降级 base `''`、resolve 抛错 fail-open | 无（纯内存） |
| 集成 | `test/guard.integration.test.mjs` | mock ctx 驱动完整 guard 钩子：误伤消除、防护保持、配置开关、混合命令、重定向、R0/system 新增用例（AC-05/AC-06） | 无（纯内存） |
| 组合 | `verify/run-verify.mjs` 内嵌 | 调实例版本二进制 `--dump-config`（`DSH_BIN` 指定，AGENTS.md 跨代红线）：test/web 各恰一行、无重复行、web 依赖为发布物形态 | `DSH_BIN` + `DSH_TEST_HOME`/`DSH_WEB_HOME`（缺省回落 `DSH_HOME`） |
| 发布 | `verify/run-verify.mjs` 内嵌 | `npm pack` → 临时目录 `npm install` tarball → 导入并校验包内文件（干净环境，无源码/兄弟包） | npm CLI（`node <npm-cli.js>`） |
| 名单驱动 | `rules.test.mjs` 遍历 `src/core/rules.js` 数据表 | 每个名单项自动生成"命中正例 + 相邻反例" | 无 |

### 名单驱动机制

`rules.js` 以结构化数据导出名单（如 `{ basenames: [...], suffixes: [...], dirSegments: [...], combos: [...], systemPrefixes: [...] }`）。`rules.test.mjs` 遍历数据表为每项生成正反用例。**新增名单项 = 修改 `rules.js` 数据 = 测试自动覆盖**，不要求手工补 fixture；`test/fixtures/` 只放行为级样本（组合场景、边界、回归命令），不放名单逐项样本。

### 覆盖率与门禁

- `node --test --experimental-test-coverage`（Node 24 内置，零依赖）。
- 门禁：行覆盖 ≥ 80%；`verify/run-verify.mjs` 解析文本报告 `all files` 行自动断言（2026-08 实测格式，总体行覆盖 96.15%）。
- 安全关键代码（名单、破坏性分支）不设豁免；漏覆盖分支必须在实现时补用例或显式标注豁免理由。

### 脚本

| script | 命令 | 内容 |
|---|---|---|
| `test` | `node --test test/*.test.mjs` | 单元 + 集成 + 生命周期 + settings + 基准目录 |
| `check` | `node --check index.js src/core/*.js src/adapter/*.js src/client/*.js && node --test test/*.test.mjs` | 语法门禁 + 测试 |
| `verify` | `node verify/run-verify.mjs` | 全量：单测+集成 → 覆盖率摘要 → composition 断言 → 冒烟提示 |

外部门禁（仓库根运行）：`node tools/plugin-layering-check.mjs plugins/dsh-guardrails`（分层 purity：core 禁 `@deepseek-ai/*` import、禁反引 adapter）；`quality_floor`（code-craft 质量地板）。

## 验证流程

`verify/run-verify.mjs` 执行顺序：

1. `node --test test/*.test.mjs`：单元 + 集成，失败即退出；
2. 覆盖率报告：输出行覆盖摘要，低于门禁阈值给出告警（阈值执行方式见上）；
3. composition 断言：调用 `DSH_BIN` 指定的**实例版本二进制** `--profile test/web --dump-config`（test 用 `DSH_TEST_HOME`，web 用 `DSH_WEB_HOME`——launcher 托管下二者分属不同 HOME），断言 test 与 web 各恰一行 `guardrails` 且解析自 `dsh-guardrails` 包、web 依赖为发布物形态、均无重复行与源码残留；
4. test profile 启动冒烟（发布门禁）：`--port 0` 临时端口起真实 test profile，存活窗口内无崩溃与激活错误；
5. 输出汇总，并提示冒烟步骤（重启 test profile 后手动验证真实拦截行为）。

## 约束与重访条件

- C-01 零测试依赖：只用 Node 内置 `node:test` 与 coverage，不引入测试框架。
- C-02 名单单一维护点：任何敏感名单或文本正则变更只改 `src/core/rules.js`。
- C-03 依赖方向单向（分层门禁强制）：`src/core/` 禁 import `@deepseek-ai/*`、禁反引 adapter；`src/core/rules.js` 不得 import 其他模块。
- C-04 部署校验二进制：verify 的组合断言与启动冒烟只用 `DSH_BIN` 指定的实例版本二进制（AGENTS.md 跨代红线；缺省回落遗留全局 CLI 时打印告警）。
- 重访：覆盖率门禁的自动化执行（CI 或脚本解析）、CI 接入、跨平台 fixtures（Linux/macOS 命令样本）。
