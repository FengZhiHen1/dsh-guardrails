|---|---|---|

**分层边界声明**：核心判定（`src/core/`）必须可被裸 Node 导入并用合成证据测试，不导入 Cordis、`@deepseek-ai/*` 或 `src/adapter/`。分析模块不访问审批服务；证据模块不返回执行判定。依赖方向归 [项目结构设计](../项目结构设计.md)，本文只验证依赖方向成立（LS-01、LS-02）。

## 工具前门 / DSH Soft-Hard gate 关联

测试必须覆盖「工具前门」到「DSH 执行门禁」的完整链路，而不是只测分析函数。按 DSH 官方工具契约，真实链路是：

1. **工具前门分类**以实际选中的工具定义为准（[架构重构设计](架构重构设计.md)「前门分类」）。检查类别与实际注册范围由 GT 类验证。
2. **有序 pre-execute 瀑布**（DSH `tools/pre-execute`，`@mode waterfall`）：插件的异步分析监听器在此取证与判定，结果以**同一个 `ToolExecution` 对象**为键写入 `WeakMap`。瀑布可被前置监听器提前短路（不调用 `next`）。
3. **DSH Soft gate**：pre-execute 的 `ask`/`deny` 结果与上游审批策略在此生效，可被其他 listener 影响。
4. **DSH Hard gate（最终同步 guard）**：DSH 的 `ToolGuard` 只有拒绝或放行、没有 allow 结果，因此任何 listener 顺序无法把拒绝翻回放行。插件在 `ctx.tools.guard` 注册的同步 guard 即此 Hard gate。

测试含义（矩阵 GT 类）：只测 Soft gate（pre-execute 返回 `deny`）不够；必须证明**即使前置监听器短路 pre-execute、或把结果改写为 allow，Hard gate 仍以「缺少可信分析结果」拒绝**。这正是「前置短路不得静默放行」的可观察投影（DSR-027 与 [架构重构设计](架构重构设计.md)「并发与生命周期」）。未接真实运行时时在合成 `ctx` 上断言；接真实 `ToolRuntime` 后复验。

### GF — 覆盖缺口 vs 检查故障

结果区分「局部覆盖缺口」与「整次检查故障」，二者判决不同（[规则模型](规则模型.md)「失败分类与提示格式」；本文只投影为可观察信号）。

| 编号 | 用例（故障注入） | 预期判决 | 信号 |
|---|---|---|---|
| GF-01 | 无分析器语言（Ruby/Perl/PHP）且无其他风险证据 | 放行并记录覆盖诊断 | `status=partial`、`gaps` 含 `no-provider`、判定 `allow` |
| GF-02 | pwsh helper 返回 reqId 不匹配 / 多余输出 / 协议错 | 拒绝检查故障 | `status=fault` → 拒绝，helper 重启 |
| GF-03 | shfmt 二进制 SHA256 不匹配 | 拒绝检查故障 | `status=fault` → 拒绝，不加载不匹配二进制 |
| GF-04 | 分别注入局部源码超限、分析请求未能受理、整次截止时间到期 | 局部超限返回 `partial`。无可信结果时按 `fault` 拒绝 | 断言每一步的状态、原因、剩余证据及派发次数 |
| GF-05 | 已进入盘存后计数/关键身份取证失败 | 拒绝 | 拒绝且不执行；可重建证明不足仅撤销豁免、照常计数 |

| GF-08 | 局部解析失败但同调用其他单元有有效结果 | 保留证据 + 缺口 + 按风险候选处置 | `status=partial` 且有风险候选时按已知范围 `confirm`/`deny` |

GF-07 与 GT-02 是同一行为的分析与门禁两面：GF 看「结果状态为何缺失」，GT 看「Hard gate 是否仍拒绝」。

| EX-03 | meta / 错误结果 | 打码 content，meta 记残余 | content 打码；`meta` 中若含 secret 记录为残余面 |
| EX-04 | PTC bridge：program value、finalizeContent、日志 hook | value 与 content 分离 | 结构化 value 按 withhold 策略处理（含可遮罩内容时整体 withhold）；`content` 打码 |
| EX-05 | 会话持久化、历史 transcript、已发送参数 | 不承诺清除 | 显式记为不承诺；测试结论只覆盖「未发送的出口」 |

EX-02/EX-03/EX-04 的「残余出口」是 [需求](../需求.md) AC-04 与 [TODO](../TODO.md)「未覆盖出口的遮罩边界」的具体化。矩阵要求**如实记录残余**，而不是要求这些出口零泄漏。

## 失败不得报绿：判决规则

执行与记录时，以下情形一律判红或记「未验证」，不得写成通过：

1. **skip 不等于 pass**。真实运行时未就绪时相关用例 skip；skip 只说明未执行，不说明行为正确。记录的通过数必须是**实际执行的 pass**，skip 单独计。
2. **直接 Node 通过不扩张为包管理器通过**。`node --test` 通过不等于 `pnpm test` 通过；若后者因环境失败，写「Node 直跑通过、pnpm 失败」，不得合并为「测试通过」。
3. **目标项缺实现即红/缺证据**。OR-02、CF-03/04、RC-04、PK-04…06、PL-01…03 等在实现缺失时只能记「目标未实现，缺证据」，不能因「未报错」记绿。
4. **合成通过不等于真实误伤率**。合成语料通过率不得当作历史误伤/漏拦率（见下「性能与回放」）。
5. **前门只测 Soft gate 不算通过**。GT-02 未断言 Hard gate 拒绝时，该集成判定视为未覆盖。
6. **残余出口如实记录**。EX-02/03/04 的残余面必须写进证据，不得省略后宣称零泄漏。
7. **仅语法检查通过不等于测试通过**。只做 `node --check` 的语法验证只证明可解析。

一条判决成立的最低证据是：`判决证据` 与 `信号` 两列都得到观察值，且该观察值可复现（命令、输入、平台、退出码留存）。

## 证据记录格式

每次验证在 `docs/verification/` 新增一份带日期、实现轮次可追溯的记录（或续写既有记录的新轮次），必须包含：

- **目标**：本次验证的矩阵编号集合（如 `AC-01b, GF-02, GT-02`）。
- **环境**：DSH 版本锚点、Node 版本、操作系统、插件提交、是否接真实 `ToolRuntime`。
- **命令**：逐条列出实际执行的命令原文与退出码。
- **结果**：逐编号的 pass / fail / skip / not-run，附测试计数（总/通过/失败/skip）与 skip 构成。
- **判决证据**：每条 pass 对应 `信号` 列的观察值（规则号、dispatch 次数、verdict、残余面）。
- **缺口**：未执行的编号、原因，以及「缺证据」声明。

历史记录是快照，不改写；新一轮数字独立成节。精确数字只在验证记录出现一次，契约文档不复述单次统计。

## 性能与回放

性能口径（本文拥有方法，不拥有阈值）：

- 分别测：pwsh helper 冷启动、helper 热路径、`shfmt` 每次启动的分布、输入字节与 AST 大小、并发与恢复。
- 用 p50/p95/p99 分位而非均值汇总；分平台采集。测试套件总耗时不代表单次调用生产延迟。
- **本文不给出任何未实测的性能阈值**。发布门禁只要求「采集到某平台某负载下的分位数据并留证」，阈值在取得本机基线后于验证记录中给出现场实测值，不预设数字（[技术栈设计](../技术栈设计.md)「分析器定版条件」第 2 条）。

回放口径：

- 只读回放只用官方解析器与纯策略函数，不执行语料、不观测磁盘目标；其安全声明须随回放输出标注。
- 语料 `status=not-run`（无独立确定 oracle、明确排除、POSIX-only 等）计为「未复核」，不当作已通过。
- 历史命令语料规模只是资料规模；人工标注回放未完成前，不得据此宣称新规则的误伤率或漏拦率。误伤与漏拦以人工标注语料回放为准，合成用例通过率不能替代。
