# dsh-guardrails 工程结构与测试体系

## 分层合同

本篇描述当前重构的职责边界与验证方法，源码仍由实施任务收敛，具体文件清单以最终交付为准。

| 层 | 职责 | 边界 |
|---|---|---|
| 包根入口 | 薄转发与 bundle 解析 | 不承载策略 |
| `src/core/` | 精确规则数据、路径/风险事实判定、审批结果映射、高置信打码 | 裸 Node 可测；不 import `@deepseek-ai/*` 或反向依赖 adapter |
| `src/adapter/` | Config 与官方自动设置、DSH 钩子、审批、执行 WeakMap、Provider IPC、目标身份探测、结果出口适配 | 依赖单向 adapter → core；不自造 Shell tokenizer |
| Parser helper / vendor | 官方 PowerShell 语法事实、固定 shfmt 二进制与校验元数据 | 不执行待审文本；平台包是否完整须另验 |
| `test/` | 稳定表驱动正反行为、Provider 与生命周期测试 | 合成凭据与隔离目标，不使用真实生产密钥 |
| `verify/` | 源码验证入口 | 仅语法与测试，不启动实例、不修改部署 HOME |

设置目标为 schema 自动表单，旧 `src/client/card.js` 自绘不再是本轮 UI 合同。包元数据与 client 入口清理由实施任务负责，未完成前不以旧 client 布线测试通过宣称自动表单可用。

## 测试层与证据

| 层 | 应证明的行为 |
|---|---|
| 领域单元 | 精确目标、动作矩阵、优先级、Unknown 与故障区分、打码正反例和格式保真 |
| Parser 合同 | 官方 AST 有效/无效语法、引用文本/未调用函数不误判、插值/替换潜在执行、超时/崩溃/非法回包 |
| DSH 集成 | 同一 execution 对象关联、pre-execute 提前短路后最终 guard 仍拒绝、批准一次不可复用、never/迟到/取消 |
| 生命周期与资源 | helper 惰性启动/恢复/卸载，并发请求不串线；输入/输出/深度/并发有界；无遗留 timer/listener/进程 |
| 平台与目标 | Windows/Linux 分别实跑，cwd、大小写、symlink/Junction、Git common-dir/Worktree、镜像与真实设备身份 |
| 出口与持久化 | Native/PTC 的模型可见结果、SDK value、错误/meta/上下文、子调用日志、顶层结果、会话持久化逐一核验 |
| 包与实例 | 干净包安装/导入、二进制清单/哈希、peer、唯一激活行、自动设置页保存与功能 |

用 Node 内置 `node:test`，规则变化用稳定成对回归验证，不以重复实现算法的测试替代行为。行覆盖目标沿用 ≥80%，但本轮新覆盖率须真实采集，不能继承旧 98% 数值。仓库分层检查从管理仓库运行 `node tools/plugin-layering-check.mjs plugins/dsh-guardrails`。

## 执行验证

按包实际脚本运行测试；必要时直接 `node --test test/*.test.mjs` 区分测试失败与包管理器自动安装失败。记录命令、平台、退出码、测试数量、耗时、skip 与证据范围。若失败源自 EPERM，不把它写成通过，也不将直接 Node 通过扩张为 `pnpm test` 成功。

当前 verify 已移除旧的直接 spawn 实例、部署 HOME dump 和临时 npm 安装阶段，只做源码语法与测试，默认不会启动实例或修改部署 HOME。实例启停另走官方启动器/dshl 且须已有授权。组合验证使用现场查询所得的目标实例版本 bin 和独立 HOME，不默认历史路径。

性能需要分别测 helper 冷/热启动、shfmt 每次启动 p50/p95/p99、输入/AST 大小、并发和恢复。测试套件总耗时不代表单调用生产延迟。历史 97,050 条命令仅是资料规模，本轮未完成标注回放；不得据此前统计宣称新规则误伤率。
