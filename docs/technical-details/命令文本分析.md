## 官方 AST 接入

语法权威只有微软 PowerShell Parser 和官方 `mvdan/sh` AST。不得保留旧分词器或自写 Bash lexer，也不得把第二权威、并集检测或故障回退作为解析来源。

| Provider | 固定接入 | 返回事实 |
|---|---|---|
| PowerShell | 惰性启动的持久受信 `pwsh` helper，调用 `System.Management.Automation.Language.Parser.ParseInput` | 有界结构化命令、参数、重定向、执行上下文、ParseErrors 与未知事实 |
| Bash | 本地官方 `shfmt v3.12.0 --language-dialect=bash --to-json`，`shell: false`，stdin 输入 | 官方 typed JSON AST，经验证后提取精简事实 |

- **固定与可校验**：shfmt 锁定版本、来源与校验和；首版交付 Windows x64、Linux x64/arm64；不在工具调用时下载。
- **待审文本是数据**：不 `eval`、不 `Invoke-Expression`、不执行待审脚本。helper 用请求 ID 关联回包；固定可执行文件与参数独立于用户文本。
- **方言按实际受管方言选择**，不按宿主 OS 猜测 Bash、POSIX、Zsh 或 WSL。
- **不要求运行机额外安装 Go 或 Bash** 完成文本解析。

## 递归包装层解包

对已知包装层（`wsl`、`bash`、`sh`、`pwsh` / `powershell`、`cmd`），按官方解析器已产生的 argv 做有界递归解包：

- **命名规则保守**：路径限定的程序名（如 `/tmp/bash`、`C:\evil\bash`、`./pwsh`）不作可信包装层，可能只是任意外部程序。POSIX 源方言下仅精确裸名（`bash`、`sh`、`pwsh`、`wsl`）可信；`BASH`、`bash.exe`、`Bash` 不解包，保留并标未知。Windows/PowerShell 源方言下大小写不敏感并剥离 `.exe`。
- **内层命令保留来源**：解包出的命令附 `dialect`、`domain`（`host` 或 `wsl`）与可证的 `cwd`；WSL 命令可携带 `distribution`、`user`。
- **不静默丢弃**：无法解析或语义不确定处保留为命令或显式未知，任何内容不得静默消失。
- **全局预算**：解包深度、调用数、命令数均有上限；超预算进入失败分流，不静默放行。
- **不越权声明**：不声称外层 AST 等于下游解释器的原生 argv；不支持的引号语义与歧义上下文交下游处置。
- **cwd 取现场值**：取自当前工作目录服务（Inspect 现场 API），不只用初始 header 或 workspace。

## 有界事实提取

解析器只报告事实，不产判定。提取的事实集合构成类型化命令 IR 的输入（IR 字段形状归[架构重构设计](架构重构设计.md)「类型化命令 IR 契约」）：

- **命令名**：字面量、动态，或空/动态执行通道。
- **参数与操作数**：区分参数标志与操作数；值分字面量、变量、替换、通配模式与未知。
- **重定向**：操作符与目标值。
- **作用域与方言**：script、scriptblock、子表达式等。
- **可证 cwd**：由现场工作目录与同调用内字面量 `cd` 变更推出；无法证明即标未知，不沿用旧假设。
- **数据位置标注**：`git -m`、`grep -e` / `-F`、`rg -e`、`gh -t` / `-b`、`echo` / `printf`、`Write-Output` / `Write-Host` 的参数标为数据位置，供删除 sink 识别跳过。
- **未知与动态**：证据不足的一律标未知，不猜、不静默消失。
- **有界推断**：只覆盖可证明的字面量事实（单次静态赋值的常量传播、纯字符串方法调用等）；超出边界即标未知，推断预算与解包预算同一口径。

本层不读文件系统、不做删除计数、不产出判定结果。

## 执行身份与最终门禁

1. `tools/pre-execute` 对本次执行异步完成官方 AST 与事实提取，结果随本次执行进入下游证据与判定（两钩子契约见[架构重构设计](架构重构设计.md)「并发与生命周期」）。
2. 结果以当前 `ToolExecution` 对象为键保存（WeakMap），不用文本哈希、裸 callId 或上一次确认作为授权身份。
3. 同步 `ctx.tools.guard` 只消费已完成结果做最终拒绝，不做异步解析或等待。
4. 属于必检 Shell 且缺少本次可信完整结果时，最终门禁拒绝；即使前置 waterfall 被其他监听器短路，也不得静默执行。
5. 结果只绑定当前执行；新执行重新分析并重新确认。

## 竞态与不保证

- 事实提取与计数都发生在派发前；并发写者或同一调用内先于删除执行的变更，可能在观察后改变目标集。这类变更必须作为失效事实暴露，由失败分流处置，不得当作已检查通过。
- 不声称在并发文件系统变动下阈值内的执行是原子的；接线该处置是集成方的职责。
- 不声称对任意语言语义（SQL、云 SDK、容器内部、远端副作用）完整覆盖；解析成功不等于理解这些语义。

## 故障与资源生命周期

| 状态 | 执行语义 |
|---|---|
| Provider 不可用、崩溃、超时、异常退出、协议损坏或无效 JSON | 进入失败分流，本次执行不得当作已检查通过 |
| ParseErrors、语法失败或结构不足 | 同上；残缺 AST 不得当作检查通过 |
| 本次对象的完整关联结果缺失 | 最终门禁拒绝 |
| 语法有效但事实未知 | 解析层只报告未知，是否升级由决策点按删除相关性判定 |

输入与输出字节、JSON 深度、解析等待、并发与进程数量均有界。取消与插件卸载须清理本次请求、计时器、监听器与子进程；helper 断线后的新请求不得继承旧回包。诊断应脱敏，不回显待审文本中的密钥。
