# dsh-guardrails Shell 语法接入

本文拥有 POSIX/Bash 与 PowerShell 的语法角色、包装层解包、Shell 操作映射、工作目录与执行域、解析器交互边界和 Shell 局部验收，追溯 R-12、R-16、R-19 及 DSR-017、DSR-027。跨语言共用的输入输出、操作事实、覆盖状态与预算归[执行分析](执行分析.md)；DSH 前门、执行关联和最终门禁归[架构重构设计](架构重构设计.md)；解析器选型、版本与交付形态归[技术栈设计](../技术栈设计.md)。本文不重复统一字段与最终判定，只交付 Shell 语言内部如何把文本还原为证据。

## 语法角色

Shell 解析器只从文本提取语法结构：待审文本是数据，解析器不解释、不求值、不执行它，也不启动被审 shell。根解析器按真实执行方言选择：PowerShell 文本交官方 `System.Management.Automation.Language.Parser` 的 AST；Bash 与 POSIX 文本交官方 `shfmt` 的 typed JSON AST。两种回包都保留原始词法边界与类型标记，不先压平成「命令名 + 字符串参数」，否则引号字面量与选项标志的区分会在入口处丢失。

方言由前门取得的实际解释器决定，不由命令名、平台或调用意图猜出。取不到解释器时记覆盖缺口，不按平台默认值推断；同一段文本在不同方言下的含义不同，不跨方言复用解析结果。

### 两种方言的结构覆盖

下表列两种方言要还原的结构角色。左列是共用角色，右列是各解析器承担的结构来源。

| 共用角色 | PowerShell（官方 AST） | Bash / POSIX（shfmt typed JSON） |
|---|---|---|
| 命令位置 | `CommandAst` 的命令元素，`GetCommandName` 与首元素字面量 | `CallExpr` 的首个 `Word`，经 `literalParts` 折叠 |
| 参数与操作数 | `CommandParameterAst`（`-Name`、`-Name:value`）与其余参数元素 | `CallExpr` 的其余 `Word`；`--` 之后一律为操作数 |
| 字面量 | 单引号、无插值双引号、常量、单次可证赋值的字面变量 | `SglQuoted`、无 `$` 的 `DblQuoted`、无转义与通配的 `Lit` |
| 动态值 | 变量、成员、类型表达式、可展开字符串、命令表达式 | `ParamExp`、`CmdSubst`、`ArithmExp`、`ProcSubst`、含转义或通配的 `Lit` |
| 重定向 | `FileRedirectionAst`（`>`、`>>`、`2>`、`*>`）与流合并 | `Redirs`，按 `Op` 映射到运算符表 |
| 执行边界 | 函数定义、scriptblock、子表达式、`&`/`.` 直调 | 函数定义、`Subshell`、`CmdSubst`、`ProcSubst` |
| 控制与循环 | `IfStatementAst`、`LoopStatementAst`、`SwitchStatementAst`、`TryStatementAst`、`TrapStatementAst` | `IfClause`、`ForClause`/`WordIter`/`CStyleLoop`、`WhileClause`、`CaseClause` |
| 赋值 | `AssignmentStatementAst`（含 `env:` 与 `$x =`） | `Assigns`、`DeclClause`、`LetClause` |

两种方言各自产出局部命令 IR，再映射出与共用角色对应的字段。解析器不能表示的语法以显式语法失败结束；能表示但本层不建模的节点以显式 Unknown 结束；任一情况都不静默丢弃。

记 Unknown 的判据是命令身份、参数值或目标集不可证，不是结构种类：

- **控制与循环体不记 Unknown。** 分支与循环内的命令照常产出操作事实，执行条件按[执行分析](执行分析.md)的三档标为 `certain`、`possible` 或 `unknown`。循环变量、`case` 模式只影响依赖它们的参数值与目标。
- **命令身份不可证时记 Unknown**：函数、过滤器、别名或模块覆盖了同名字面命令；`&`/`.`、`Invoke-Expression`、`eval`、`exec` 的动态目标；由变量、拼接或替换构成的命令位置；`Set-Alias`、`Import-Module`、`using module`、`#requires` 改变可用命令集。
- **目标集不可证时按值记 `target.kind=unknown`，不把整条命令记 Unknown**：变量多次赋值、分支合并、循环更新、来自命令输出或环境变量的值、无法求值的参数拼接。普通参数的未知只影响该参数。
- **赋值与常量传播**：单次可证的字面赋值可作为字面量；被重新赋值、解包、条件赋值或循环更新后，依赖它的目标回到 `unknown`。
- **两种方言的引号语义**：PowerShell 单引号与无插值双引号是字面量，`@"…"@` 与双引号内 `$(…)` 会执行；`@'…'@` 是字面数据。Bash 的 heredoc 主体是否执行取决于接收者：接收者是 shell 解释器时按脚本分析（引号只影响展开，不影响执行）；接收者是数据工具时是数据。

### Shell 局部命令字段

Shell 局部命令表示保留以下字段。这些是 Shell 语言内部的表示，作为操作事实的来源输入，不替代执行分析定义的统一字段。

- 命令位置是字面名称、动态表达式或缺失（映射为 `null`）。
- `role` 区分参数（`parameter`）和操作数（`operand`）。值种类区分字面量（`literal`）、变量（`variable`）、替换（`substitution`）、通配（`glob`）与未知（`unknown`）。
- 带引号的 `'--- label ---'` 作为参数时是字面操作数，不被当作选项或命令；语句头只是引号串时是输出语句，不是命令调用。
- 重定向保留操作符、目标和所在单元。写重定向只在可执行位置产出操作事实；包装命令自身携带的重定向归外层单元。
- 保留作用域（`script`/`file`、`scriptblock`、`subexpression`、`Subshell`、`CmdSubst`、`ProcSubst`）。作用域决定一个命令是「本次执行」「可能执行」还是「定义/潜力执行」。
- PowerShell 命令额外携带 `pipeline: { index, source }`：该命令在所在 `PipelineAst` 中的 0 基位置，以及紧邻上游元素的可证文本（只含字面命令名与字面参数，限长，动态内容省略为 `null`）。它是范围标签：不改变执行条件、不产生操作或候选；无显式路径的删除用它表达 `knownScope`。

命令参数中的数据位置由命令语义识别，比如 `grep -e` 的查询、`git commit -m` 的消息、`gh pr create -t/--title` 的标题和 `Write-Output` 的输出文字。可执行的插值、替换和脚本块独立分析，引用中的危险词面本身不构成操作。这样 `grep "rm -rf"`、提交信息中的删除字样、`echo '$(rm ...)'` 都不产出删除操作，而双引号插值、命令替换、可执行 scriptblock 仍被作为执行位置分析。

### 参数解析与选项归属

选项与操作数的归属不由正则把字符串重猜成选项，而由解析器给出的结构确定，再由各命令文法解释。这一分工在入口处固定：

- 解析层只输出命令名、参数 token、字面/动态标记、重定向与作用域，不判定某 token 是「选项」还是「操作数」的业务含义。
- 命令文法判断某个参数是不是选项、是否带值、带值选项是否消耗后继词，以及 `--` 之后一律为操作数。带值选项（如 `-Path`/`-LiteralPath`、`head -n`/`-c`、`grep -e`、`git commit -m`）必须消耗其值，值不得被当成目标或命令名。
- 开关参数按值解释：`-Recurse:$true`、`-WhatIf:$false` 的布尔值决定行为，不能只看开关名。PowerShell 的 `-Path` 支持通配，`-LiteralPath` 不解释通配，这一差别直接决定目标是 `pattern` 还是 `exact`。
- 两种方言的选项拼写不互借：PowerShell cmdlet 的 `-Recurse` 与 POSIX `rm` 的 `-r`/`-R` 是不同的文法；同一字面 token（如 `-WhatIf`、`-whatif`）在不同方言下的含义不同，由方言选择文法，不用一个共用的字面判断。
- 命令名按方言的大小写规则比较：PowerShell 命令名不区分大小写，POSIX 命令与选项区分大小写。

### 数据位置与执行位置的区分

一个 token 是否产生操作，取决于它的语法角色而不是词面：

- 单引号、无插值双引号、注释、PowerShell `@'…'@`、`printf`/`echo` 的参数位——都是数据位置，不产生操作。heredoc 主体按接收者判定：交给 shell 解释器的按脚本分析，交给数据工具的是数据。
- 双引号内插值 `$(...)`、命令替换、过程替换、未加引号 heredoc 主体中的展开、可执行 scriptblock（`&`/`.` 直调、`ForEach-Object`/`Where-Object`/`Invoke-Command` 的块体、`try`/`switch` 分支体）——都是执行位置，其内命令必须作为事实暴露。
- 行内删除字样只有在确有执行位置或删除命令时才构成事实或风险线索；普通参数中的危险词面不产生风险候选。

## 已知包装层

只解包已确认语义的 Shell 包装：`wsl`、`bash`、`sh`、`pwsh`、`powershell`、`unshare`（命名空间透明包装，只交出内层命令）；`cmd /c` 的文本按 cmd 薄方言单独分析，不当作解释器 argv 解包。解包输入是解析器已产出的 argv，不重新切分原文本；外层解析器的词边界不直接当作下游解释器的语法事实，存在歧义时保留不确定状态。

**受信名称。** 带目录分隔符或盘符的名称（绝对路径、相对路径、带盘符）不当作受信解释器解包：它可能是任意外部程序，保留为可见的不透明入口并记缺口，不据 basename 推断身份。POSIX 只接受已知裸名的精确拼写（`bash`、`sh`、`pwsh`、`wsl`）；`BASH`、`bash.exe`、`BaSh` 这类需经大小写折叠或去 `.exe` 才像解释器的名字不解包。Windows 与 PowerShell 按该环境的大小写及 `.exe` 命名规则识别已知包装层。

各包装层的处理约定：

- **`bash`/`sh` 内联脚本**：`bash -c '<文本>'`、`sh -c '<文本>'` 的第一个非选项参数是脚本文本，提取后按对应方言递归分析。`sh` 与 POSIX 模式按 POSIX 文法解析，绝不按 bash 解析（语义不同）。
  - `-c` 可以出现在组合选项里（如 `-lc`、`-ic`、`-xec`）；组合中的其余选项按语义处理，无法证明的标 Unknown。以 `+` 开头的选项（如 `+x`、`+o`）不请求内联命令串。
  - 脚本文本之后的参数依次是 `$0`、`$1`…，按执行分析的 `scriptArgs` 交出；不得把 `$0` 的值当成命令名。脚本内未求值的 `$1` 等仍按变量处理，其目标为 `unknown`。
  - 启动类选项（`-l`/`--login`、`-i`、`--rcfile`、`--init-file`）会加载启动与 profile 代码，标 Unknown 并保留可见。`--posix` 改变解析与展开模式，按 POSIX 处理并记来源；`-r`/`--restricted` 限制 `cd`、重定向与命令查找，相关语义不可证时标 Unknown。
  - 无脚本文件、无 `-c` 的裸 shell 从标准输入读取命令，本次文本不证明其待执行内容，标 Unknown。profile 是否加载只由 `-l`/`-i` 证明，不按「交互式」推断。
- **`pwsh`/`powershell` 内联脚本**：
  - `-Command`/`-c` 后只有一个字面串时提取并递归分析。官方语义要求 `-Command` 的字符串形式是最后一个参数，其后的词都属于命令文本；因此字符串之后再出现额外词时命令串不可证，标 Unknown。
  - `-CommandWithArgs`/`-cwa` 的首个字符串是命令文本，其余词按位置进入 `$args`，按同一 `scriptArgs` 契约交出。
  - `-EncodedCommand`/`-ec` 是不透明载荷，不解包，标 Unknown。
  - `-File`/`-f` 是最后一个参数，其后为脚本路径与脚本参数；脚本文件按「外部脚本文件的只读 IO」处理。
  - 缺少 `-NoProfile`/`-nop` 时 profile 可能重定义命令，标 Unknown，除非可用其它证据排除。
  - `-WorkingDirectory`/`-wd`/`-wo` 的值为可证字面路径时，可证明内层 PowerShell 命令的相对路径基准；它不证明内层外部程序的工作目录（见「工作目录与执行域」）。
  - `-ConfigurationName`/`-config`、`-ConfigurationFile`、`-SettingsFile`、`-PSConsoleFile` 改变会话配置与可用命令集，标 Unknown。
  - `-ExecutionPolicy`/`-ex`/`-ep` 只设置本次会话的执行策略（仅 Windows 生效），不改变被执行的命令文本，作为上下文记录；只在其导致脚本无法运行时由失败语义处置。
  - `-NoLogo`/`-nol`、`-NoExit`/`-noe`、`-NonInteractive`/`-noni`、`-InputFormat`/`-if`、`-OutputFormat`/`-o` 不改变载荷语义，不因此标 Unknown。
  - `-Version`/`-v`、`-Help` 不执行命令文本，不产出操作事实。
- **`wsl`**：
  - 以 `--exec`/`-e` 为界：其后的程序与参数按直接 argv 交下游，不再经发行版 shell 切分；执行域标 `wsl`。
  - 未给 `--exec` 时，剩余命令行由发行版默认 shell 解析执行，分词、展开与 profile 加载都不可证，标 Unknown。
  - `--` 之后的参数原样传给命令。
  - `--distribution`/`-d`、`--user`/`-u`、`--cd` 的值只有可证时才写入执行域；不可证时保留为未知，不猜发行版、用户或目录。
  - 内部程序若是已识别解释器（如 `pwsh`、`bash`），按该方言继续递归；否则保留为不透明程序。
- **`cmd`**：`cmd /c`、`/k` 的内联命令行没有官方语法权威可分析，保留为不透明并标 Unknown。
- **其它 POSIX shell**：
  - `dash` 严格 POSIX，其脚本文件按 POSIX 文法分析。
  - `zsh`、`ksh`、`mksh`、`ash`、`fish` 作为未接入的方言记录覆盖缺口。已证实的独立操作或风险线索随本次结果保留。

**脚本文件形式**。`bash`、已识别的 POSIX Shell 或 `pwsh -File` 的文件参数，按对应版本和方言的入口语义交给统一分析。无法读取或确定脚本文本时，记录原因与来源。

**归属。** 内层单元保留方言、执行域、工作目录和来源位置。包装命令自身携带的重定向由外层单元产出操作事实，不并入内层单元：`bash -c 'rm -rf x' > log` 中 `> log` 由调用方执行，内层 `bash` 只执行脚本文本。重定向既不因解包而丢失，也不改变归属。

## Shell 操作映射

本层把已还原的命令结构映射为对删除分析有意义的事实；动作的最终判定、计数与分档归[规则模型](规则模型.md)与[执行分析](执行分析.md)，这里只描述 Shell 语言如何确认「这是哪类操作」。

- **命令身份**。按可证的命令、平台与运行器解释删除语义。例如，POSIX 的 `rm` 和 `rmdir` 属于不同的程序契约。PowerShell 别名须核对平台和有效会话，命中 `Remove-Item` 时按 cmdlet 的参数契约分析。函数、别名或模块改变身份时追踪可证明的定义，无法证明时记录缺口。
- **递归**：`recursive=false` 只由非递归语义证明；`true` 由 `-Recurse`（含 `-Recurse:$true`）、`rm -r`/`-R`/`--recursive`、目录删除语义等共同证明；参数不足以证明时用 `unknown`。目录树由目标与递归标记一起表达。
- **移动**：`Move-Item`、`mv` 的源产出 `action=move-source`；目标路径能证明被覆盖时另记目标写。目标集按删除同样枚举，但动作不混用。
- **写重定向**：`>`、`>>`、`2>`、`&>`、`*>` 产出文件内容操作事实；`>>` 是追加，不声称清空。是否触发独立的清空规则由策略定义。
- **Git**：先按 `git` 文法切出全局选项（`-C`、`-c`、`--git-dir`、`--work-tree`）与子命令，再切子命令选项和 `--` 之后的路径；子命令到专用动作（`git-clean`、`git-restore`、`git-worktree-remove`、`git-history-destroy`）的映射归规则模型，本层只保证命令名、子命令与参数向量正确。
- **预览**：只有确属该命令与选项组合的预览语义才标 `preview`。
  - PowerShell 的 `-WhatIf`/`-wi` 是风险管理参数：命令支持该参数时，`-WhatIf` 与 `-WhatIf:$true` 是预览，`-WhatIf:$false` 照常执行；命令不支持该参数时 PowerShell 报参数错误、不执行删除，也不因此标预览。
  - `--dry-run`、`-n` 只在命令的官方语义确为预览时成立，如 `git clean -n`/`--dry-run`。`rm` 没有预览选项，`--dry-run` 在 `rm` 上是无效参数。
  - `-Confirm`/`-cf` 是运行时交互确认，不是预览：确认后删除仍会发生，本层不把它当作抑制删除的依据。
  - 选项拼写相同的其它命令不自动获得预览语义：`--dry-run`、`--whatif` 在无该语义的命令上是普通操作数，绝不因此抑制删除分析。

删除目标的表达沿用执行分析的统一目标种类：

- **`exact`**：已知字面路径或可证的字面路径集合。`-LiteralPath` 的值即使含 `*`/`?` 也是字面。非递归地删除目录条目本身也记 `exact`。
- **`pattern`**：已知基准目录与通配规则，如 `-Path '*.tmp'`、`rm -rf build/*.o`。POSIX 通配由外层 shell 展开；未启用 `nullglob` 且无匹配时字面 token 仍传给命令，因此通配目标需要盘存才能得到结果集，本层不声称已枚举。
- **`subtree`**：已知根目录的递归删除。
- **`unknown`**：变量、替换、表达式或运行时上下文未解析，保存原因和可证范围（基准目录、绝对前缀、已证项数）。

Shell 侧对「执行条件」的贡献限于语法：命令在 `script`/`file` 作用域下按直线执行；在 `&&`/`||` 右侧、`if`/`switch`/`case` 分支体、循环体、`try`/`catch`/`trap` 处理体、管道段与后台命令中属于可能执行；可达性无法证明时属于未知。这些条件随操作事实一并交出，供策略区分「必然执行」「可能执行」「未知」。

## 执行/数据/预览

本节在 Shell 角度把操作事实按三种语义归类，与执行分析的统一状态相接，不重复其字段定义：

- **执行事实**：命令身份已识别、且确知在执行位置时产出，如 `rm -rf /x`、`Remove-Item C:\x`、写重定向到具体文件、`git clean`。执行条件取决于所在作用域。
- **数据**：以数据角色出现的内容不产出操作，如引号字面量、注释、只读命令参数位上的危险词、交给数据工具的 heredoc 主体。交给 shell 解释器的 heredoc 主体按执行分析，不属于数据。
- **预览**：确知是 `-WhatIf`/`--dry-run` 时标注预览。预览是否进入破坏性观察与计数、以及混合调用中真实删除部分如何分档，由[规则模型](规则模型.md)定义；本层仍把路径与凭据扫描所需的文本交出，只报告预览标记与作用域。

当命令名可识别为某语言运行时（`node`/`python` 等）时，本层不在 Shell 文法内展开其内联代码，交由跨语言分析（见[跨语言删除分析](跨语言删除分析.md)）；无法展开时保留覆盖缺口，不伪装成已检查。

`sudo`、`env`、`nice`、`time`、`stdbuf`、`nohup`、`command`、`exec`、`timeout` 按 DSR-029 解包为内层命令事实；`unshare` 按 DSR-031 作为命名空间透明包装解包，命名空间能力本身不单独判定。`xargs`、`parallel` 与 `find -delete`/`-exec rm` 按字面 argv 与流式输入表达删除范围。`wsl` 载荷按 DSR-029、`ssh` 主机之后的命令按 DSR-030 分析；`ssh` 的 PowerShell/cmd 接收者按对应方言分析自己的载荷，`ssh host <<EOF` 与 `wsl … bash <<EOF` 的 heredoc 正文按远端 shell 脚本分析。`docker run|exec` 的载荷只在触碰到宿主文件系统时（`-v`/`--volume` 绑定源、`--mount type=bind`、`--device`、`--privileged`）作为容器域子单元分析，其余载荷不分析并记覆盖缺口：本层不按文本关键词推断其载荷，能说明具体载荷的作为已识别执行入口的风险候选报告，载荷不可证的记覆盖缺口。

## 工作目录与执行域

工作目录与执行域是目标解析的前提，两处都要么可证、要么显式未知。本层区分「位置」与「进程工作目录」：前者是当前 shell 解析相对路径的基准，后者是外部程序继承的基准，两者只在可证时相同。

- **Bash/POSIX**：`cd` 改变进程工作目录，子进程继承。只有目标为字面路径、无通配/波浪号/NUL、`..` 段可词法证明、且经只读 `lstat` 证实为真实目录（非符号链接）时，才更新后续命令的工作目录；否则标 Unknown，使之后的相对删除按失败语义保守处置。
- **子 shell 与管道边界**：`( … )`、命令替换、过程替换、管道段与后台命令中的 `cd` 不改变外层目录。挂在 `&&`/`||` 右侧的 `cd` 只在条件成立时生效，其后的目录在条件不可证时按 Unknown 处理。
- **PowerShell**：`Set-Location` 及其别名 `cd`、`chdir`、`sl` 改变当前 runspace 的位置。官方语义明确位置与进程工作目录不同，外部程序继承的 cwd 不由位置保证：内层 PowerShell 命令的相对路径可用位置解析，内层启动的外部程序的相对路径基准不可证，相关目标标 `unknown`。`Push-Location`/`Pop-Location`、`Set-Location -StackName`、`cd -`/`cd +` 的历史与位置栈不可证时标 Unknown。`HKLM:`、`Env:` 等非文件系统提供程序的位置不改变文件系统基准，按 Unknown 处理。
- **`wsl`**：`--cd` 以 `/` 开头是发行版内绝对路径；否则是 Windows 绝对路径，需要可证的挂载映射。未给 `--cd` 时工作目录由 WSL 从宿主 cwd 映射到发行版内，或取发行版默认目录；映射与默认值不可证时标 Unknown。
- **`pwsh -WorkingDirectory`**：字面值可证明内层 PowerShell 命令的相对路径基准，不证明内层外部程序的 cwd。
- **会话状态变更**：`alias`、`export`、`set`/`shopt`（改变展开、位置或交互语义）、`source`/`.`、`eval`、`exec`、`Set-Variable`、`Import-Module`、`Set-Alias`、`Invoke-Expression` 等使依赖它们的命令身份、展开或目标集不可信，按依赖关系标 Unknown；不受影响的命令照常产出事实。
- **执行域**：执行域（宿主、WSL、容器或远端）决定路径如何解释。宿主域用本机文件系统视图解析路径；非宿主域不能从宿主视图读取其脚本文件或盘存其目标，相关证据标 Unknown，不猜测，也不把 `/mnt/c` 与 `C:` 视为同一对象。执行域随每个内层单元保存，并进入统一操作事实。

解析器与观察器共用同一个已取得的工作目录，避免解析、观察与计数各自推断而产生不一致。

工作目录和执行域本身不等于删除范围：一个路径或目录名不能证明其删除范围，范围仍须由目标盘存与证据确定。

## 解析器交互边界

解析器通过受控的进程边界交互，边界决定哪些是可信事实、预算从哪里来、失败如何归类。Shell 层只消费解析器声明的结果；协议或进度失效不被解释为「没有删除」。

### 进程边界与可信来源

- **PowerShell**：持久、惰性启动的受信 `pwsh` helper。helper 自身以不加载 profile、不进入交互的方式启动，因此解析不继承调用者的 profile。待审文本以 JSON 行（含请求标识）经 stdin 送入，helper 用官方 `Parser` 取 AST，以含同一请求标识的 JSON 行回包。文本只作数据，绝不执行。
- **Bash/POSIX**：随包分发的固定版本官方 `shfmt`（版本与交付形态归[技术栈设计](../技术栈设计.md)），按 bash 或 POSIX 语言模式从 stdin 读取文本，回包为 typed JSON AST；加载时核对固定校验和。每个请求用独立子进程隔离。
- **关联**：两种回包都必须与原请求关联。PowerShell 回包要与该请求的标识及发往的 helper 进程身份一致；`shfmt` 以每次独立子进程隔离请求。身份不符、迟到或重启后的旧回包不可消费。

### 预算来源与计量

预算是「这一层声明、可归因」的：超限一律记为缺口或显式失败，不因超限而放行或静默。执行分析持有整次调用的共享预算对象并定义各预算的数值与调用期限；本层只声明会消耗的类别与超限表现，不另立常量，也不把未知预算当作无限。

| 预算类别 | 本层的使用方式 | 超限表现 |
|---|---|---|
| 输入文本字节 | 把待审文本送入解析器前检查 | 该单元记输入超限缺口，无事实 |
| 解析输出与诊断字节 | 逐次回包检查 | 协议失败，终止 helper |
| 调用期限 | 排队与执行共用同一调用期限 | 未交付可信结果时记录检查故障 |
| 并发与队列 | 解析请求并发受限 | 请求无法受理时报告检查故障 |
| 嵌套单元深度 | 包装、脚本与语言运行器的递归层数 | 停止递归，记深度缺口 |
| 解析调用次数 | 同一调用内的解析请求总数 | 停止解析，保留已得事实 |
| 保留命令数 | 已还原命令项的上限 | 停止保留，记缺口 |
| AST 节点遍历 | 单次遍历的节点上限 | 协议失败或缺口，不产出残缺事实 |
| 脚本文件读取字节 | 外部脚本正文的单文件上限 | 记脚本不可证缺口 |

局部预算达限且仍能形成可信缺口时返回 `partial`，保留已取得的事实；整次调用的期限、协议或崩溃问题按检查故障处理。实现须在内部接收显式预算以便测试注入，不以缺省值代替未知值。

### 失败与协议事实

- 语法拒绝（如 `shfmt` 非零退出、PowerShell `ParseErrors`）→ 显式语法失败，不把残缺 AST 当作已通过。
- 协议损坏（无法识别请求身份、多余输出、非法 JSON、输出超预算）→ 显式协议失败，并终止该 helper。
- helper/二进制不可用、启动失败、崩溃退出 → 显式不可用失败。
- 取消与卸载 → 中止请求、终止 helper、清空队列；迟到或重启后的旧回包不可消费。
- 外部脚本文件不可证（非字面或动态路径、缺失、符号链接、非普通文件、超上限、编码不可判定、无工作目录、非宿主域）→ 显式 Unknown，包装命令保留可见。

局部语法失败和脚本读取缺口提交给调用汇总。解析器不可运行、崩溃或返回损坏协议时，提交检查故障。最终处置由统一规则模型定义。

### 外部脚本文件的只读 IO

命名脚本文件以「元数据后正文」的有界 IO 只读打开：只接受可判定的编码（带 BOM 的 UTF-8/UTF-16LE，或无 BOM 且严格合法的 UTF-8），拒绝符号链接、非普通文件、超限文件与解码后含 NUL 或无效编码的正文；读前与读后各核对一次大小。读入的正文只作为文本交对应解析器，绝不执行；该文本同时作为规则模型定义的凭据静态扫描的输入来源之一。任何一步不可证都以 Unknown 结束，绝不落到放行。

### 归本层与不归本层的事实划分

- **归本层（事实）**：命令名与参数 token、字面/动态标记、重定向与作用域、包装解包结果、工作目录跟踪、执行域、脚本文件正文、解析预算与失败类别、显式 Unknown 原因。
- **不归本层（交执行分析与策略）**：统一操作事实与目标种类的最终归一、覆盖状态 `status` 与 `gaps`、风险候选的产生依据、计数与分档、`decision`、确认与拒绝、最终门禁。

本层交付的是「尽可能精确的语法事实与可归因的缺口」，策略层基于这些证据判定；两层边界固定，本层不自行给出放行或拒绝。

## 验收

围绕本层可观察行为设计验收，分三组：等价性、成对正反例、失败与预算。

**等价性**（与执行分析的跨语言验收衔接，本层只核对 Shell 侧证据一致）

- 对同一个隔离目录，PowerShell `Remove-Item -LiteralPath <目录> -Recurse` 与 Bash `rm -r -- <目录>` 产出等价的动作、目标和递归标记。`Move-Item` 与 `mv` 的源同为移走源。
- 直接参数向量调用（`wsl --exec rm -rf /x`）与含解释器的文本调用（`wsl -d U bash -c 'rm -rf /x'`）各自保留正确的执行语义，目标一致；`bash -lc` 这类加载登录 profile 的组合选项仍提取脚本文本，但 profile 加载标 Unknown。
- 嵌套方言（`wsl -> bash -> pwsh`）保留各方言与执行域。
- `bash -c 'rm -rf "$1"' _ /tmp/x` 的 `scriptArgs` 与目标求值一致：`$1` 未求值时目标为 `unknown`，`$0` 不作为命令名。

**成对正反例**（数据位置 vs 执行位置、字面 vs 动态、包装 vs 不透明）

- 引号中以横线起始的字面量（`'--- label ---'`）、只读命令的未知选项、引号内数据（`echo '$(rm ...)'`、`grep "rm -rf"`）作为数据，不产出操作。
- 可执行子表达式（`"$(Remove-Item ...)"`、`$(rm ...)`、`<(…)`）、可执行 scriptblock（`& {}`、`ForEach-Object {}`、`try {}`）作为执行，产出事实。接收者为 shell 解释器的 heredoc 主体（含 `bash -s`）产出事实；接收者为数据工具的不产出。
- 原生重定向进入 IR；包装层自身重定向归外层单元，内层脚本事实不被改写或丢失。
- 字面路径使用 `exact`；`Remove-Item -LiteralPath '*.tmp'` 仍是 `exact`；`rm -rf dir` 使用 `subtree`；基准目录与模式可证的通配使用 `pattern`；变量表达式使用 `unknown`。
- 包装层 vs 不透明：`bash` 精确裸名解包；`/tmp/bash`、`BASH`、`bash.exe` 不解包并记缺口；`pwsh -NoProfile -Command` 解包，缺 `-NoProfile` 标 Unknown。
- 预览与布尔值：`Remove-Item -Path x -WhatIf` 与 `-WhatIf:$true` 标预览；`-WhatIf:$false` 按实际删除分析；`git clean -n`/`--dry-run` 标预览；`rm --dry-run` 是无效参数而不是预览；其它命令上的 `--dry-run`/`--whatif` 是普通操作数。
- 工作目录：`cd <存在的目录> && rm -rf build` 在更新后的目录计数；`(cd <目录>; rm -rf build)` 只用子 shell 内的目录；`Push-Location`/`Pop-Location`/`cd -` 之后的目录标 Unknown；PowerShell 中 `Set-Location` 后启动的外部程序的相对路径标 `unknown`。

**失败与预算**

- 语法失败（`if`、`function {`）、协议损坏（错配请求标识、多余输出）、helper 不可用、超时、取消、卸载都显式失败，并保留已取得的事实与诊断。
- 预算超限（命令项、输入/输出字节、深度、解析调用数、脚本文件大小）可归因，不静默放行；具体数值由执行分析声明。
- 外部脚本文件的不可证形式（缺失、目录、符号链接、超限、无效 UTF-8、无工作目录、非宿主域）都以 Unknown 结束，包装命令保留可见。

验收以合成目标与隔离目录为回放基础，逐条断言「必须出现的命令/参数/重定向/Unknown」与「不得出现的命令」，并把失败路径单列。合成用例通过不等于真实主机、真实仓库或跨平台验收；回放入口、平台实跑与真实语料误伤率归[工程结构与测试体系](工程结构与测试体系.md)。

## 覆盖边界与验证要求

- **终端上下文**：`terminal_send` 的有效解释器、工作目录与待提交输入状态须由前门现场契约证明。方言与 cwd 只能来自该终端本身；取不到时记缺口，不按平台推断（不把 Windows 当 PowerShell、其它当 POSIX）。核实项见 [TODO](../TODO.md)「补齐执行分析覆盖」。
- **平台实跑**：交付平台以实际运行记录验证；helper 启动与每份解析进程的延迟分位数按[工程结构与测试体系](工程结构与测试体系.md)采集留证。平台交付目标不等于已运行通过。
- **透传包装**：`sudo`、`env`、`nice`、`time`、`stdbuf`、`nohup`、`command`、`exec`、`timeout` 按 DSR-029 解包，`unshare` 按 DSR-031 作透明包装；`xargs`/`parallel`/`find` 的删除 argv 按字面或流式范围表达。`ssh`/`wsl` 的 heredoc 传递与 `ssh` 的 PowerShell/cmd 通道已按方言分析；`docker run|exec` 仅在宿主绑定挂载、`--device` 或 `--privileged` 时分析载荷，其余记缺口。
- **外传面边界**：`curl`/`wget` 的云元数据端点访问产出 `unverified-effect` 候选；`curl`/`wget`/`scp`/`rsync`/云存储上行的字面本地源产出 `read-content` 事实。通用出网、通用上传与隧道（`nc`/`socat`/`ssh -R`）、`sftp` 批处理、`scp -i` 身份文件读不建模，按缺口放行（DSR-031「不做」）。
- **非宿主域覆盖边界**：WSL、容器与远端的脚本读取和目标盘存不能从宿主视图完成，相关事实只到执行域与已知路径为止。
- **预览语义矩阵**：除 PowerShell 风险管理参数与按命令官方语义确认的 `--dry-run` 外，各工具的预览选项须逐一按官方语义核对后才可标预览；未核对的选项不标预览。核对项见 [TODO](../TODO.md)「预览选项语义矩阵」。
