# dsh-guardrails 命令文本分析

## 权威范围

本文唯一拥有 `dsh-guardrails` 对 pwsh 命令文本的词法、动词分类、列举模式判定、破坏性分析与固有限制。规则模型与名单归 `规则模型.md`，需求归 `../需求.md`。

## 结论先行

pwsh 命令文本是唯一"只有文本、没有操作类型"的通道，因此先做**列举模式判定**（是否为纯元数据列举），再按模式套用敏感规则；破坏性分析独立于敏感规则，两种模式下都执行。解析不了的命令一律按全规则处理（fail-closed）。

## 词法（tokenizePwsh）

对命令文本做纯静态词法切分，不执行任何代码：

- 单词（word）：连续非空白、非分隔符字符。**词带引号来源**：词首为引号者标 `quoted: true`（语句位置判定的输入，见下）。
- 引号：单引号 `'...'` 与双引号 `"..."` 原样吞入内容；反引号 `` ` `` 为转义符，吞入下一个字符。**双引号内插值**：`"$(...)"` 是真正会执行的子表达式，其体一并收进 `nested`（单引号在 PowerShell 中是字面量，永无插值，不收集）。
- 子表达式 `$(...)`：按括号配平提取 `nested` 列表，原位置替换为占位 `$(x)`（子表达式内容单独递归分析）。**配平须引号感知**：引号内的 `)` 是字符串内容而非配对，且双引号内新开的 `$(` 自成一组。
- 分隔符（sep）：`;`、换行、`|`、`&`；`&&`/`||` 保留双字符原值（DSR-009 错误门保真——`a && b` 与 `a ; b`/`a || b` 对后继语句的成败约束不同，词法层不得压扁；`||` 不是管道），按分隔符切分为 fragments。

## 语句位置（DSR-012）

命令文本是"语句序列"，不是"命令序列"——`splitFragments` 的每个 fragment 未必是**命令**。判据（`isCommandPosition`）：

- 词首**不是**引号 → 命令位置（正常命令）。
- 词首是引号 → **默认是输出语句**（裸字符串），不是被调用的命令。依据：PowerShell 中 `"cmd" arg` 是**语法错误**（引号串不能带参数），故引号开头的语句不可能是命令调用。两个例外仍属命令位置：`leadSep === '&'`（前置 `&` 调用算符）与词首为 `&`/`.`。

## 动词分类

命令名经 `normalizeCommand` 归一（小写、去连字符）后分类：

| 集合 | 成员（基线） | 语义 |
|---|---|---|
| METADATA_CMDS | `getchilditem`、`gci`、`ls`、`dir`、`getitem`、`gi`、`testpath`、`resolvepath`、`getlocation`、`gl`、`pwd`、`splitpath`、`joinpath` | 列举/元数据：不读取内容 |
| REMOVAL_CMDS | `removeitem`、`rm`、`ri`、`rmdir`、`del`、`erase`、`rd` | 删除 |
| CD_CMDS | `cd`、`setlocation`、`sl`、`pushd` | 目录切换（破坏性分析跟踪 cwd 链） |
| MUTATION_CMDS | `moveitem`、`mi`、`move`、`copyitem`、`cp`、`copy`、`renameitem`、`rni`、`ren` | 源消耗型变异（DSR-009：目的路径自此持有唯一副本；chain/misuse 的动词面） |
| LIST_CMDS | `getchilditem`、`gci`、`ls`、`dir` | 列举（管道删除检测） |
| 其余（未列出） | — | 视为内容访问或写/删，套全规则 |

> DSR-006（v1.1.0 已实现）：`classifyVerb → read / modify / list` 协助（复用 `CONTENT_VERBS` / `WRITE_VERBS` / `METADATA_CMDS` 集合）与 `assessContentClass`（整条命令的操作级分类：`>` 或修改类动词 → modify；`$()`/未知动词 → unknown 全规则）一起，使命令文本层按操作叶子（`env.read` 与 `env.modify` 等）判定，而不是类别整开关；引用规则的分组与叶子保持一致。

## 列举模式判定（isListingOnly）

整条命令同时满足以下条件才按"列举"处理（只查凭据目标）：

1. 不含 `>`（PowerShell 中 `>` 只表示重定向，重定向目标可能是敏感文件）；
2. 无 `$()` 子表达式（子表达式内可能含内容访问命令）；
3. 每个 fragment 的首命令（`unwrapFragment` 跳过 `$var`、`&`、`.` 前缀后）都 ∈ METADATA_CMDS。

不满足任一条件 → 全规则（env / git / credentials 文本引用 + destructive 分析）。

## 敏感文本引用

三个检查都以 `maskTextSpans(resolved)` 的结果为输入（**引用豁免**，DSR-010）：引用位置先被抹成等长空白，故三者只对"剩下的文本"判定。豁免**只作用于这三个检查**——列举模式判定、内容级别分类、W0 系统区写、不可验证 fail-safe 与破坏性分析全部仍看原命令。

- `ENV_REFERENCE`：匹配 `.env` 及 `.env.*`（排除 `$env:NAME` 形式）。
- `GIT_DIR_REFERENCE`：匹配独立成词的 `.git`（后随分隔符或行尾）。
- `CRED_TEXT_REFERENCE`：凭据文件名/目录段/组合的文本出现（`.pub` 排除）；`.dsh`（含会话历史）不在任何引用规则中（见 DSR-003 重访注记，规则模型.md）。目录段分支由 `CRED_DIR_SEGMENTS` + `SAFE_CRED_DIR_FILES` **派生**（不再手写），故与路径通道同源。
- `CRED_TEXT_REFERENCE_STRICT`（DSR-013）：同上但**不含具名安全文件例外**。判定层按操作级别选用——`read`/`list` 用宽松版（`Get-Content ~/.ssh/config` 放行），`modify` 与 fail-closed 的 `unknown` 用严格版（`Set-Content ~/.ssh/config`、`Out-File ~/.ssh/config` 仍拦）。两个通道必须同宽：路径通道的 `pathTargetsCredentials(resolved, allowSafeDirFiles)` 也按 `modifying` 取严格版，否则 pwsh 通道会成为绕过写拦截的缺口（DSR-004 镜像名单的意义所在）。

### 引用豁免（maskTextSpans，DSR-010）

位置感知的 `scanWordSpans` 找出两类"引用位置"并抹成等长空白（长度与其余字符偏移不变，故真实路径周围的定界上下文不受影响）：

| 规则 | 位置 | 为何安全 |
|---|---|---|
| 散文引号分段 | 引号内**含空白且不含 `\` 或 `/`** 的分段 | 含空白、不含分隔符只可能指名**当前目录下的单个文件名**，而 `.git` 这个名字本身不含空白 ⇒ 该分段不可能是 `.git` 目录，抹掉它藏不住一次访问 |
| 文本/模式参数值 | `-match`/`-notmatch`/`-like`/`-notlike`/`-replace`/`-split`/`-join`/`-contains`/`-notcontains`，以及 `-m`/`-Message`/`-Title`/`-Description`/`-Subject`/`-Body`/`-Comment`（含 `-Param:value` 内联式） | 这些值不会被任何 cmdlet 当文件打开 |

⚠ **双引号内含 `$(` 的分段不豁免**（v1.7.0）：该分段插值的子表达式**真的会执行**，而"文件名不可能就是 `.git` 目录"这条论证对可执行代码完全不适用。此前豁免它，正是 `Write-Output "$(Get-Content .env)"` 整条逃过文本引用检查的原因。单引号在 PowerShell 中不插值，维持普通散文豁免。

**路径能力参数一律不豁免**：`-Path`/`-LiteralPath`/`-Filter`/`-Include`/`-Exclude`/`-Pattern`/`-Value`/`-Destination`——其中 `-Filter`/`-Pattern` 名字看着像文本参数，但**真的会命中文件系统名字**，豁免它们风险大于收益。

## 破坏性分析（assessDestructive）

独立于敏感规则，对命令文本做片段级模拟分析：

| 类别 | 判定 |
|---|---|
| 机器级 | `shutdown`（重启/关机/休眠）、`restartcomputer`、`stopcomputer`、磁盘工具（`cleardisk`/`initializedisk`/`formatvolume`/`removepartition`）、`net user/localgroup /add` |
| 进程 | `stop-process`/`taskkill` 目标为 node/dsh/pwsh/explorer/cmd |
| 远程内容执行 | `iex`/`Invoke-Expression`；管道进 `bash`/`sh`/`pwsh` 等；`curl \| bash` 模式 |
| 清空 | `Clear-Content`；`Set-Content` 到 `$null` |
| 管道删除 | `Get-ChildItem`（含与不含 `-Recurse`）管道 `Remove-Item` |
| git 高危 | `reset --hard`、`clean -f`、强推/删远端 ref、`branch -D`、`stash drop/clear`、`checkout/restore .` |
| 文件/磁盘 | `shred`、`find -delete`、`dd of=`、`mkfs*`、`fdisk`/`parted`/`format`/`diskpart`、`truncate -s 0` |
| 基础设施/云 | `docker system prune`、`terraform destroy`、`kubectl delete`、`aws s3 rm --recursive` |
| 数据库 | `dropdb`、`redis flushall/flushdb`、psql/mysql 等 CLI 的 drop/truncate/delete |
| 删除目标分析 | 删除命令的目标解析：`cd` 链模拟 cwd；目标为 `./*`/`$pwd` 等"全部"且 cwd 为工作区根 → 拦；cwd 动态不可知 → 拦（无法验证删除范围） |
| 无门控链删（DSR-009） | 同调用内 mutator（MUTATION_CMDS）→ 无 `&&` 门 → 带爆炸半径标志（`-Recurse`/`-Force`/`-r`/`-f`、del/rd `/s`）的 removal → 拦；removal 的回退边界：仅被 `&&` 链直接门控的 mutator 视为"已成功"；mutator 带 `-EA Stop`/`-ErrorAction:Stop` 视为已设门 → 放行 |
| 参数误用（DSR-009） | `-Literal*` 参数值含 `*`/`?`（NTFS 不可能存在此类文件名，语句必败且非终止，链式后果即 09-10 事故）→ 拦；removal/mutator 动词的位置或 `-Path` 目标含 `[ ]`（FileSystem provider 按单字符通配类解析，命中未指名文件）→ 拦；`-Include`/`-Exclude`/`-Filter` 的值合法含通配，豁免 |
| .NET 直接 API | `[System.IO.File/Directory]::Delete/WriteAllText` |

> 子族分组（DSR-006 六子族 + DSR-009 两子族，逐族可配，缺省全开）：`machine` = 机器级 / 进程 / 清空；`eval` = 远程内容执行 / .NET 直接 API；`cli` = 文件磁盘 / 基础设施云 / 数据库；`bulk` = 管道删除；`git` = git 高危；`target` = 删除目标分析；`chain` = 无门控链删；`misuse` = 参数误用。片段主循环判定顺序：git → machine → eval → bulk → cli → target → misuse → chain。

## 子表达式递归（DSR-012）

`checkCommand` 在跑完全部层后，对 `tokenizePwsh(resolved).nested` 的每个子表达式体**递归调用自身**（同一套规则、同一 base，最大深度 `MAX_SUBEXPRESSION_DEPTH = 8`）。理由：`$(...)` 是命令，写在哪儿都要执行——不递归的话，双引号插值里的命令对内容/系统写/破坏性三层全部不可见。

- 递归使 `"$(Get-Content .env)"`、`Write-Output "$(Remove-Item C:\Windows\x -Recurse)"`、`"$(git reset --hard)"` 全部被拦（此前整类放行）。
- 深度上界防对抗性嵌套；超界即停（保守方向：外层已见过该文本）。
- 与**语句位置**互补：`assessUnverifiable` 不再把引号开头的语句当命令，但其中的插值由本递归逐个体判定——比"整段按不可验证拦"更精确。

## 固有限制（接受并文档化）

- **动态路径不可解析**：`$var`、通配符、`Join-Path` 拼接等无法静态求值，敏感引用按文本出现判定或放行；这是"正则兜底"存在的原因，也是误伤的来源——操作分级已把无害列举与内容访问分开，**引用豁免（DSR-010）又消掉了"引用敏感名被当成访问它"这一整类**（2026-09-27：提交信息引用守卫自己的拒绝原文即被拦），**DSR-012 再消掉"裸引号输出语句被当成动态命令"这一整类**（2026-09-29：实测 9062 条真实命令中 407 条属此误伤）。残余误伤面收窄为动态路径的内容访问，以及两处**有意 fail-closed** 的保守判定：`-Pattern` 的值不豁免、无空白且不含分隔符的散文分段不豁免。
- **不是解析器，仍是文本启发式**：`$var` 作命令名（`& $exe`）无法静态判定——但该形态在**新进程 + `-NoProfile`**（DSH 的 pwsh 调用方式）下无法被赋值，实测 `& $exe --help` 抛 `InvalidOperation` 且不执行任何命令；已赋值的合法形态由 `resolveCommandLiterals` 还原（语料中 53 处 `& $var` 全部还原为字面量，0 处残留动态）。真正的根治是换用完整 PowerShell 解析器（已评估，见 DSR-012）。
- **别名不完备**：动词集合是常用子集，未知动词按全规则处理（保守方向正确）。
- **cwd 链为近似模拟**：`pushd`/动态目标会使 cwd 状态变为 unknown，此时删除"全部"目标无法验证 → 拦。
- **`>` 判定**：命令文本含任何 `>` 即退出列举模式（全规则），可能把无害列举升级为保守模式，但不会漏拦。
- **跨回合串联不判**（DSR-009 无状态边界）：`chain` 只判"同一调用内"的无门控链删；move 与删除分属两次调用时判定层无上下文，唯一副本风险不属插件判定面（会话状态方案已评估并否决，规程层补偿，见 DSR-009）。
- **控制流不建模**：`try/catch`、`if ($?)`、`$ErrorActionPreference` 等级别的错误门不在词法层识别——此类"mutator 后接强删"会被 `chain` 拦（误伤方向，出路是拆回合或关叶子）。
- **`[ ]` 通配判定为 Windows FileSystem provider 语义**（C-05 同前提）：Linux 上文件名可合法含 `[ ]`，届时该规则属保守误伤，按叶子关闭。
- **脚本文件外的世界不可见**：先 write 一个 `.ps1` 再执行的链式结构对文本层不可见——静态守卫防的是 AI 的意外，不防对抗性绕道（同 `-EncodedCommand` 一类，接受为定义性边界）。

## 与工具通道的关系

工具通道（read/grep/write/edit/glob）直接携带路径与操作类型，不需要命令文本分析；命令文本分析只服务于 pwsh 工具。两者名单与规则语义一致（同一 `checkPath` 规则集，命令文本层增加动词/引用判定）。
