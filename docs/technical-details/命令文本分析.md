# dsh-guardrails 命令文本分析

## 官方 AST 与严格门禁

本文拥有 Shell 分析与最终门禁的**源码实现合同**；源码与隔离 Runtime 验证通过，详见[验证记录](../verification/2026-11-14-delete-gate.md)，live 激活已在验收环境复验，但 UI 与跨平台运行验收仍未完成（见文末「验证状态」）。语法权威只有微软 PowerShell Parser 和官方 `mvdan/sh` AST。不得保留旧 `tokenizePwsh`、`splitFragments`、`maskTextSpans` 或新写 Bash lexer 作为第二权威、并集检测或故障回退。

| Provider | 固定接入 | 返回事实 |
|---|---|---|
| PowerShell | 惰性启动的持久受信 `pwsh` helper，调用 `System.Management.Automation.Language.Parser.ParseInput` | 有界结构化命令、参数、重定向、执行上下文、ParseErrors 与 Unknown |
| Bash | 本地官方 `shfmt v3.12.0 --language-dialect=bash --to-json`，`shell:false`、stdin 输入 | 官方 typed JSON AST，经验证后提取精简事实 |

shfmt 首版交付目标为 Windows x64、Linux x64/arm64，锁定版本、来源与校验和；不在工具调用时下载。待审文本是协议数据，不能 `eval`、`Invoke-Expression` 或执行待审脚本。helper 用请求 ID 关联回包；固定可执行文件/参数独立于用户文本。解析工具按实际受管方言选择，不按 Host OS 猜测 Bash/POSIX/Zsh/WSL。不得要求运行机额外安装 Go 或 Bash 来完成文本解析。

## 递归包装层解包（`shell-analysis`）

`src/adapter/shell-analysis.mjs` 导出 `analyzeShell({ dialect, source, parsers, cwd, signal })`，在单个 `dialect`（powershell/bash/posix）上工作。它只通过官方解析器重新解析**文本**，从不解释、求值或执行被检查的文本，也不启动被检查的 shell。对已知包装层（`wsl`、`bash`、`sh`、`pwsh`/`powershell`、`cmd`）按官方解析器已产生的 argv 做有界递归解包：

- 命名规则保守：路径限定的程序名（如 `/tmp/bash`、`C:\evil\bash`、`./pwsh`）**不**作为可信包装层，可能只是任意外部程序；POSIX 源方言下仅精确裸名（`bash`、`sh`、`pwsh`、`wsl`）可信，`BASH`、`bash.exe`、`Bash` 不解包而是保留并标记 unknown；Windows/PowerShell 源方言下大小写不敏感并剥离 `.exe`。
- 解包出的内层命令保留并附加 `dialect`、`domain`（`'host'` 或 `'wsl'`）、可证的 `cwd`；WSL 命令可携带 `distribution`、`user`。
- 无法解析或语义不确定的地方**保留为命令或显式 unknown**，任何东西不得静默消失。
- 全程解析有全局预算（深度/调用数/命令数上限）；超预算 fail-closed。
- 不声称外层 AST 等于下游解释器的 Windows 原生 argv；不支持的引号语义、歧义上下文必须交下游拒绝。

`cwd` 取当前工作目录服务（Inspect 现场 API），不只用初始 header/workspace。

## 严格 deletion-intent 判定（`deletion-intent`）

`src/core/deletion-intent.js` 导出 `assessCommands(commands, { unknown = [] } = {})`，返回 `{ operations, denial? }`。`operations` 只含删除计划 `{action:'delete', path, recursive, domain, cwd?, commandName, unknown?}`；已知删除意图但路径无法解析时**必须保留为 `path:null` + `unknown`**，不得消失。

严格策略（英文 reason）：

- **未知程序名不再拒绝（v4 L3）**：`assessCommands` 对 `Test-Path`/`Copy-Item`/`New-Item`/`whoami` 等未建模程序名返回无 denial、无 operation（放行）。**只有 adapter 无法解析的执行语义**（`unknown` 数组非空且与删除意图相关）仍以 `DI-UNKNOWN-SEMANTICS` 拒绝——这是“执行通道可分析否则拒绝”的落点，不是程序名兜底。纯展示/状态噪声（见下「触发收敛」）不再拒绝。详见 [DSR-020](../decisions/DSR-020-灾难性删除标准.md)、[DSR-021](../decisions/DSR-021-非删除unknown放行.md)。
- **执行通道仍拒绝**：目的是执行任意命令文本且无法分析的通道（未证明的 shell 脚本、动态命令文本、`env/xargs/sudo/start/source`、WSL 包装、`run_code`）拒绝；所有删除类拒绝附统一强提示。
- **git 分级（v4）**：`git` 不再是命令名拒绝项，由 `assessGit(argv)` 分类——销毁历史子命令 `refuse`（`DI-GIT-REFUSE`），`clean`/`restore`/`worktree remove` 产 operation 交 `git-evidence` 计数，其余 `allow`。git allow 命令不进入通用文件扫描。
- **语言运行时脚本放行**：`node/nodejs/python/python3/py/perl/ruby/php/deno/bun/uv`（及 `python -m ...`）作为不透明脚本运行器直接允许、不计数；**内联代码开关**（`node -e/--eval/-p/--print/-i`、`python -c`、`perl -e/-E`、`ruby -e`、`php -r`、`-` 从 stdin 读脚本）仍 `DI-INLINE-CODE` 拒绝，因为命令行本身变成了无法枚举的代码。
- **shell 脚本文件分析**：`bash/sh/dash/zsh <脚本文件>`、`pwsh/powershell -File <脚本文件>` 在文件为字面路径、存在、常规非链接文件、≤1MiB、编码可判定（UTF-8（含 BOM）、UTF-16LE BOM）时读取源文本、按该方言走既有 AST 分析并拼入嵌套命令；缺失/非常规/过大/编码未知/读取错误，或脚本内出现 `source`/`eval`/动态构造，一律产 `unknown` 交由下游拒绝。**不支持** `./x.sh` 路径限定可执行或 `cmd /c file.bat`。
- 仅极窄的可验证非删除命令形态可通过（如 POSIX `echo/pwd/ls/cat/printf` 与 PowerShell `Write-Output/Get-ChildItem/Get-Content` 等的明确选项子集）；未知可执行、自定义路径、Git hooks/aliases、分页器、`-exec` 模式、启动/profile 文件、重定向与方法副作用，都不因 basename 熟悉而安全。
- `rm`/`Remove-Item` 选项语义严格；同步删除模式（`rsync --delete` 变体、`robocopy /MIR /PURGE`、`git clean/reset/restore/worktree remove`、`find -delete/-exec`、Python/Node/.NET 删除、磁盘销毁等）要么产生可靠计划，要么显式拒绝。core 内不执行任何预览/dry-run。
- 会改变固定目标集的 shell 状态（循环、alias、source、函数、替换、环境变更、cwd 变更）与前置变更必须作为 unknown 暴露给下游门禁。
- **（v6）非删除语义 unknown 不拒绝**：变量/环境变量赋值、通用动态参数（`Dynamic command or argument` 仅保留给命令名为 null 的执行通道；参数 null 交各语法判定）在本次调用**无真实删除**时不构成拒绝理由；存在真实删除时仍保留为保守标记。**动态目标的删除、动态命令名（`& $cmd`/`iex`）、通配/无法枚举目标、执行通道不可分析、>20、L1 灾难拒绝全部保持拒绝**（见 DSR-021）。
- **（v6）字面量 `cd` 跟踪**：同一调用内、script scope、单参数字面量的 `cd`/`Set-Location`/`sl`/`chdir`，其目标经 `lstat` 确认为真实目录（非符号链接）后更新**后续命令的 `cwd`**；动态/多参/带选项/非 script scope 的 `cd` 仍标 `State-changing command ... invalidates a fixed target set`（其后删除 fail-closed）。`pushd`/`popd` 不跟踪。
- **（v6）成员/类型能力分级**：属性/索引访问不产生 unknown；实例方法仅放行纯字符串/格式化白名单（`Replace/Substring/Trim*/ToUpper/ToLower/ToString/PadLeft/PadRight/Split/IndexOf/LastIndexOf/StartsWith/EndsWith/Contains/Normalize`）且仅当目标为变量/属性链/字符串字面量；静态类型 `::` 调用、非白名单方法（如 `.Delete()`、`.Invoke()`）与自定义类型转换仍 unknown。基元类型约束（`[int]$x`）放行。
- **（v6）字面量常量传播（仅 PowerShell）**：顶层、单一赋值、右侧为静态字面量且赋值早于使用的 `$p = 'literal'` 会被解析为字面量（恢复 `-LiteralPath $p` 的计数与凭据保护）；多次赋值、命令结果、循环/条件/脚本块内赋值仍为动态（fail-closed）。bash 侧不做常量传播。

## 执行前删除清单与 20 文件硬门禁（`deletion-plan`）

`src/adapter/deletion-plan.js` 导出 `planDeletions({operations, cwd, boundary, rules, signal, ...})` 与常量 `DELETION_LIMIT = 20`，返回 `{kind:'allow'|'deny', ruleId?, reason?, counts?, entries?}`。只观察 lstat/readdir 元数据，从不读文件内容、从不执行被检查文本、从不自动跑 dry-run。filesystem 删除与 `move-source` 共用同一遍历；三个 git action 由 `git-evidence` 计数后并入同一 20 上限（git allow 命令不进入本扫描）。

- **20 文件硬门禁**：整次调用内统计**未命中白名单的常规文件 + 删除的链接条目**，目录条目去重（按路径而非 inode）并**单独报告目录数**；`<=20` 要求完整枚举；`>20` 可在「至少 21」处早停，绝**不**声称精确总数。
- **未知/预算/权限/歧义语义 → 拒绝**，reason 为英文；ENOENT 仅在命令语义允许时才算已知零。
- **链接与祖先**：不跟随链接；守护不安全祖先而非只看最终链接；语义无法证明时拒绝链接/挂载跨越。
- **白名单是计数-only**：受保护文件与绝对 deny 始终生效；不做不检查保护/链接的整树跳过。命中只减少计数，不是删除授权。
- **WSL 与跨域**：不假设 `/mnt/X` 映射；若是 Windows 上的 bash 删除域无法对应到 Node 路径，或无法做可靠的域特定枚举，返回显式拒绝并要求改用受支持的受管宿主命令（例如 literal 的 `Remove-Item`），不猜测映射、也不静默 allow。
- 不新增可配置 mountMap/threshold/whitelist；上限固定 20。
- **git action 计数（v4）**：`git clean`/`restore <paths>`/`worktree remove <path>` 走 `git-evidence` 模块（真实 `git` dry-run）得出受影响集，不在此做文件系统遍历；`DEL-GIT-CLEAN`/`DEL-GIT-RESTORE`/`DEL-GIT-WORKTREE` >20 拒绝，worktree remove 额外要求工作树干净、非分离 HEAD、可重建之外忽略条目 ≤20；证据模块不可用或返回 unknown → `DEL-GIT-UNKNOWN` fail-closed。`move` 的源删除按 `DEL-14` 计数。
- **边界口径（v4）**：工作区之外的删除同样计数（>20 拒绝），不因“在边界外”本身拒绝；系统树/设备/`.git` 的 L1 保留。

## 结构化与直通通道

- 结构化文件工具直接用明确操作与目标，不经过 Shell Parser。`move` 的源删除按 L2 计数（`DEL-14`）；`copy` 不删源、放行。
- **`run_code`**：一律拒绝（载荷是程序，内部副作用不可排除）。
- **`terminal_send`（持久终端）**：其 `text` 是命令行，**就地按平台方言分析**（Windows PowerShell / 其他 POSIX）；可识别删除照常计数/拒绝，无法分析则拒绝（不再整类拒绝）。
- 真正的边界是「不经 `ctx.tools` 直接调用 runtime service」——本插件不覆盖该直连路径。
- **未审查工具默认拒绝**；已审查的协调类 `tools` 通过 allow-list 允许（含 `create_worktree`、`terminal_open`、全部 `plugin_manager` 动作），不把任意工具名 blanket 标为安全。
- 保持既有敏感文件/打码保护；拒绝 reason 仅英文。

## 执行身份与最终门禁

1. `tools/pre-execute` 对本次执行异步完成官方 AST、事实提取、策略、删除清单与必要审批。
2. 使用同一 `ToolExecution` 对象作为 WeakMap key 保存完整判定；不用文本哈希、裸 callId 或上一调用批准作为授权身份。
3. 同步 `ctx.tools.guard` 只消费已完成判定做最终拒绝，不做异步解析或等待。
4. 必检 Shell 若缺本次可信完整结果，最终 guard 拒绝；即使前置 waterfall 被其他监听器短路，也不能静默执行。
5. 允许只绑定当前执行；新执行对象重新分析和审批。**审批后需重新计数**；检查与执行之间存在 FS 竞态（见下）。

## 定向提示与凭据静态扫描（v6）

所有经 `tools/pre-execute` 返回的拒绝、以及 `ctx.tools.guard` 的最终拒绝、审批前的 ASK 文案，统一渲染为可预测的五段式英文块（`src/core/diagnostics.js`）：

```
[GUARDRAILS] DENY|ASK <RULE-ID> (<layer>)
Why:     <点到具体 token/语句/表达式，而非 “unknown semantics”>
Trigger: <实际命令/参数/路径 + 解析器的具体表达式详情，截断 200 字符，凭据先遮蔽>
Effect:  <本来要检查/计数什么；为何无法完成>
Next:    <最小可行替代：拆语句、字面量路径、改用计数删除、改用 read 工具等>
```

- `Why`/`Trigger` 的表达式详情来自解析器为 unknown 追加的 extent（如 `Dynamic command or argument: <expr>`）；`DELETION_DOCTRINE` 作为删除类拒绝（DEL-*/DI 删除族/S-F1/S-F2/ABS-*）的末句保留。
- `Trigger` 与 `Why` 在返回前经 `redactText` 打码（PEM/JWT/provider token/Bearer），不泄漏凭据。
- **凭据静态文本扫描（仅动态读取缺口）**：命令文本、`terminal_send` 文本、以及被当脚本读入并解析的文件源（`bash -File`/`pwsh -File` 内容）**仅当本次调用存在未解析动态操作数（`args` 含 `null`）且决策为 allow** 时，才静态匹配凭据基名（`rules.js` 的 `CRED_BASENAMES`、`.env.*.local`、私钥名）与私钥头；命中则升级为 `S-F1` 审批（只升不降）。路径全部可解析时交给既有 path-check/S-F1，不做文本扫描（提交信息、搜索模式、echo 中的 `.npmrc`/`.env` 不触发）。不扫描 `write`/`edit` 的正文字段；其路径仍由 path-check 判定。

## 竞态与不保证

本模块在派发前观察文件系统进行计数。**并发写者，或同一调用中先于删除执行的变更，可能在计数后改变目标集**。intent 层须把这类前置变更作为删除计划的 `unknown` 暴露（本门禁会拒绝）。本模块**不**声称在并发文件系统变动下的 `<=20` 执行是原子的；接线该拒绝是 Integrator 的职责。不声称对任意语言语义（SQL、云 SDK、容器内部、远端副作用）完整覆盖；不能把解析成功等同于理解这些。

## 故障与资源生命周期

| 状态 | 执行语义 |
|---|---|
| Provider 不可用、崩溃、超时、异常退出、协议损坏或无效 JSON | fail-closed，明确说明检查基础设施不可用 |
| ParseErrors、语法失败或结构不足 | 拒绝，不能将残缺 AST 当作检查通过 |
| 本次对象的完整关联结果缺失 | 最终 guard 拒绝 |
| 语法有效但效果 Unknown | 解析层只报告该 Unknown（覆盖限制）；**策略层只对“与删除意图相关”的 Unknown 拒绝**（见 DSR-021）：非删除语义噪声（赋值、只读动态参数）在无真实删除时放行；任何可能隐藏删除的 Unknown（动态目标、动态命令、执行通道、预算/观察失败）仍拒绝 |

输入、输出字节、JSON 深度、解析等待、并发和进程数量均有界。取消和插件卸载须清理本次请求、计时器、监听器与子进程；helper 断线后的新请求不得继承旧回包或授权。诊断应脱敏，不回显待审文本内密钥。
