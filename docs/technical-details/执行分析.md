# dsh-guardrails 执行分析

本文规定受管执行输入如何转换成操作事实与覆盖状态，追溯 R-12、R-16、R-17、R-19 和 DSR-027。Bash、PowerShell、Python、JavaScript 和 TypeScript 使用同一个分析入口及结果形状。

## 输入与来源

一个调用最多有一个根分析单元。解释器、包装器、脚本或外部进程可以产生子单元。结构化文件工具直接提供操作事实，采用同一结果形状。

| 字段 | 形状与约束 |
|---|---|
| `unitId` | 调用内唯一。按发现顺序分配，根单元先于子单元 |
| `source` | `inline { text }`、`file { path }` 或 `argv { executable, args }`。`argv` 指直接传给进程的参数向量 |
| `language` | `bash`、`powershell`、`python`、`javascript`、`typescript`、`unknown`。需要时附原始运行器标识供诊断。直接 `argv` 入口先识别外部程序 |
| `scriptArgs` | 脚本可观察的参数。每个已知项保留一个独立字符串，未知项保留原因；参数个数不可证时另标长度未知 |
| `context` | `domain` 为宿主、已识别的独立执行域或未知。`cwd` 为该域内已知的绝对目录或未知。独立执行域必须附可用于区分实例的已知信息 |
| `origin` | 入口、来源位置及可选 `parentUnitId`。位置使用文件或工具输入标识和半开区间 `[start, end)`，插件统一使用 UTF-16 码元偏移 |

工作目录、解释器及执行域从能证明实际执行语义的输入获得。嵌套单元继承可证明仍然有效的字段。工作目录变化、跨域或载荷来源不可证时，相应字段转为未知。分析结果可以是「确知会删除，目标在未知目录」，应保留删除动作。

## 语法角色与操作识别

1. 读取并分派根单元。文件入口按已证实的执行域解析，读取常规本地文件。按本次预算的单文件上限读取，并在读前、读后核对字节数。解释器脚本文件（`python`、`node`、`tsx`、`deno`、`bun` 等）正文不读取，记覆盖缺口 `script-file-body-not-analyzed`，其外层命令事实保留；Shell 脚本文件仍按本步读取。来源、身份或编码无法确认时记录缺口。词首未引号的 `~` 按宿主 HOME 归一后再进入路径判定；`~user` 形态保持未知并记缺口 `tilde-user`。宿主为 win32 时，无法归属方言的内联文本（`language` 为 `unknown`，如 `cmd /c`、`os.system`、`execSync` 的载荷）按 cmd 方言薄分析；未命中任何删除形态的文本记缺口 `cmd-inline` 放行。heredoc 正文在接收者为 shell 解释器时按同域脚本进入分析，数据接收者不分析；`ssh` 主机之后的命令按 POSIX shell 建子单元，执行域记为 `ssh`。
2. 解析源码。由对应语法权威提供执行位置、参数角色、数据位置、重定向及嵌套执行边界。有确定不会执行证据的分支不产出操作。可达性无法证明时保留可能执行的操作。
3. 识别已接入的语言 API 及外部命令。在 Bash 和 Python 子进程中调用同一个已识别外部程序时，共用参数语义。Git 清理和恢复映射到相应专用动作，销毁 Git 历史的已知操作另外报告其命令事实。
4. 对已知解释器、脚本、内联源和包装层产生子单元。直接参数向量保持参数边界。只有调用语义明确经过解释器时才按该解释器解析命令文本。
5. 在预算内求值。允许已证明的常量、纯路径变换、局部参数传递、有限分支及循环。分叉得到有限目标集合时保留集合，任一分支的范围不可证时同时保留未知部分。数据流跨入未建模调用时停止求值并报告缺口。
6. 汇总所有单元，保留操作顺序和来源。分析层只合并重复的语法发现，真实文件项的去重留给目标取证。

分析器以只读方式取得所需源码和上下文。待审源码是解析器的输入数据。目录枚举仅限可证范围内的只读观察。项目代码、回调、模块导入、项目生命周期及命令替换均留在实际执行阶段。

## 操作事实与分析结果

### 操作事实

| 字段 | 形状与约束 |
|---|---|
| `action` | `delete`、`move-source`、`git-clean`、`git-restore`、`git-worktree-remove`、`git-history-destroy`，以及 `read-content`、`copy-content`、`write-content`、`truncate-content`、`metadata` |
| `target` | 下表定义的目标表达。若涉及多个语义不同的目标，如移走源和写目标，按各自动作分别记录 |
| `recursive` | `true`、`false` 或 `unknown`。须由操作语义与参数共同证明。目录树由目标及递归标记一起表达 |
| `condition` | `certain` 表示已证实进入该执行位置，`possible` 表示已知条件分支可能进入，`unknown` 表示可达性分析未完成 |
| `preview` | 仅在已确认原程序与选项组合确实采用预览时为 `true`。其他情况按实际操作或未验证状态报告 |
| `context`、`origin` | 可证的执行域、工作目录及导致操作的来源。保留跨语言嵌套来源 |
| `details` | 仅携带操作需要的领域参数。例如 Git 已知子命令和参数向量；远端删除附 `remote { provider, scope }`；非宿主执行域的删除以 `unknown` 目标加 `knownScope` 表达，不做宿主盘存。参数不完整时明确标示缺失项 |

同一目标在宿主与不同执行域中是不同对象。路径可以仍为相对路径，使用 `context.cwd` 解释。已证明的通配结果与仅带通配表达式的目标保持区分。

| `target.kind` | 必要内容 | 含义 |
|---|---|---|
| `exact` | `paths` | 已知的路径集合。至少一项，每项可由上下文解释 |
| `pattern` | `base`、`pattern`、`dialect` | 已知基准目录与通配规则，不声称已枚举结果 |
| `subtree` | `root`、可选 `maxDepth` | 已知或可解析的目录根。深度以根为 0，一层枚举使用 `maxDepth=1`。目录身份仍待取证 |
| `unknown` | `reason`、可选 `knownScope` | 目标存在未知部分。`knownScope` 只含已经证实的路径或操作约束 |

非宿主执行域（`ssh`、`wsl`、容器、云端）的删除与设备写一律使用 `unknown` 目标并附 `knownScope`，不经宿主盘存；`knownScope` 只是展示范围，不能反推为宿主路径。设备写附 `details.deviceMutation`，由身份探测决定是否升级为灾难级；容器域内的设备写取不到宿主身份时按不可证选择器处置（拒绝，不静默放行）。PowerShell 管道中无显式路径的删除把相邻上游命令文本写入 `knownScope`（`reason: 'pipeline-input'`），不伪造精确路径。

云元数据端点访问不产出文件操作，只产出 `unverified-effect` 候选；本地上传与传输（`curl`/`wget`/`scp`/`rsync`/云存储上行）的源文件产出 `read-content` 操作，由凭据规则按受保护路径判定，普通文件不因此确认。

`git … --abort` 以 `git-restore` 事实加只读状态探测表达：仅当探测证明有进行中操作（`rebase-merge`、`rebase-apply`、`MERGE_HEAD`、`CHERRY_PICK_HEAD`、`REVERT_HEAD`）时确认；证明没有进行中状态时不记录任何证据，按 `git-evidence` 例外放行；探测失败记 `unknown`（确认），不得升级为检查故障。`git restore --staged`（只还原索引）不产生事实。

删除的目录树内含 `.git` 时，`.git` 内容不参与普通计数，也不把枚举失败升级为检查故障：产出确认，范围注明「`.git` 元数据将一并销毁」；以 `.git` 或其内容本身为目标的删除仍按 `catastrophic.git-metadata` 绝对拒绝。

### 候选与覆盖状态

单次结果为 `{ status, operations, candidates, gaps }`，所有列表均可为空。

| 成员 | 内容 |
|---|---|
| `candidates` | 含 `kind`、`origin`、`reason` 和可选 `knownScope`。`dynamic-execution` 表示已识别的动态执行位置。`unverified-effect` 表示有具体破坏性操作线索，事实尚不足以进入操作分档 |
| `gaps` | 含 `kind`、`unitId`、`origin`。原因结构至少区分无分析器、源码不可读、编码不支持、局部语法失败、不支持结构、上下文不明、局部预算耗尽及检查故障 |
| `status` | `complete`、`partial`、`fault`。`complete` 表示声明范围的检查结束。`partial` 表示回包有效并说明哪些部分未覆盖。`fault` 表示服务、协议或整次检查未能给出可信结论 |

已确认动作但目标未知时，保留一项操作。可信事实不足以确认动作时，只有在源位置与执行线索均可说明时才记录风险候选。普通参数未知只影响有关参数的求值。诊断限于原因、来源位置和必要的经打码目标信息。

结果由最严重的单元状态归并。故障结果保留经过验证的既有证据供诊断。无分析器的单元返回 `partial`，缺口原因明确为无分析器。解释器脚本文件正文不读取时返回 `partial`，缺口原因为 `script-file-body-not-analyzed`。空位或回包缺失由调用方归类为检查故障。

### 跨语言例子

同一个隔离目录下，Bash 的 `rm -- sample.txt`、PowerShell 的 `Remove-Item -LiteralPath sample.txt` 和受支持的 Python、JS 文件删除 API，均应产出 `action=delete`、`target.kind=exact` 且仅含 `sample.txt`。语言与来源位置可以不同。若该路径来自无法静态求值的表达式，保留 `action=delete` 并使用 `target.kind=unknown`。若只在输出字符中出现命令文本，结果为空。

## 资源与边界

分析根调用持有一个共享预算对象，子单元只消耗剩余预算。入队前扣减分析单元数和深度，读取前检查字节上限，解析器回包时检查输出上限，再扣减保留的节点数。队列等待和请求执行都受同一个调用期限约束。期限向子单元传播，子单元不得延长它。

| 预算维度 | 生效位置 |
|---|---|
| 总耗时 | 覆盖排队、源码读取、解析及有界求值。各步骤使用剩余时间 |
| 输入、输出与内存 | 限制单份源码、聚合源码、单个解析回包和保留结果大小 |
| 展开工作量 | 限制单元数量、嵌套深度、语法节点、符号跳数、读取文件数及目标集合规模 |
| 宿主资源 | 限制全局并发、排队长度和解析子进程个数 |

实现接收显式的有限预算，测试可注入小值。发布值由目标平台的同一语料、并发测量、峰值资源和 DSH 执行时限确定。局部预算达限且可形成可信缺口时返回 `partial`。整次分析超过期限、回包不符合协议或分析器崩溃时返回 `fault`。取消和卸载应清理请求、计时器、监听器与辅助进程，每次回包要绑定请求身份。

覆盖限于可接入的本地或同一已证执行域。远端、容器内部、云 SDK 和内嵌 SQL 的后续副作用属于覆盖边界：对这些入口只表达命令事实与确认范围，不模拟资源模型，也不据此做本地盘存。脚本执行前可能被外部修改，静态分析只能标识读取到的版本以及仍可观察的变化。解释器脚本文件正文不读取（RR-5）；这是与 Shell 脚本文件正文的明确区别。

## 验收

- 用同一隔离目标验证各语言的等价操作产出相同事实。目标未枚举时保留操作和已知范围。
- 用相同外部命令分别经直接 `argv` 和 Shell 文本进入分析，验证参数边界和执行语义。
- 对 `complete` 空结果、`partial` 缺口、候选、`fault`、取消和迟到回包分别断言。可检测的局部缺口不得丢弃同一调用已确认的操作。
- 对多层包装、多个脚本与重复进入同一单元的场景注入小预算，验证合计上限和资源回收。
