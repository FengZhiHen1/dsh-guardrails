# DSR-025 定位重定位与判定模型重构

- 状态：已采纳
- 日期：2026-11-17
- 关联：[需求](../需求.md) v2、[规则模型](../technical-details/规则模型.md)、DSR-019/020/021（部分被取代）、DSR-022/023/024

**决定 / 理由 / 被否决项：** 把插件从"只防灾难性删除"重定位为**多面安全网**（数据破坏 / 凭据与敏感信息 / 不可控执行三面），并用"**不可逆 × 后果 × 可重建性**"三档（拒绝 / 确认 / 放行）取代 L1/L2/L3 与"`>20` 硬拒"。否决"维持只防灾难性删除"与"策略闸门（默认收紧）"。

## 背景

用户指出"本插件只防灾难性删除"这一表述错误。审计证实：插件实际同时防凭据泄露（受管结果打码（旧号 `R-M1`）、内联真实凭据纠正型拒绝（旧号 `R-M2`）、敏感文件确认）、不可控执行（`run_code`、动态执行通道）与数据破坏；一半以上能力与删除无关；`>20` 门禁、敏感文件审批都不在"灾难"量级。该错误表述把凭据面降为"附带例外"，使"L3 其余一律放行"与凭据面自相矛盾，也是历次极性混乱与过度拦截（把只读命令的未知选项当危险）的表述根源。

## 真实方向与评价

| 方向 | 评价 |
|---|---|
| 维持"只防灾难性删除" | 与代码实际能力矛盾，弃 |
| 策略闸门（默认收紧、证明安全才放行） | 与"安全网、低误报"目标相反，弃 |
| **多面安全网**（选定） | 与包描述、代码能力、用户指令一致 |

判定模型方向：

| 方向 | 评价 |
|---|---|
| 保留 L1/L2/L3 与 `>20` 硬拒 | 把可重建清理（`node_modules`）也硬拒，过度拦截；且"灾难/非灾难"不是正确判据，弃 |
| **不可逆 × 后果 × 可重建性三档**（选定） | 可逆/可重建放行、批量/动态/敏感确认并列范围、灾难身份拒绝 |

## 决定

1. **定位** = 多面安全网，面向善意但会犯错的 agent；原则 = 不可逆且高后果 → 拒绝或确认，可逆 / 低后果 → 放行。
2. **三面** = 数据破坏 / 凭据与敏感信息 / 不可控执行，互不替代。
3. **三档判定**：拒绝（仅灾难身份，无条件、不可审批/配置覆盖）/ 确认（批量 `>20`、目标不可枚举、敏感文件操作）/ 放行（可重建、≤20 非豁免、未命中）。
4. **确认必须列范围**（文件清单、计数、受保护命中、无法枚举部分）。
5. **规则可解释可配置**（R-18、[规则模型](../technical-details/规则模型.md)）：稳定规则号、`intent`、`severity`、证据；按规则号放行（`rules.<id>.allowlist`）、一次性放行；项目层只能收紧；灾难规则不可关。
6. **取代与并入**：取代 DSR-019 的"`>20` 硬拒"与 DSR-020 的 L2 硬门禁；DSR-022（前门只命令面、未知工具放行）、DSR-023（语言层动态目标由拒绝改为确认）并入本模型。DSR-021 的"非删除 unknown 放行"方向保留并升级为"删除相关性门控"。

## 直接后果

- `需求.md`、`规则模型.md` 就地重写为新模型；`架构重构设计.md` 的决策点改为新三档。
- DSR-019 / DSR-020 的 L2 条款由本决策取代（原文不改，以本记录为准）。
- 相对旧实现的可见行为改变：`>20` 由**拒绝 → 确认**；可重建批量产物由**拒绝/计数 → 放行**；只读命令的未知选项/循环/成员由**可能拒绝 → 放行**；MCP/未知工具由**拒绝 → 放行**；语言层动态删除目标由**拒绝 → 确认**；灾难身份仍**拒绝**。
- README 状态区与 TODO 同步。

## 重访条件

若批量删除"确认"在生产中噪声过大，或出现"确认后仍误删"事故，重访是否对特定路径类恢复硬拒；若"可重建证据"无法在误报与伪装之间取得平衡，重访其判据。执行面（`run_code`/动态执行）的处置已由 [DSR-026](DSR-026-执行面尽力分析.md) 定为"尽力分析后分档"。
