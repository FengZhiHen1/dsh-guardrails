# DSR-027 统一执行分析契约

- 状态：已采纳
- 日期：2026-11-18
- 关联：R-09、R-12、R-16、R-17、R-19，DSR-024、DSR-025、DSR-026

**决定 / 理由 / 被否决项**　各语言遵守同一分析契约，DSH 命令行工具只在接入层适配 / 同等证据应按同一规则处置，覆盖缺口应可见 / 否决按语言或入口独立定义判定，以及无分析器就确认。

## 上下文

目标设计已有单一决策点。Shell 先产出命令与参数结构，Python 和 JavaScript/TypeScript 另产出删除操作，两处各定义了失败处置。DSR-026 决定 4 将没有分析器的语言单独升级为确认。同一决策又要求按删除候选分流。

DCG 的内嵌代码分析区分局部分析失败与总评估截止时间。CC Safety Net 区分默认覆盖范围、严格策略和顶层失败。这两种做法提供了区分覆盖缺口与检查故障的参考。

## 取舍

| 议题 | 选定 | 代价与被否决项 |
|---|---|---|
| 分析边界 | 各语言使用适合本语言的语法结构，对外提交同一操作事实 | 需要明确操作、目标和执行上下文的映射。否决以 Shell 命令结构作为全语言接口 |
| DSH 命令行入口 | DSH 提供执行上下文及门禁接线，统一规则根据证据判定 | 需取得终端实际上下文。否决同等证据下仅对 DSH 工具附加处置 |
| 未接入分析器且无可见风险 | 放行，记录覆盖缺口 | 正文中可能存在未识别的风险。无分析器即确认会让支持覆盖率决定正常脚本能否执行 |

## 直接后果

- 新增 [项目结构设计](../项目结构设计.md) 与 [技术栈设计](../技术栈设计.md) 作为项目级定调。
- [执行分析](../technical-details/执行分析.md) 统一分析契约和状态。各语言语法映射分篇保留。
- [架构重构设计](../technical-details/架构重构设计.md) 保留 DSH 前门、取证和执行关联。R-17 的用户可见行为归 [需求](../需求.md)，执行处置细则归 [规则模型](../technical-details/规则模型.md)。
- 本决定取代 DSR-026 决定 4，保留其对源码先尽力分析的方向。DSR-024 的类型化语法角色继续保留在适用分析器内，共用边界改为操作事实。
- 旧目标方案的 `execution.run_code`、`execution.inline-code`、`execution.unanalyzable-shell` 按入口分配规则号。统一后以风险证据分配规则，入口留在诊断来源。同一风险证据使用同一规则级配置。
- 现有范围要求、目标计数、灾难身份、凭据规则及必检调用的最终门禁继续生效。

## 重访条件

在隔离验证或人工标注语料中发现常见用法因覆盖缺口导致不可接受的漏判，或必检故障造成高频阻断时，分别重访分析器覆盖和分析预算。对等语言用例应继续产出等价证据。
