# DSR-010：文本引用豁免（引用敏感名 ≠ 访问敏感路径）

## 上下文

`GIT_DIR_REFERENCE` / `ENV_REFERENCE` / `CRED_TEXT_REFERENCE` 是在"只有文本、没有操作类型"的 pwsh 通道上按**文本出现**判定敏感引用的兜底（`命令文本分析.md` 固有限制第 1 条已声明误伤）。2026-09-27 实测暴露该兜底的一类系统性误伤：命令字符串里**引用**敏感名（而不是访问它）也被判成路径引用。

本机实测复现（agent 侧探针，均为真实使用形态）：

| 命令 | 旧行为 | 性质 |
|---|---|---|
| `git commit -m "…引用 [guardrails] Blocked: this shell command references the .git directory…"` | **拦** | 提交信息引用了本插件自己的拒绝原文——记录门禁结果时被自己的守卫拦住 |
| `git commit -m "fix: load .env earlier"` | **拦** | 提交信息提到 `.env` |
| `git commit -m "docs: keep .ssh out of the repo"` | **拦** | 提交信息提到凭据目录 |
| `Write-Output "see .git for history"` | **拦** | 纯输出文本 |

即 `.git`/`.env`/凭据名只要出现在命令文本任意位置（含引号内的散文）就触发硬阻断，使"用 `git commit` 提交一份引用了守卫拒绝原文的说明"这类**正当且高频**的操作无法进行。

## 真实方向与评价

- 方向 A：**引用位置豁免**——在词法层把"引用"与"路径"分开，只豁免**能证明不可能是敏感路径本身**的位置（散文引号分段 + 文本/模式参数的值）。
- 方向 B：改为真正的参数解析 / 路径提取（同 DSR-002 的方向 B）。语义最正，但 PowerShell 参数解析完备性成本不成比例，且正则兜底仍须保守——DSR-002 已以同一理由否决过。
- 方向 C：维持现状，只把规避写法（提交信息写入文件后 `git commit -F`）记进文档。零风险，但误伤面留在插件里，每次引用都要绕。

评价：A 的可行性取决于"豁免位置不可能藏住一次访问"能否被证明——可以（见下），故选 A。C 把成本转嫁给使用者且同类误伤会反复出现，仅作兜底方案保留。

## 最终决定

新增 `maskTextSpans()`（`src/core/command.js`）。在**仅文本引用检查之前**，把"引用位置"抹成等长空白：长度与其余字符的偏移完全不变，故真实路径周围的定界上下文不受影响。

1. **散文引号分段**：引号内**含空白且不含 `\` 或 `/`** 的分段。
   - 安全性可证：含空白、不含分隔符的字符串只能指名**当前目录下的单个文件名**，而 `.git` 这个名字本身不含空白 ⇒ 该分段不可能是 `.git` 目录，抹掉它不可能藏住一次对 `.git` 的访问。
   - 含分隔符的引号分段（`"C:\Program Files\x\.git\config"`、`'.git/config'`）**保持全规则**，故绝对/相对路径不受影响。
2. **文本/模式参数的值**：`-match`/`-notmatch`/`-like`/`-notlike`/`-replace`/`-split`/`-join`/`-contains`/`-notcontains`，以及 `-m`/`-Message`/`-Title`/`-Description`/`-Subject`/`-Body`/`-Comment`（含 `-Param:value` 内联式）。这些值不会被任何 cmdlet 当文件打开。
   - **路径能力参数一律不在豁免集**：`-Path`/`-LiteralPath`/`-Filter`/`-Include`/`-Exclude`/`-Pattern`/`-Value`/`-Destination`。其中 `-Filter`/`-Pattern` 名字看着像文本参数，但**真的会命中文件系统名字**，豁免它们风险大于收益。

豁免**只作用于三个文本引用检查**：列举模式判定、内容级别分类、系统区写（W0）、不可验证 fail-safe、破坏性分析全部仍看原命令。

## 直接后果

- `src/core/command.js` 新增 `maskTextSpans()`，配一个位置感知的 `scanWordSpans()`——`tokenizePwsh` 会把引号解析进词值且不留偏移，答不了"这个名字是不是写在散文里"，故不复用。
- `src/core/check-command.js` 由 `resolved` 算出 `cited`，只把 `cited` 喂给 `detectContentSensitiveRef()` 与 `CRED_TEXT_REFERENCE`。
- 测试 130 → 138：`command.test.mjs` +6（散文分段 / 含分隔符分段不豁免 / 参数值豁免 / 路径能力参数不豁免 / 偏移不变 / 抹除与否决定引用判定），`guard.integration.test.mjs` +2（引用放行 6 例 + 真实路径仍拦 10 例，含 `git commit -m "see .git" -- .env` 证明引用不会给旁边的真引用洗白）。
- **已知残余误伤（接受并文档化，均为 fail-closed 方向）**：① `-Pattern` 的值不豁免（`Select-String -Pattern '\.git'` 仍拦）；② 无空白且不含分隔符的散文分段不豁免（单独的 `'\.git'` 仍拦）。

## 重访条件

- 出现落在残余误伤面内的新高频形态（例如以 `-Pattern` 传正则成为常态写法）时，重新评估 `-Pattern` 的豁免可行性。
- 若未来改为真正解析参数与路径（DSR-002 方向 B），本豁免应整体删除而非叠加。
