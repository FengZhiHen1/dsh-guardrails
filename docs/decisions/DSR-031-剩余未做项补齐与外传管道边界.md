# DSR-031 剩余未做项的补齐与外传、管道边界

## 背景

DSR-029 与 DSR-030 补齐了删除族、包装层、`cmd.exe`、git 子命令、`ssh` 载荷、`tar --remove-files` 与设备擦除的薄层后，[TODO](../TODO.md) 仍列着一批未做形态。它们分两类：一类是**同一破坏语义换个入口**（heredoc 传递、`ssh` 的 PowerShell/cmd 通道、`sgdisk`/`parted` 其余写子命令、`tar -C`、云/DB/K8s 更多子命令、`unshare`、`git … --abort`、PowerShell 管道删除、`docker run` 绑定挂载载荷），另一类是**参考项目置 strict 档而我们没做**的外传面（数据外传与云元数据端点）。本决定把两类一次做完，并写明各自的安全下限与放行边界。

参考项目为 `references/cc-safety-net`（下称 CSN）与 `references/dcg`。两者对本决定各形态的实际覆盖与其证据由取证任务给出，本文只写我们采纳的结论与边界。

## 决定

1. **`ssh host <<EOF` 与 `wsl … bash <<EOF` 的 heredoc 正文是远端 shell 的 stdin 脚本。** 接收者是 POSIX shell 解释器且该调用从 stdin 读脚本时，正文作为同域子单元分析（`ssh` 用 `domain: 'ssh'`，`wsl` 用 `domain: 'wsl'`、`platform: 'linux'`）。`ssh host` 既无命令又无 heredoc 时仍记缺口放行。

2. **`ssh` 的 PowerShell 与 cmd 通道按接收者方言分析。** `ssh host powershell -Command '…'`、`ssh host pwsh -c '…'` 的载荷作为 `powershell` 子单元；`ssh host cmd /c …`、`cmd.exe` 作为 cmd 方言子单元（执行分析索引增加 `cmd` 语言入口，复用既有 cmd 词法器）。接收者无法用字面量辨识时记缺口。
   - PowerShell 子单元**不声明** `platform: 'win32'`：远端可能是 Linux 上的 `pwsh`，声明 win32 会让 `rm` 走 Windows 别名与路径语义。删除在 `ssh` 域内表达为 `unknown` + `knownScope`，按 `data.delete.dynamic` 确认。

3. **设备写子命令补齐到「改分区表即设备变更」。** `sgdisk` 的 `-d/--delete`、`-n/--new`、`-t/--typecode`、`-A/--attributes`、`-c/--change-name`、`-Z/--zap-all`、`-o/--clear` 都是分区表写入，进入 `write-content` + `details.deviceMutation` 路径；这些选项的取值必须被正确消费，不得当作磁盘操作数或被后续选项吞掉。`parted` 的 `resizepart` 与既有 `mklabel`/`mkpart`/`rm` 同级。只读形式（`sgdisk -p/--print`、`parted -l/--list`、`-v/--version`）保持放行。

4. **`tar -C/--directory` 改变成员的解析基准。** 每段 `-C` 依次重定位成员的解析目录；删除目标表达为按该目录解析后的路径，解析目录不可证明（动态取值、相对路径无法求值）时按 `unknown` + `knownScope` 表达。`--remove-files` 之外的 `tar` 调用维持既有缺口放行。同档覆盖归档后删源的等价工具：`7z a -sdel`、`zip -m/--move`。归档工具（`tar`/`7z`）对目录成员默认递归，递归标记一律为 `true`，由证据层按实际类型分流（单文件计 1 条、目录枚举子树）；`zip` 的递归由 `-r` 决定，无 `-r` 时不标记递归。

5. **云、数据库、容器、IaC 的删除面按「删除与不可逆资源变更」逐类补齐**（`aws` 的 `ec2 delete-*`、`iam delete-*`、`s3 rb`、`dynamodb`、`rds`、`efs`、`secretsmanager delete-secret` 等；`gcloud`/`gsutil` 的 `delete`/`rm`/`rb`；`az` 的 `group`/`vm`/`sql`/`storage`/`keyvault delete`；`kubectl delete` 的 `pvc`/`pv`/`ns`/`secret`/`crd`；`helm uninstall`；`docker` 的 `prune` 族与 `volume rm`；`terraform destroy`/`state rm`；`mongosh`/`redis-cli`/`mysqladmin` 的库表级删除）。判定统一沿用远端删除契约：`delete` + `unknown` + `knownScope` + `details.remote`，确认档；只读查询、`--dryrun`/`--help` 与无资源名的调用不产生操作。

6. **外传面只做两条可证边界，不做通用出网拦截。**
   - 云元数据端点（`169.254.169.254`、`fd00:ec2::254`、`metadata.google.internal`、`100.100.100.200`、`169.254.170.2`（ECS task role）、`169.254.170.23`、`fd00:ec2::23`（EKS Pod Identity）、`metadata.goog`）由 `curl`/`wget` 访问：产出 `unverified-effect` 候选，按 `execution.unverified-effect` 确认。端口忽略，主机名精确比较。
   - 本地文件上传：`curl -T/--upload-file`、`-d @file`、`-F name=@file`、`wget --post-file`/`--body-file`，以及云存储上行（`aws s3 cp/sync`、`gsutil cp`、`gcloud storage cp`、`az storage blob upload` 的本地源）产出 `read-content` 事实，凭据文件由既有凭据规则判定。
   - 普通出网、普通上传（非凭据文件、非元数据端点）**不产生**任何操作或候选：这是本决定对正常上传流量的零摩擦承诺。

7. **`unshare` 是透明包装。** `unshare [options] <program> …` 解包后按内层命令分析，解包本身不新增候选或拒绝；无程序操作数记缺口。命名空间能力本身不单独判定。

8. **`git rebase/merge/cherry-pick/revert/am --abort` 只在证明「有进行中状态」时确认。** facts 用 `git-restore` + `{kind:'unknown', reason:'git-evidence', knownScope:[<子命令说明>]}` + `details.command: '<子命令>-abort'`（`knownScope` 必填，否则无范围的 `unknown` 会被判成拒绝而不是确认）；证据层只读探测 git 目录下的 `rebase-merge`、`rebase-apply`、`MERGE_HEAD`、`CHERRY_PICK_HEAD`、`REVERT_HEAD`。进行中 → 记 `noteUnknown`（确认 `data.git.restore`；`rebase`/`am` 的 abort 会丢弃未提交改动，`merge`/`cherry-pick`/`revert` 只重置操作状态、未提交改动可能保留，范围文本按子命令区分），并把探测到的状态并入该 `knownScope` 以便展示；不存在 → 不记录（按 `buildDeletionHit` 的 `git-evidence` 例外放行）；探测失败 → `noteUnknown`，不得升级为 `execution.check-failed`（D1）。

9. **`Get-ChildItem … | Remove-Item` 的删除范围来自管道源命令。** PowerShell 解析结果暴露每个命令在 `PipelineElements` 中的位置后，`Remove-Item` 这类无显式路径的删除把上一元素的命令文本作为 `knownScope`，产出 `delete` + `unknown`；不伪造精确路径。源命令无法辨识时仍按 `unknown` + 通用范围表达，不产生额外候选。

10. **`docker run|exec` 的载荷只在触碰宿主文件系统时分析。** 存在宿主绑定挂载（`-v`/`--volume` 的绑定源、`--mount type=bind`）、`--device` 或 `--privileged` 时，载荷作为 `domain: 'container'` 子单元分析，删除在该域内表达 `knownScope`，由 D2 保证不进入宿主盘存，按 `data.delete.*` 确认；没有上述暴露时不分析载荷（容器内删除不影响宿主，保持缺口放行）。容器域内对被 `--device` 暴露的块设备做写入时取不到宿主设备身份，按不可证设备选择器处置：保留 `write-content` 事实与 `unverified-effect` 候选，**拒绝**而非静默放行（与本地设备选择器不可证时同档）。

11. **不新增规则号。** 以上全部落在既有 21 个规则号上；任何无法落到既有规则号的形态不实现，留给后续决定。

12. **删除面与传输面按参考项目的地表补齐，但仍只做可证形态。** 云/数据库/容器/IaC 的删除与不可逆资源变更按 provider 薄表补齐（`aws` 的 `ec2 delete-*`/`iam delete-*`/`s3api`/`efs`/`elasticache`/`secretsmanager`/`kms`/`sqs`/`sns`/`logs`/`cloudformation`/`lambda`/`ecr`/`route53`；`gcloud`/`gsutil`；`az` 的 `group`/`vm`/`sql`/`storage`/`keyvault`/`webapp`/`aks`/`network`/`disk`/`cosmosdb`/`redis`/`identity`；`kubectl delete` 的 `pvc`/`pv`/`ns`/`secret`/`crd`/`drain --force`）；备份与密钥源删除（`restic forget --prune`/`prune`、`borg delete`/`prune`、`rclone delete`/`purge`、`velero backup delete`、`gh repo delete`/`gh release delete`、`vault kv metadata delete`、`doppler`/`infisical secrets delete`）。`scp`/`rsync` 上行方向（目的地为 `[user@]host:path` 或 `[ipv6]:path`）对字面本地源产出 `read-content`。可恢复的软删除（`vault kv delete`、`vault delete`、`restic forget` 不带 `--prune`）按 D3 记缺口放行，不确认。全局选项写在子命令之前的形式（`aws --profile …`、`gcloud --project …`、`docker --context …`、`gsutil -m …`）先跳过再取子命令；完全没有字面资源选择器的 usage-error 调用不产生操作（取值动态的选择器仍确认）。

13. **PowerShell 方言不关闭外部程序的分析。** `language: 'powershell'` 只决定 cmdlet 与别名的解析方式；`ssh`、`find`、`rsync`、`tar`、`7z`、`zip`、`unshare`、`curl`、`wget`、设备工具、`docker run|exec` 载荷等外部程序在 PowerShell 单元中同样按各自的文法分析。DSH 的 `pwsh` 工具入口因此与 `bash` 入口具有相同的覆盖（差异只在 cmdlet/别名解析）。PowerShell 文本里没有 POSIX heredoc，heredoc 接收者分析仍只在 POSIX 方言下生效。

## 不做

- **PowerShell 5.1 的 `curl`/`wget` 别名差异**：这两个名字按外部程序分析（pwsh 7 已移除 `Invoke-WebRequest` 别名）；在 5.1 会话中若被解析成 `Invoke-WebRequest`，属该方言的既有边界，不另建立别名模型。
- 通用出网、批量上传与数据外传的内容判定（只做第 6 条的两条可证边界与第 12 条的传输读事实）。
- 隧道与交互传输：`nc`/`ncat`/`socat`、`ssh -R`/`-D`/`-o ProxyCommand`、`scp -i` 身份文件读、`sftp` 批处理、`rclone`/`azcopy` 之外的传输客户端。
- `parted` 交互式（裸 `parted /dev/sda`、`printf 'rm 1' | parted /dev/sda`）、`zip -d`、`7z` 除 `-sdel` 外的删除变体、`cmd` 双引号内含反斜杠路径的字面量折叠。
- `cmd.exe` 的 `for`/`if`/`%VAR%`、`/k` 交互、`del /s` 通配枚举（DSR-030 遗留）。
- 备份/密钥/平台面的长尾（`eks`/`glue`/`athena`/`redshift`/`kinesis`/`cloudtrail`、`bq`/`snowflake`/`databricks`/`supabase`、DNS/邮件/消息、CI/CD）。
- `ssh -o ProxyCommand`、多跳跳板链的额外语义：仍按文本分析。
- `unshare` 命名空间逃逸能力本身、`sgdisk` 非目标平台的设备身份判定。
- 管道删除的精确路径回填（只给 `knownScope`）。

## 后果

- 每条 `ssh`/`wsl` 的 heredoc 或 PowerShell 载荷多消耗一个分析单元，受既有单元预算约束。
- `git … --abort` 多一次只读 git 目录探测；探测只在 `git-restore` 分支、`details.command` 以 `-abort` 结尾时发生。
- PowerShell 管道删除从「无事实」变为「确认」，代价是 `Get-ChildItem | Remove-Item` 类清理命令需要一次确认；这是真实删除，符合 D3。
- 普通用法零变化：`ssh host ls`、`wsl ls`、`tar -czf`、`sgdisk -p`、`parted -l`、`kubectl get`、`aws s3 ls`、`psql -c "SELECT 1"`、`docker ps`、`git status`、`git merge --ff-only`、`curl https://example.com`、`npm publish` 全部 allow 且无候选。
