## 背景

v1–v3 把删除门禁做得越来越严：遇到未建模的程序名就拒绝、把 `terminal_send`/`create_worktree`/`terminal_open`/`plugin_manager` 全拒绝、把任意工作区外批量删除当成灾难。这把“删除门禁”和“可用性”混在一起，拒掉了很多没有删除能力的正常操作，也把“未知即拒绝”当作安全默认。用户裁决：插件只防**灾难性删除**，其余放行。本决策把该标准固化为三级。

## 决定

### 1. 三级标准

- **L1 灾难性删除，直接拒绝，永不计数、永不审批**：
  - 物理设备/卷销毁：`\\.\PhysicalDrive*`、`format`、`mkfs.*`、`diskpart`、`dd`、`fdisk`、`parted`、`wipefs`、`shred`、`cipher /w`、`vssadmin delete`、`wbadmin delete`。
  - 宿主系统树整树破坏。
  - `.git` 元数据路径（含 worktree 指针）。
  - 销毁 git 历史的 git 子命令（见 §2）。
- **L2 可识别命令行删除，计数**：枚举目标，统计未命中白名单的常规文件 + 链接条目；≤20 放行并执行；>20 拒绝。**工作区之外的删除同样计数**（不因“在边界外”本身拒绝；系统树/设备/.git 的 L1 除外）。
- **L3 其余全部放行**：未建模程序、`copy`、`create_worktree`、`terminal_open`、全部 `plugin_manager` 动作、常规 git 操作。

### 2. git 分级（`assessGit` + `git-evidence`）

| git 子命令 | 级别 | 处理 |
|---|---|---|
| `status/diff/log/show/add/commit/branch/switch/merge/rebase/fetch/pull/reflog/rev-parse`、`worktree add|list|prune`、`branch -D`、`tag -d`、裸 `gc` | L3 | 放行，不进入文件扫描 |
| `stash clear`、`stash drop`、`gc --prune=now/--prune=all`、`filter-branch`、`filter-repo`、`push --force/-f/--force-with-lease/--delete/--mirror`、无路径的 `reset --hard`、`reflog expire --expire=now --all` | L1 | `DI-GIT-REFUSE` 立即拒绝，带 doctrine |
| `clean`（`-f`/`--force`，非 `-n`）/ `restore <paths>` | L2 | `git-evidence` 计数：>20 拒绝（`DEL-GIT-CLEAN`/`DEL-GIT-RESTORE`） |
| `worktree remove <path>` | L2 | 见 §3；`DEL-GIT-WORKTREE` |
| 证据模块不可用或返回 unknown | — | fail-closed 拒绝（`DEL-GIT-UNKNOWN`），绝不放行 |

### 3. worktree remove 规则（用户口径，零容忍 + 忽略计数）

`git worktree remove <path>` 仅当：
1. `path` 解析成功（相对 `cwd`）；失败 → unknown 拒绝。
2. 目标是该仓库的**已注册 linked worktree**（非 `cwd` 的主 worktree、非缺失、非 locked）。
3. 非分离 HEAD（`symbolic-ref -q HEAD` 成功）。
4. `status --porcelain -unormal`：**任何**非 `!!` 行（未跟踪或已暂存/未暂存修改）即拒绝（`untracked-or-modified`，零容忍）。
5. 仅忽略条目 `--ignored=matching` 中，剔除可重建产物（构建输出、缓存、`node_modules`、`__pycache__`、`*.pyc`、`dist`、`build`、`target`、`.cache`、`vendor` 等）后，剩余非可重建条目 ≤20；非可重建的忽略**目录**计 1；>20 拒绝（`ignored-over-limit`）。
6. 任何 git 失败/超时 → unknown 拒绝；deadline 与计划共享。

### 4. L3 的两条诚实边界

1. **执行通道保持“可分析否则拒绝”**：目的是执行任意命令文本的通道（无法分析的 `bash x.sh`、`pwsh -Command $var`、`Invoke-Expression`、`env/xargs/sudo/start/source/call`、WSL 包装）在文本无法分析时拒绝。语言运行时（`node`/`python` 等）是显式例外（脚本是 agent 自己的程序）。`run_code` 仍拒绝（载荷是程序，不是命令行）。`terminal_send` 的 `text` 是命令行，**就地按平台方言分析**（Windows PowerShell / 其他 POSIX），可识别删除照常计数、无法分析则拒绝。
2. **灾难模式仍然拒绝**：即使程序名未知，`.git` 路径、provider 路径、工作区外批量（>20）、物理设备等模式仍拒绝。

### 5. `copy` / `move` 区分

- `copy` 不删源 → L3 放行（目标已存在的静默覆盖不额外拦截，仅在文案提示）。
- `move` 的源删除可枚举 → L2 计数，>20 拒绝（`DEL-14`「move 源删除」，带 doctrine）。

### 6. 诚实声明（必须保留）

**不得再声称“拦截所有删除”**。准确声明：**可识别的命令行删除被计数；无法分析的执行通道被拒绝；其余操作放行。**

## 后果

- 移除 `git`、语言运行时的命令名拒绝；未知程序名改为放行。
- `plugin_manager` 全部动作、`create_worktree`、`terminal_open` 放行；删除 `pluginManagerReadOnly` 助手。
- 边界外删除从“L1 拒绝”改为“L2 计数，>20 拒绝”。系统树/设备/.git 的 L1 保留。
- 新规则：`DEL-14`（move 源删除）、`DEL-GIT-CLEAN`/`DEL-GIT-RESTORE`/`DEL-GIT-WORKTREE`/`DEL-GIT-UNKNOWN`、`DI-GIT-REFUSE`。

## 已知残余风险

- 非原子：计数是 dispatch 前的观察，并发写者或同调用内前置 mutation 仍可能改变集合；不声称并发下原子 ≤20。
- 覆盖范围仅经 `ctx.tools` 受管的可识别操作；绕过工具通道的直接 runtime 调用、程序内部副作用不在覆盖内。
- `git-evidence` 依赖本地可用的 `git`；不可用时 fail-closed（拒绝而非放行），可能拒绝本可安全执行的 git 清理。
- worktree remove 的“可重建产物”判定基于固定分类器；自定义构建布局可能被当作非可重建条目而触发 >20 拒绝（保守，非漏放）。
- `git checkout <path>`（无 `--`、非 `.`/`:(`/反斜杠形态）被当作分支/路径切换放行、**不做删除计数**；它可能覆盖工作区文件。需要计数保护时改用 `git restore <path>`（计入 `DEL-GIT-RESTORE`）。这是 `checkout` 语义歧义（分支名与路径无法从词面唯一区分）下的有意取舍：只把明确的 `checkout .`/`checkout -- <path>`/`:(`/反斜杠判为 restore。
