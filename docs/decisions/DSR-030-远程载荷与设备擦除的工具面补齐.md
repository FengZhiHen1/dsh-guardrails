# DSR-030 远程载荷、heredoc 与设备擦除的工具面补齐

## 背景

0.3.0 把删除族、包装器、`cmd.exe`、git 子命令与远端薄层纳入分析后，仍有一批参考项目已覆盖的形态对插件不可见：`bash <<'EOF'` 的脚本正文、`ssh host '<命令>'` 的远程载荷、`tar --remove-files`、`diskutil`/`parted`/`sgdisk`/`fdisk`/`blkdiscard` 的设备擦除、`awk 'BEGIN{system("…")}'`。这些都是绕过成本低、后果不可逆的路径。

## 决定

1. **heredoc 正文按接收者决定是否执行语义**。接收者是 shell 解释器（`bash`、`sh`、`dash`、`zsh`、`ksh`，含 `bash -s`）时，body 作为同域 shell 文本继续分析；分隔符是否引号不影响结论（引号只影响变量展开，命令仍会执行）。接收者是数据工具（`cat`、`tee`、解释器、数据库客户端等）时 body 是数据，不分析。
2. **`ssh` 的远程命令按 POSIX shell 分析**。主机之前的选项与其取值按 `ssh` 语义跳过（`-t`/`-T` 只影响 TTY）；主机之后的参数合并为一段 shell 文本，`context.domain` 记为 `ssh`。删除动作在域内表达为 `unknown` + `knownScope`，判定为 `data.delete.dynamic` 确认；只有主机无命令时记缺口放行。
3. **`tar --remove-files` 是删除**。归档后删除源条目，按 `exact`/`subtree` 与递归标记进入常规删除分档；没有该选项时 `tar` 不产删除。
4. **设备擦除工具走设备变更路径**。`parted`、`sgdisk`、`fdisk`、`blkdiscard` 的设备操作数可求时，产出 `write-content` + `exact` 目标 + `details.deviceMutation`，交由灾难身份（`catastrophic.device`）判定；只有选择器（`diskutil` 的 `diskN`、盘号/盘符）无法映射到宿主设备路径时，产出 `write-content` + `unknown` 且**必须**同时产出 `unverified-effect` 候选，按既有语义拒绝，不得静默放行。
5. **`awk` 的 `system()` 是执行入口**。字面量参数按同域 shell 交子单元分析；变量或 `$0` 等动态参数记 `dynamic-execution` 候选。
6. 以上形态一律不新增规则号；只读子命令（`list`/`-l`/`-p`/`print`）与无破坏语义的调用保持放行。

## 不做

- `ssh host <<EOF`（无远程命令，载荷是本地 stdin）与 `wsl … bash <<EOF` 的 heredoc 传递：记缺口放行。
- `ssh` 的 PowerShell/cmd 通道、`sgdisk -d/-n/-t`、`parted resizepart` 等其余写子命令：记缺口放行。
- `tar -C` 对相对成员的目录语义：按执行 cwd 表达，不重定位。
- 网络外传与云元数据端点、`unshare`、`git rebase/merge --abort`、无显式路径的 `Remove-Item` 管道：维持既有延期或未做状态（DSR-029）。

## 后果

- 新增形态在目标可枚举时按 R-07 分档，在目标不可证时按既有语义拒绝；正常用法（`ssh host ls`、`tar -czf`、`diskutil list`、`awk '{print $1}'`、`bash <<EOF` 只含 `echo`）保持放行且无候选。
- 设备擦除的安全下限由此前「一律 allow」变为「路径可证则灾难身份判定，选择器不可证则拒绝」。
- 设备身份依赖平台探测：非目标平台（例如 Windows 宿主上的 `/dev/sda`）拿不到设备身份时只表达操作事实而不拒绝，这与「镜像文件不得凭路径词面拒绝」的既有口径一致；目标 Linux 平台由身份探测给出 `catastrophic.device`。
- 代价：每条 `ssh` 命令勾与 `awk system` 字面量会多消耗一个分析单元，受既有单元预算约束。
