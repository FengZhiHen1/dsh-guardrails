# DSR-005：W0 系统区读语义——读放行、只拦写

## 上下文

范围边界（DSR-001）决定新增 system 类别拦截系统区写入。参考文档对 W0 的定义是"受限可读、禁止修改"——"受限"程度需要定夺。

## 真实方向与评价

- 读放行、只拦写：系统区敏感内容已由 R0 名单覆盖（SAM/凭据/浏览器资料/DPAPI 等，读也禁），其余系统文件（dll/exe/ini/公开配置）读取基本无害；无需二次拦截。概念最少，与"内容泄露防护"目标对齐。
- 读写都拦：与参考文档 W0"受限可读"字面最接近，但会误伤查看系统公开结构等无害操作，需要额外白名单机制（版本、区域、扩展名），复杂度上升且收益被 R0 名单吸收。

评价：R0 名单负责"哪些系统内容读也禁"，system 类别只负责"系统区不可写"，两者叠加语义完整；读写都拦的增量价值趋近于零。

## 最终决定

system 类别只拦写（write/edit 工具与写类命令文本命中系统区前缀），读与列举放行。

## 直接后果

- write/edit 指向 `C:\Windows\**`、`C:\Program Files\**` 等被拦；read/grep/glob 指向同路径放行。
- 系统 Hive（SAM/SECURITY/SYSTEM）由 credentials 名单承担读禁，不依赖 system 类别。

## 重访条件

- 系统区读取出现实际泄露面（如公开配置含令牌）时，评估"受限读"白名单机制。
