# DSR-028：解释器脚本文件正文不读取

**决定 / 理由 / 被否决项**　对 `python`、`node`、`tsx`、`deno`、`bun` 等解释器后接的脚本文件，只保留外层命令事实与来源，**不读取、不分析脚本正文**，以 `script-file-body-not-analyzed` 覆盖缺口返回 `partial`；Shell 脚本文件（`bash`/`sh`/`pwsh -File`）仍按命令文本分析读取。内联 `-c`/`-e` 与 PTC `run_code` 仍按执行分析契约分析。

- 日期：2026-11-18
- 状态：已采纳
- 关联：R-17、DSR-026、DSR-027

## 上下文

Python/JavaScript/TypeScript 脚本文件正文包含 `rm(root, { recursive: true })` 这类动态目标时，静态分析无法在不执行脚本的前提下证明 `root` 的来源（例如 `mkdtemp` 在运行时生成）。按现有规则会进入 `execution.unverified-effect`，因无可说明范围而拒绝。这个拒绝命中的是“测试脚本清理自己创建的临时目录”这类良性场景，误伤面大，且实现无法给出可信的“无影响”证明。

参考项目的处理边界：

- **cc-safety-net**：`docs/residual-risk.md` RR-5 明确，`python tool.py` 等解释器文件不读取；Shell 脚本文件才做 best-effort 正文分析，且不确定结果保留外层命令裁决。
- **dcg**：`docs/agents.md` 明确写入脚本文件再执行属于“same limitation”；只分析 inline/heredoc。其 Python `mkdtemp` 生产者证明（`tempfile_provenance.rs`）也只覆盖 inline 直接清理，跨行两段式仍拦截。

## 决定

1. 解释器脚本文件正文不进入分析：分析层遇到 `source.kind='file'` 且语言为 `python`/`javascript`/`typescript` 时，不读取文件，记录 `script-file-body-not-analyzed` 缺口；外层命令事实、来源和执行条件保留。
2. Shell 脚本文件（bash/posix/pwsh -File）保持现有读取与解析，不因本决定收缩。
3. 内联源码与 PTC `run_code` 保持现有分析；`-c`/`-e` 的正文仍属于分析面。
4. 该缺口是覆盖边界而非检查故障：无其他风险证据时按 R-17 放行并留下诊断；未覆盖的正文写入 TODO「解释器脚本文件正文覆盖（RR-5）」。
5. 不为解释器脚本文件新增“按文件无影响即放行”的启发式；静态分析不执行、不建立跨回调 taint，避免把“看起来无害”当成证明。

## 直接后果

- `node test/target-analysis.test.mjs` 这类直接执行脚本文件的调用不再因脚本正文中的动态 `rm(root)` 被拒绝；命令本身仍受外层 Shell 分析与其他检查约束。
- 原测试 `a scoped file entry is read as data and preserves child origin` 改为覆盖边界用例：断言不读取正文、返回 `partial` 与 `script-file-body-not-analyzed`。
- 解释器脚本文件正文中的删除/内容操作不再被 Guardrails 计数；这是明确接受的残余风险，写入 R-17 覆盖边界与 TODO。

## 重访条件

若真实语料显示“脚本文件正文中的删除”是高后果且可高频发生，或目标平台提供可靠的解释器执行前入口/沙箱，重新评估是否引入有界正文读取与来源证明；在此之前保持本边界。
