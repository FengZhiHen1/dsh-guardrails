# DSR-019：删除计数与不确定执行拒绝

**决定 / 理由 / 被否决项：** 用户确认把任意删除操作收紧为「执行前计数 + 超 20 硬拒绝 + 未知显式拒绝」；本决策覆盖 DSR-017 中与之冲突的条款（删除默认 Allow、不设生成物白名单、数量只作辅助、Unknown 不 Deny 等旧表述），历史 DSR 原文不改。否决「删除一律 Allow 靠 Auto Review」「只按 basename 整树豁免」「把 agent 自报/dry-run 当授权」。

- 日期：2026-11-14。
- 状态：源码实现，源码与隔离 Runtime 验证通过，详见[验证记录](../verification/2026-11-14-delete-gate.md)。live 激活已在验收环境复验；UI 显示、稳定环境部署与 Linux/跨平台实跑尚待完成（见「后果与重访」）。本记录是决策沉淀，不是稳定部署生效证明。
- **前向更新（v4）**：本决策的“未知显式拒绝”口径已被 [DSR-020 灾难性删除标准](DSR-020-灾难性删除标准.md) 部分修订——未知**程序名**改为放行（L3），仅执行通道无法分析时拒绝；删除门禁收敛为 L1/L2/L3 三级。本记录保留历史决策原文，冲突处以 DSR-020 为准。

## 上下文与备选

DSR-017 采用官方双 Shell AST 与最终硬门禁，但把正常清理、缓存、生成物与局部 Git 默认 Allow，并把文件数量只当作已命中风险的辅助说明。用户在此后的一次批量删除事故中确认要收紧：任意删除都要在执行前计数，超过单次 20 文件上限必须硬拒绝，无法确证的删除必须显式拒绝而不是放行。

| 方向 | 评价 |
|---|---|
| 维持 DSR-017 的「删除默认 Allow + 数量仅辅助」 | 不符合用户已确认的收紧目标 |
| 只按目录 basename（dist/build/tmp/node_modules 等）整树豁免 | 用户明确否决：混淆用户资料与生成物，且易被伪装 |
| 把 agent 自报、预览/dry-run 当作删除授权 | 不可靠，且不构成真实执行前证据 |
| 执行前逐条计数 + 未知显式拒绝 + 保守文件级白名单 | 选定 |

## 决定

1. **20 文件硬门禁**：整次调用内统计未命中白名单的常规文件 + 删除的链接条目；目录去重（按路径）单独报告目录数。`<=20` 要求完整枚举；`>20` 可早停于「至少 21」，绝不声称精确总数。
2. **未知显式拒绝**：未知命令/效果、未证明的 shell 解释器脚本、未知可执行、Git hooks/aliases、分页器、`-exec` 模式、启动/profile 文件、重定向与方法副作用，都显式拒绝并要求更清晰、受支持的命令；不因 basename 熟悉而放行。仅极窄的可验证非删除命令形态可通过。所有删除类拒绝附统一强提示（先列明并核对确切文件集）。**（v3 修订）语言运行时脚本放行**：`node/python/perl/ruby/php/deno/bun/uv` 作为不透明脚本运行器直接允许（不计数），其内联代码开关（`-e/-c/-p/-r/-E/-i`、stdin `-`）仍 `DI-INLINE-CODE` 拒绝；**shell 脚本文件**在可证明（字面路径、存在、常规文件、≤1MiB、编码可判定）时分析其内容并计数。
3. **`run_code` 整个 transport 一律拒绝**（不仅 direct Node 载荷，副作用不可排除）；**`terminal_send` 持久终端无例外一律拒绝**（状态不可靠推断）。真正边界是「不经 `ctx.tools` 直接调用 runtime service」，本插件不覆盖该直连路径。
4. **未审查工具默认拒绝**：只有与框架协调、经审查的 `tools` 走 allow-list 放行；不把任意工具名 blanket 标为安全。
5. **WSL/跨域删除无法在宿主枚举时拒绝**：不假设 `/mnt/X` 映射；Windows 上的 bash 删除域无法对应到 Node 路径时，要求改用 literal 的受管宿主命令（如 `Remove-Item -LiteralPath`）。
6. **保守内置文件级白名单（形态匹配 + 证据双通过）**：Python `__pycache__/*.cpython-<ver>[.opt-N].pyc`（需配对 `.py`）、pytest `.pytest_cache/v/cache/{nodeids,lastfailed,stepwise}`、mypy `.mypy_cache/<major.minor>/**/*.{data,meta}.json`、Maven `target/{classes,test-classes}/**/*.class`（需对应 `src/{main,test}/java`）、TypeScript `*.tsbuildinfo`（有限子集）。命中须再经证据适配器证明归属/再生才减计数。**（v3 修订）Cargo 取消自动豁免**：`target/*/deps/*.{rlib,rmeta,d}` 照常计数；`Cargo.toml` 仅保留为项目边界 marker。白名单是**计数-only**，受保护文件与绝对 Deny 始终生效；不做不检查保护/链接的整树跳过；不支持用户自加任意白名单。
7. **不把审批/自报/dry-run 当授权**：审批只放行当前调用；审批后需重新计数。检查与执行间存在 FS 并发竞态——已知边界，插件不声称 `<=20` 执行原子；同调用中先于删除的变更由 intent 层作为 `unknown` 交门禁拒绝。
8. **英文工具返回**：所有变更面 reason 为英文；文档可中文。
9. **不声称全语言语义完整或 live 生效**：不能把 Shell AST 成功等同于理解任意 SQL、云 SDK、容器内部或远端副作用；本轮交付为源码实现，验证待补。

## 对 DSR-017 的取代关系

- DSR-017 第 9 条「正常清理、缓存、生成物与局部 Git 默认 Allow；撤回一般清理白名单、生成物注册表；数量只附加已命中风险」被本决策收紧：删除不再默认 Allow，而是执行前计数 + 超 20 拒绝，并引入受严格约束的**文件级**白名单（仍不是目录白名单，也不是用户可配置白名单）。
- 覆盖 DSR-017 的旧「有效语法 Unknown 不自动 Deny」默认：**解析层只负责报告 Unknown**（覆盖限制，不在此层 Deny）；**策略层（`assessCommands`）对任何非空 `unknown` 都拒绝**——只要无法排除删除副作用，就拒绝并要求更清晰命令。旧 Unknown-Allow 默认不再保留。
- 其余 DSR-017 条款（官方 AST、最终硬门禁、自有审批、凭据遮罩、绝对/纠正型 Deny 三对象）保持不变。历史 DSR 原文不改。
