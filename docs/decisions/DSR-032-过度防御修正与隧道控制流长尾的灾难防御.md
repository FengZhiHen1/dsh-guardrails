# DSR-032 过度防御修正与隧道、控制流、云长尾的灾难防御

## 背景

DSR-031 交付后留下的两类问题：

1. **已确认的过度防御**（用户要求继续处理）：删除含 `.git` 的临时目录被 `git-metadata-inside-tree` 的检查失败升级为 `execution.check-failed` 拒绝，连正常清理临时仓库都做不到；`git restore --staged <paths>`（只还原索引、不动工作树）被当作工作树还原，走到 `git-evidence` 失败同样被拒。
2. **仍缺灾难防御的形态**（用户要求参考参考项目补齐）：隧道与传输（`nc`/`ncat`/`socat`、`ssh -R`/`-D`/`ProxyCommand`、`scp/sftp -i`、`sftp -b`）、`parted` 交互式、`zip -d`、`cmd.exe` 的 `for`/`if`/`%VAR%`、以及云/DNS/数据仓库的长尾删除子命令。DSR-031 把这些列在「不做」，但它们仍能造成灾难性错误。

参考项目：`references/cc-safety-net`（CSN）与 `references/dcg`（DCG）。判定分档沿用三档（拒绝 / 确认 / 放行）与既有 21 个规则号。

## 决定

### A. 过度防御修正

1. **`git restore --staged` 不产生破坏事实。** 只还原索引区（`--staged` 且未显式 `--worktree`/`-W`）不改变工作树，不产生 `git-restore` 操作，放行。`git restore --worktree`/`-W` 或无 `--staged` 的 `git restore` 仍是工作树还原，维持 `data.git.restore` 分档。
2. **删除目录树内含 `.git` 改为确认，不再以检查失败拒绝。** 子树枚举遇到 `.git` 条目时，不把其内容当作普通计数条目，也不把「无法完整计数」升级为 `execution.check-failed`；改为「已证实的删除 + 未观察到的 git 元数据」：产出确认（`data.delete.dynamic` 或 `data.delete.bulk`，按已计条目），范围明确写出「`.git` 元数据将一并销毁」。以 `.git` 或其子目录本身为目标的删除在 DSR-032 时仍按 `catastrophic.git-metadata` 绝对拒绝；**DSR-033 起改为确认（ask）**，Git worktree（`.git` 文件指针）不触发该审批。

### B. 隧道与传输面（灾难防御）

3. **`nc`/`ncat`/`netcat`/`socat`/`telnet` 的执行通道与本地读。**
   - 反弹/执行载荷（`nc -e <prog>`、`ncat --exec=`/`--sh-exec`/`--lua-exec`/`-c`、`netcat -e`、`socat` 的 `EXEC:`/`SYSTEM:` 地址）→ `dynamic-execution` 候选（`execution.dynamic-command`）：执行程序可证时按范围确认，范围不可证才拒绝。参数无法辨识时按缺口。
   - **`socat` 仅当另一端是网络类地址**（`TCP:`/`UDP:`/`OPENSSL:`/`SOCKS:`/`PROXY:`/`HTTP:` 等）时才判执行通道与文件读写；纯本地 `socat EXEC:… UNIX-CONNECT:…` 放行。
   - 本地文件作为外传源（`socat FILE:<path>`/`OPEN:<path>`；`nc`/`socat` 的 stdin 重定向由既有 `read-content` 覆盖）→ `read-content` 事实，凭据文件由既有凭据规则判定。
   - 纯监听（`nc -l 8080`）与普通连接（`nc host port`）不产生操作（放行，记缺口）。
4. **`ssh` 的隧道选项 → `unverified-effect` 候选；`ProxyCommand` 载荷按本地命令分析。** `ssh -R <spec>`（反向转发）、`-D <spec>`（SOCKS 代理）→ 已知范围候选（确认）。`ssh -o ProxyCommand=<value>` 的 value 作为本地命令文本交同域子单元分析（`nc %h %p` 这类普通代理命令放行，`bash -c "…"` 这类命中删除/执行事实）。`-L`（本地转发）与 `-J`/`ProxyJump`（跳板，参考项目都不拦、正常用法常见）放行并记缺口。远端命令/heredoc 的既有分析不受影响（多个事实可共存）。
5. **`scp`/`sftp` 的批处理。** `sftp -b <batchfile>` 或从 stdin 读批处理的 `sftp`（`-b -` / heredoc 喂入）→ `unverified-effect` 候选（批处理可能上传凭据或删除远端文件），范围含批处理文件名。`sftp host`（交互、无批处理）→ 缺口放行。**`-i` 身份文件不产生读事实**：身份文件是正常认证用途、不随传输外发（CSN 标准模式同样豁免），避免每次 `scp -i` 都触发凭据确认。

### C. 归档与分区交互

6. **归档内删除：`zip -d`、`tar --delete`、`7z d` 都是删除。** 归档内容不可逆丢失：产出 `delete` + `unknown` + 非空 `knownScope`（归档名 + 成员模式），确认 `data.delete.dynamic`。缺归档或成员 → 缺口放行。
7. **`parted` 交互式是设备写入入口。** `parted [options] <device>` 无写子命令（含 `printf … | parted <device>` 的 stdin 脚本）→ 设备变更：产出 `unverified-effect` 候选并附 `knownScope`（设备 + 交互/脚本输入）；设备路径可证时同时保留设备变更事实，按设备身份判定（`catastrophic.device`）。显式只读子命令（`print`/`p`/`unit`/`u`/`help`/`h`/`quit`/`q`/`select`/`version`/`free`/`align-check`）与 `-l/-m/-v/--version` 只读放行；无设备操作数 → 缺口放行。

### D. cmd.exe 控制流

8. **`cmd /c`、`cmd /k` 文本含控制流且命令位出现删除族时按范围确认。** 控制流记号：`for`/`if`（词边界）、`%VAR%`/`!VAR!`、`^`、`(`/`)` 分组、`start`、`call`。删除族（`del`/`erase`/`rd`/`rmdir`/`move`）**只在命令位**（段首、`do`/`else` 之后、`(`/`&`/`|` 之后）计入；`echo`/`rem`/`@echo` 的参数是数据，不参与删除族判定。命中时产出 `delete` + `unknown` + `knownScope`（限长原文）→ 确认 `data.delete.dynamic`；未命中 → 既有 `cmd-inline` 缺口。`/k` 与 `/c` 同路分析正文（裸 `/k` 交互无正文 → 缺口）。既有 `/s` 分支不变。

### E. 云与数据仓库长尾

9. **按 provider 薄表补齐长尾删除/不可逆变更，表驱动、确认档。** （命令形态可字面辨识才纳入，否则缺口）：
   - `aws`：`eks delete-cluster`、`glue delete-database/table/partition/crawler/job` 与 `glue batch-delete-table/batch-delete-partition`、`athena start-query-execution` 的字面 `DROP`/`TRUNCATE`/无 `WHERE` `DELETE`、`athena delete-data-catalog`、`redshift delete-cluster`、`kinesis delete-stream`、`cloudtrail delete-trail`、`logs delete-log-stream`、`s3api delete-object/delete-objects`、`s3 sync --delete`（远端目的地）、`ecr batch-delete-image`。
   - `gcloud`：`compute`/`sql`/`container` 等既有、`dataproc clusters delete`、`spanner instances delete`、`storage rm`/`storage objects delete`、`firestore databases delete`、`artifacts docker images delete`/`artifacts repositories delete`、`iam roles delete`、`dns managed-zones delete`、`bigtable instances delete`、`projects delete`。
   - `gsutil`：`rm`/`rb`（既有）。`azcopy remove`/`sync --delete`。
   - `az`：既有 `group/vm/sql/storage/keyvault delete` 等，加 `keyvault purge`、`account subscription cancel`、`account management-group delete`、`acr repository delete`、`ad app delete`/`ad sp delete`、`storage blob delete-batch`。
   - `kubectl`：`delete`（含 `--all`/`--all-namespaces`）、`apply --prune`、`apply --force`、`replace --force`、`drain --force`。
   - 容器编排：`docker compose down -v/--volumes` 与 `docker-compose down -v`（删 named volume）；不带 `-v` 放行。
   - `redis-cli`：`FLUSHALL`/`FLUSHDB`（既有）、`shutdown nosave`（数据丢失）；普通 `shutdown` 放行。
   - 数据仓库客户端：`supabase db reset`/`migration down`/`storage rm`、`databricks bundle destroy`/`fs rm`、`bq rm -r/-t` 与 `bq query` 的字面 `DROP`/`TRUNCATE`/无 `WHERE` `DELETE`、`snowsql -q` 的 `DROP`/`TRUNCATE`/无 `WHERE` `DELETE`（对象含 `warehouse`/`user`/`role`/`database`/`schema`/`table`）。
   - IaC/存储客户端：`pulumi stack rm`、`mc rb`/`mc rm -r`。
   - 未知/歧义形态一律缺口，不猜。
10. **不新增规则号。** 全部落在 `data.delete.dynamic`、`execution.dynamic-command`、`execution.unverified-effect`、`credential.file.read`、`catastrophic.device`、`catastrophic.git-metadata` 上。

## 不做

- 通用出网内容检查与隧道流量审计（只做第 3/4/5 条的可证入口）。
- `ssh -L`（本地转发）、`ssh -J`/`ProxyJump`（跳板，正常用法）、`telnet` 的交互载荷、`sftp` 的交互命令流（只做 `-b`）、`scp/sftp -i` 的读事实。
- `kubectl scale --replicas=0`（可用性破坏而非数据删除）、DNS/邮件/消息/CI-CD 等整类（命令形态不稳定，按缺口）。
- `zip` 除 `-d` 外的归档改写、`bsdtar` 的删除条目（无证据其支持）。
- `cmd` 控制流的逐条符号执行（只按命令位范围确认）。

## 后果

- `rm -rf <临时仓库>`（目录树含 `.git`）从「检查失败拒绝」变为「确认」，范围列出「`.git` 元数据将一并销毁」，正常清理可一次确认完成；以 `.git` 本身为目标的删除仍绝对拒绝。
- `git restore --staged .` 恢复为放行；`scp/sftp -i` 不再触发凭据确认。
- 隧道/反弹 shell/`sftp -b`/`parted` 交互/`zip -d`/`tar --delete`/`7z d`/`cmd` 控制流从「静默放行」变为确认（`nc -e` 等执行通道为 `execution.dynamic-command` 确认）；云与数据仓库长尾删除按 provider 确认。
- 普通用法零变化：`nc -l 8080`、`nc host port`、`socat - TCP:…`、`sftp host`、`ssh host ls`、`ssh -J bastion host`、`ssh -L 8080:localhost:80 host`、`scp -i … host:`、`parted -l`、`parted /dev/sda p`、`zip -r out.zip src/`、`tar -xzf`、`7z a`、`cmd /c dir`、`cmd /c echo %PATH%`、`aws s3 ls`、`kubectl get`、`docker compose down`（无 `-v`）、`redis-cli shutdown`（无 `nosave`）全部放行且无候选。

## 已知边界

- `printf 'p\n' | parted <device>` 在 POSIX 方言下与交互式 `parted <device>` 的 argv 相同（`shell.js` 只对 PowerShell 注入管道来源），仍按确认处理；显式 `parted <device> p` 放行。补齐需把管道来源传到 POSIX 分支。
- 被本决定改为确认的形态（含 `.git` 的目录清理、隧道、长尾删除）在无人值守会话里仍需一次用户确认；这是防御本身，不是失败。
