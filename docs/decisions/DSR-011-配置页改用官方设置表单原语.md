# DSR-011：配置页改用官方设置表单原语，拆掉自绘卡片壳

> 状态：**已落地，静态门禁全绿**（2026-09-28）。`npm run check` 退出 0：`node --check`（9 个文件）+ `node --test` **145/145**（较原 133 增 12）；`verify/run-verify.mjs` 8/8 全绿（含 test profile 启动冒烟存活 ≥30s 且无错误标记）。`card.js` 574 → 415 行。
> ⚠ **实例级页面走查未做**（红线：实例启停由用户执行）——见文末「尚未验证」。

## 上下文

插件在 0.1.7 换代（基线与 peer 抬到 `^0.1.7-rc.2`）时已改对**接线**，但配置页外观与交互仍是**自绘**：`src/client/card.js` 是 574 行单文件，自带一套折叠卡外壳——`CardHeader`（`button.header` + 标题「规则开关」+ 摘要 + 折叠箭头）、`Chevron`（图标或 `▾`/`▸` 回落）、`dirtyPillStyle`（「未保存」徽标）、footer 的「放弃」按钮——外加自写的草稿状态机（`draft`/`busy`/`failed`/`hoverDiscard`/`focusEl`），并在 Save 时自己拼 `mutate(ops)`。

用户比对时指出：**官方页面没有这层卡片壳**。核查证实（源码取证，非文档转述）：

- `packages/client/ui-settings-shell/src/client/ShellCard.tsx` 全文 **55 行**，结构只有
  `<SettingsForm labels state onSave onDiscard>` + 两个 `SettingsValueField` — **无 header、无折叠、无「放弃」、无「未保存」标记**。行标题/图标/面包屑全由 Plugins 页自绘（`PluginManagerPage.tsx:491-495`）。
- `SettingsForm.tsx` 的模块注释原文：*"discards on unmount and offers no discard control"* — 官范式里**没有**放弃控件；`onDiscard` 由 `useEffect` 在卸载时调用（`:54`）。
- 姊妹插件 `dsh-skill-manager` 已在 2026-09-28 完成同一次对齐（其 DSR-026），guardrails 当时只做了接口适配、没做视觉对齐 ⇒ 本次补上。

## 真实方向与评价

- **A（只拆外壳）**：去掉折叠卡/箭头/未保存/放弃，换成裸 `SettingsForm`，保留自写草稿状态机与 `mutate` 调用。改动小、风险低，但同一套草稿逻辑在两个插件里各写一份，且 revision 围栏、保存后回读、离开页面丢弃三件事都靠自己维护。
- **B（完整对齐：拆外壳 + 换官方表单模型）**：草稿暂存、revision 围栏、保存后回读、离开页面丢弃全部交给官方 `SettingsFormModel`；本插件只留「字段规格 + 自绘布尔控件 + 快照投影」。
- **C（不动）**：接受与官方页面长期分叉；官方每改一次表单材料都要手工跟一次。

## 最终决定（B，用户裁定"a+b 完整对齐"）

1. **表单框架换成官方 `SettingsForm`**：删除 `CardHeader`/`Chevron`/`dirtyPill`/footer（含「放弃」与「全部重置」按钮）/`cardShell`/`bodyStyle`/`headerStyle` 与 `hoverDiscard`/`focusEl`/`open` 等自绘交互态。
   - **「全部重置」一并删除**：它是自绘 footer 的产物，官方表单只提供 per-field 重置（`SettingsValueField` 的 `overridden` + `resetLabel`）。逐项重置的能力保留在每行右侧。
2. **草稿与写入交给官方 `SettingsFormModel`**（新增 `createController`，形态逐段镜像官方 `ShellCardController`）：`new SettingsFormModel(scope, SPECS)` → `bind(projection)` → `inject()` 返回 `{ hooks: { guardrailForm }, ...actions() }`。
   - `hooks` 是注入面的**保留键**，渲染器把成员拆成 `use<成员名>` selector hook；页面下发的 `form` prop 是一次性快照，不能用于重渲染（此契约原样保留）。
   - 模型随本 fiber 释放（`ctx.effect(() => () => form.dispose())`）。
3. **结构化字段用「文本承载 + 规格互转」骑上官方模型**：官方字段原语只有 text（`SettingsValueField`）与 write-only secret（`SettingsSecretField`），spec 助手也只有 `settingsNumberField`/`settingsTextField` —— **没有布尔控件**。故：
   - 每个 category 是官方模型里的**一个字段**，其草稿文本是该 leaf 对象的**规范序列化**：全开 = `'true'`、全关 = `'false'`、混合 = leaf JSON（`{"read":false,"modify":true}`）。
   - `parse` 只接受这三种，且**镜像 Host 的校验**（`src/core/rules.js` 的 `evaluateCategory` 同样拒未知键与非布尔 leaf）——本地就把 Host 一定会拒的草稿标为 `invalid`，而不是让保存跨网才失败。
   - 均匀 leaf 集**归一为布尔**（v1 兼容形态）；`system` 只有一个 leaf，故它天然只存布尔。
   - 自绘控件用**官方 `Checkbox`** 与官方 `Tag`（覆盖徽标），勾选只 `edit(field, text)` 暂存，保存才落 —— 与同页文本字段同一套语义。
4. **token 与几何归位**：色值只用 `--dsw-alias-*`；**字面量半径清零**（原 `borderRadius: 12`/`8` → `--dsw-radius-md`/`sm`）。整圆徽章用官方 `Tag` 承担，不再保留自写字面量 `999`。

## 直接后果

- `card.js` **574 → 415 行**，自绘外壳与草稿状态机整体消失；代码里（剥离注释后）已无 `Chevron`/`cardShell`/`headerStyle`/`dirtyPill`/`hoverDiscard`/`setDraft`，也不再直接调 `form.mutate`/`form.unset`。
- 字面量半径 0 处、`rgba(` 0 处，`var(--dsw-*` 12 处。
- 新增回归闸 **12 项**：
  - `test/client-wiring.test.mjs`：假 ctx/假 React 之外，新增一个**迷你渲染器**（`expand` 解函数组件）+ 假 `SettingsFormModel`（记录 specs 与动作），据此断言「body 是官方 `SettingsForm`」「无放弃控件/未保存标记」「每 leaf 一个官方 `Checkbox`（2+2+3+1+8+1）」「模型绑定到本行 `ConfigForm` 且随 fiber dispose」，以及一条**代码级契约**（自绘外壳名与自写 `mutate`/`unset` 必须不再出现）。
  - `test/config-page.test.mjs`（新文件）：字段规格与 Host 的**漂移守卫** —— 页编辑的字段集必须等于 `RULE_KEYS`、每个 category 的 leaf 集必须等于 `CATEGORY_LEAF_KEYS`（用 spec 的 `parse` 行为逐键探测，因为 CATEGORIES 在闭包里不外export）、`format∘parse` 对每种接受形态稳定、且本地拒绝 Host 会拒的草稿。

## 四条消融（均确认有判别力）

| # | 消融 | 结果 |
| --- | --- | --- |
| ① | 把裸 `SettingsForm` 换回自绘 `div`+「放弃」 | ✖「body 必须是官方 SettingsForm」 |
| ② | 删掉非布尔 leaf 的校验 | ✖「env spec 必须拒绝 `{"read":"yes"}`」 |
| ③ | 给 `system` 多加一个 leaf | ✖「category system 的 leaf 与 rules.js 漂移」 |
| ④ | 把 `dirtyPill` 加回代码 | ✖「未保存徽标必须已从代码中消失」 |

**②是真实缺陷**：初版 `parseCategory` 的 `toLeaves` 会把 `{"read":"yes"}` 静默强制成 `true`，即接受一份 Host 必然拒绝的草稿 —— 由新测试当场抓出并修掉。

## 尚未验证（如实登记）

- **实例级页面走查未做**：未在浏览器里看过配置页。以下属**读源码 + 单测推断**：官方 `Checkbox`/`Tag` 在本页布局下的实际观感（尤其每行右侧 leaf 网格与「已覆盖/重置」徽标并排时的换行与垂直对齐）；删掉折叠外壳后页面纵向长度（16 个开关 + 5 行提示 + 1 条脚注）是否可接受；「离开本页丢弃草稿」在真页面上的用户可感知性。
- **未跑真 `SettingsFormModel`**：测试用假模型捕获 specs 与动作，**未**真的驱动官方 `plan()`/`save()`/`revision` 围栏（避免为测试把官方客户端包拉进 devDependencies）。⇒「一次原子 mutate 写入全部脏字段」这条来自读 `form-model.ts:300-320`（`plan()` 一次性收集、单次 `scope.mutate(ops, revision)`），未在运行中观察。
- **`--check` 类的构建闸不适用**：本插件无构建器（`card.js` 即产物，`package.json` 无 build 脚本、无 `dist/`），故「产物新鲜度」这一层不存在；代价是**没有编译期检查**，语法靠 `node --check` + 本次新增的代码级契约断言兜。
- **`verify/run-verify.mjs` 的 2 项失败属环境问题，非本次回归**：其默认 `DSH_HOME=~/.dsh` 且回落到 nvm4w 的 **0.1.1-rc.2** DSH（本机实际目标为 0.1.7-rc.2），故「test 恰一行」读到 0 行、「test profile 启动冒烟」因该 HOME 无此 profile 立即退出。改用 `DSH_HOME`/`DSH_TEST_HOME`/`DSH_WEB_HOME`/`DSH_BIN` 指向 test 实例与 0.1.7-rc.2 后 **8/8 全绿**（含启动冒烟）。该脚本的默认值需要修，已登记 `docs/TODO.md`。

## 重访条件

- 官方为布尔字段补 spec 助手或字段控件 → `boolSpec` 与自绘 `Checkbox` 可撤，直接换官方控件；category 的文本承载仍可保留（结构化值本就需要一层转换）。
- 官方在 `SettingsForm` 里给「操作级失败」或「拒绝原因」一个呈现位 → 本插件可去掉自定义的 `saveFailed` 文案补语。
- 官方公开半径/阴影 token 的**枚举表**（现只有 CSS 变量）→ `R` 可改成从平台读取而不是本插件抄一份。
