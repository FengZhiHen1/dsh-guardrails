# DSR-013：`.ssh/config` 安全例外与 SSH 别名引导

## 上下文

`.ssh` 是凭据目录段，DSR-002 采纳**严格策略**——凭据目录的读、写、列举全拦，理由是"文件存在性本身敏感"。该策略把 `.ssh` 下的**一切**文件都当作密钥物质，其中包含 `~/.ssh/config`。

`~/.ssh/config` 是 `Host` 别名到主机/用户/密钥文件的路由表，**不含任何密钥材料**（私钥实体在 `*.pem`）。把它一并拦住产生两个实际后果：

1. **把"用别名"这条正路堵死了**。密钥不应被 Agent 持有；推荐的用法是 `ssh <别名>`，而别名清单只能从 config 获得。拦住 config ⇒ 别名只能靠人肉告知，或写进 AGENTS.md 并随之漂移；`glob ~/.ssh` 也被拦，连自行发现都不可能。
2. **拦截语义与防护目标错位**。守卫实际守的是"密钥物质"（防读取/外带），而不是"密钥使用"——`ssh <别名>` 用着私钥却放行，`ssh -i key.pem` 才被拦。既然如此，config 这种纯路由信息没有理由按密钥对待。

同时，凭据拒绝文案只说"让用户手工处理"，没有告诉调用方**在 SSH 场景下应该怎么做**——拒绝之后没有可行替代路径，容易诱导绕过尝试。

## 真实方向与评价

- 方向 A：仅改拒绝文案，规则不动。最便宜，但 config 仍不可读，"提示优先查 config"是**不可执行的建议**（指向一个会被同一守卫拦住的路径），等于自我矛盾。
- 方向 B：把 `.ssh` 整个目录从凭据段移出，改为文件级名单（只拦 `id_*`/`*.pem`）。改动大且**明显放松**：`known_hosts`（基础设施拓扑）、`.ssh` 下任意非标准命名的密钥都会放行；列举也不再敏感。
- 方向 C：**按目录的最小安全例外**——只豁免 `.ssh` 下**文件名恰为 `config`** 的那一个文件，其余（含 `known_hosts`、`*.pem`、`config.bak`、子目录、目录列举）全部维持拦截。外加 SSH 别名引导文案。

评价：C 把"非敏感内容可读"精确到一个已知文件名，放松面最小且可枚举。A 缺少可达的替代路径；B 的放松面不可枚举（"`.ssh` 下不是密钥的东西"没有闭集）。

## 最终决定

采用方向 C。DSR-002 的严格策略**整体维持**，仅对 `.ssh/config` 开一个具名例外：

- 新增 `SAFE_CRED_DIR_FILES`（`rules.js`）：**按凭据目录段**声明该目录下可豁免的文件名。键是目录段、值是豁免文件名集合。当前唯一条目 = `{ '.ssh': { config } }`。
- 例外**仅对直接父目录生效**：`~/.ssh/config` 放行，`~/.ssh/sub/config` 仍拦。
- 目录段规则与命令文本正则**同源派生**（`CRED_DIR_PATTERN` 由 `CRED_DIR_SEGMENTS` + `SAFE_CRED_DIR_FILES` 生成），保持 DSR-004 的单一维护点。
- `.kube/config` **不豁免**——它是真正的持有者令牌/证书存储；例外按目录而非按文件名，正是为了避免"凡是 config 都放行"这类泛化。

## 直接后果

- 路径通道：`read ~/.ssh/config` 由拦改为放行；`.ssh/id_rsa`、`.ssh/known_hosts`、`.ssh/config.bak`、`.ssh/sub/config`、`glob ~/.ssh` 维持拦截。
- 命令文本通道：`Get-Content ~/.ssh/config` 放行；`.ssh` 其他引用与 `ssh -i ~/.ssh/*.pem` 维持拦截（`.ssh` 段仍命中，`config` 负向断言不成立）。
- 拒绝文案新增 SSH 别名引导：改用 `~/.ssh/config` 中的 `Host` 别名（`ssh <别名>`），用 `ssh -G <别名>` 查生效的主机/用户/密钥，不要读密钥文件、不要用 `-i` 拼路径。
- 自洽性副作用（正向）：拒绝文案本身提到 `~/.ssh/config`，而该引用在文本通道**不再被拦**——不会复现 DSR-010 那类"引用守卫自己的拒绝原文反被拦"的误伤。

## 已知缺口（本次不修，记录在案）

命令文本通道的凭据正则只覆盖文件名/目录段/相邻组合，**不含 `.pem` 等私钥后缀**。故 `ssh -i C:/keys/x.pem ubuntu@host`（密钥不在 `.ssh` 目录下时）在 pwsh 通道**不命中**；路径通道（read 等）仍会拦。这是 DSR-013 之前即存在的缺口，本次未扩展后缀文本匹配——避免把"开一个具名例外"扩大成"重做文本引用名单"。若需闭合，应作为独立决策处理。

## 重访条件

- 若 SSH 配置改为目录式包含（`~/.ssh/config.d/*`）并成为实际用法，需评估是否把豁免扩为"该目录下的具名文件集"。
- 若出现"`.ssh` 下的非密钥文件也必须可读"的成规模需求，重新评估是否转为文件级名单（方向 B），并重估 `known_hosts` 的敏感性。
- 若 Agent 侧出现绕过倾向（改用 `-i` 拼路径、复制密钥到工作区），说明别名引导不足，须加强文案或收窄例外。
