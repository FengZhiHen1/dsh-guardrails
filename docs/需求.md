# dsh-guardrails 需求

## 权威范围

本文唯一拥有 `dsh-guardrails` 的目标、用户、场景、功能范围、需求约束、非目标与验收语义。技术机制归 `technical-details/`，选型理由归 `decisions/`。本文不指定实现模块或目录。

## 结论先行

- 目标：在 DSH 的 AI 工具调用管线上做**技术性硬阻断**（不弹确认框），防止 AI 侧读取凭据与隐私、篡改仓库内部、写入系统区、执行破坏性命令；用户自己的命令不受影响。
- 已确认结论：范围边界为参考文档 `references/coding-agent-file-access-security-boundaries.md` 的 **R0 文件系统子集 + W0 系统区写禁**；P1 审批区与非文件入口不纳入（DSR-001）。拦截模型为**敏感类别 × 操作类型**矩阵（DSR-002）；凭据目录连列举都拦（严格）；混合目录按文件级规则（DSR-003，已重访：sessions 类别移除）；名单硬编码（DSR-004）；系统区读放行、只拦写（DSR-005）；防御层全量配置化已实现（DSR-006，v1.1.0，R-03 为 v2 验收）。
- 实现状态：**v1.0.0 已实现**——五类规则、R0 范围 B 补漏、W0 系统区写拦、配置校验与工程化结构（`lib/` 四模块、四层测试、`verify` 全量脚本）；**v1.1.0 已实现**——防御层全量配置化（叶子级，DSR-006）。规则矩阵 98 例全绿（行覆盖 97.07%，门禁 ≥80%）。
- 下一重点：先读范围与约束，再读验收条件。

## 背景与问题

DSH 的 AI 工具（read / write / edit / grep / glob / pwsh）执行时，文件沙箱约束的是"工作区范围"，approval 机制约束的是"需确认的操作"；二者都不覆盖"工作区内外的高危敏感面"——凭据文件、仓库内部结构、系统区与破坏性命令。AI 一旦拿到这些内容，等于把用户凭据交给模型处理；破坏性命令则会摧毁本地工作或系统状态。guardrails 作为工具管线内的语义防护层，在调用执行前同步判定并硬阻断。

## 用户与场景

- 主要用户：本机 DSH 用户（web / test 两个 profile）。
- 防护场景一（读取侧）：AI 试图读取 `.env`、SSH 私钥、云凭据、`.git` 内部、浏览器资料、Windows 凭据目录时被硬阻断。
- 防护场景二（写入侧）：AI 试图修改 `.env`、`.git` 内部、系统区（`C:\Windows` 等）时被硬阻断。
- 防护场景三（命令侧）：AI 在 pwsh 中执行 `rm -rf`、`git reset --hard`、机器级命令、`Get-ChildItem | Remove-Item` 等被硬阻断。
- 放行场景：AI 列举 `.dsh` 目录、查看 `.git` 目录结构、读取系统区公开文件等无害操作不被误伤。

## 范围与功能需求

- R-01 插件形态：以真实插件包交付，声明 `dsh.bundle.patch`，随包携带 `cordis.patch.yml` 安装层；Host 进程持久挂载，跨会话与重启存在。验收：profile `--dump-config` 出现且仅出现一行 `guardrails`（id）/`dsh-guardrails`（name）。
- R-02 硬阻断语义：对 AI 工具调用（read / write / edit / read_image / grep / glob / pwsh）返回拒绝原因，不进入确认流程；用户自己的命令不经工具管线，不受拦截。验收：工具调用被拒时返回以 `[guardrails] Blocked` 开头的可读原因。
- R-03 规则类别与防御层配置（v2，DSR-006，v1.1.0/v1.2.0 已实现）：五类别（env / git / credentials / destructive / system）+ 动态目标 fail-safe（unverifiable）全部配置化；类别键接受布尔（= 整类开/关）或对象（= 按操作/子族细分，子键缺省继承 true），缺省全开。操作级叶子：`env: { read, modify }`、`git: { read, modify }`、`credentials: { read, modify, list }`、`system: { write }`；`destructive: { git, machine, eval, cli, bulk, target }`（六子族分组见 R-07）；`unverifiable: true`（动态 `$()` 目标 fail-safe）。**配置入口按 DSH 官方范式（0.1.1）**：插件导出 Schemastery `Config` schema，loader 在 `apply` 前验证并填充默认值（`ValidationError` 挂载即失败）；未知键/未知子键由 `evaluateRules` 拒绝。`.dsh` 目录（含会话历史）不属于敏感类别（DSR-003 重访注记）。v1 五键布尔写法继续有效（等价于对应类别全开/全关）。验收：每叶子/子键置 `false` 后对应防御层放行，其余不受影响；非法配置挂载即失败。
- R-04 操作类型分级：内容访问（读内容/写/删）套全规则；元数据列举（glob、列举类命令）只套凭据目标；未识别命令保持全规则。验收：`Get-ChildItem .dsh` 放行、`Get-Content .dsh/sessions/...` 放行（`.dsh` 无敏感规则）、`Get-ChildItem .ssh` 拦截。
- R-05 credentials 清单（R0，读/写/列全拦）：私钥与令牌文件名（`id_rsa` 系列、`.npmrc`、`.pypirc`、`.netrc`、`.pgpass`、`.credentials.yaml`、`.auteur-media-secret`、`.git-credentials`）、私钥后缀（`.pem`/`.key`/`.p12`/`.pfx`/`.ppk`）、凭据目录段（`.ssh`/`.aws`/`.azure`/`.gnupg`/`.kube`/`.pki`）、相邻段组合（`.config/gcloud`、`.docker/config.json`）、浏览器资料目录（`Chrome User Data` 等）、Windows 凭据/DPAPI 目录（`Microsoft\Credentials`、`Microsoft\Protect`）、用户注册表 Hive（`NTUSER.DAT`、`UsrClass.dat`）、系统 Hive（`System32\config\SAM`/`SECURITY`/`SYSTEM`）、内存与转储（`pagefile.sys`、`hiberfil.sys`）。公钥（`*.pub`）与安全 `.env` 后缀（example/sample/template/dist/default）不拦截。验收：上述每类至少一个拦截用例，`.pub` 与 `.env.example` 各一个放行用例。
- R-06 system（W0，只拦写）：写入系统区路径被拦——`C:\Windows\**`（含 `System32`、drivers、Tasks）、`C:\Program Files\**`、`C:\Program Files (x86)\**`、`C:\ProgramData\**`、EFI/Recovery 分区、用户启动目录与 PowerShell Profile、系统 Hosts、证书与计划任务目录；读取与列举系统区放行。验收：write/edit 与写类命令指向系统区被拦，read/grep/glob 与列举类命令指向系统区放行。
- R-07 破坏性命令（命令文本静态分析；子族分组——`machine`=机器级/进程/清空，`eval`=远程内容执行/.NET 直接 API，`cli`=文件磁盘/基础设施云/数据库，`bulk`=管道删除，`git`=git 高危，`target`=删除目标分析，见 [命令文本分析.md](technical-details/命令文本分析.md) 与 DSR-006）：机器级（重启/关机/磁盘/账户）、清空（`Clear-Content`、`Set-Content $null`）、管道删除（`Get-ChildItem | Remove-Item`，含与不含 `-Recurse`）、`git` 高危子命令（`reset --hard`、`clean -f`、强推、删远端 ref、强删分支、`stash drop/clear`、`checkout .`）、远程内容执行（`iex`、管道进 shell、`curl | bash`）、`.NET` 直接数据 API、`shred`/`find -delete`/`dd`/`mkfs`/`truncate`/`docker system prune`/`terraform destroy`/`kubectl delete`/`aws s3 rm --recursive`/数据库 CLI 破坏操作。验收：每类至少一个拦截用例，`git status`/`git log` 等安全子命令放行。
- R-08 命令文本列举模式：整条命令所有片段首命令均为元数据动词（`Get-ChildItem`/`gci`/`ls`/`dir`/`Get-Item`/`Test-Path`/`Resolve-Path`/`Get-Location`/`Split-Path`/`Join-Path` 等），且无 `$()` 子表达式、无重定向（`>`）时，只查凭据目标；否则走全规则。验收：`Get-ChildItem .dsh > .env` 被拦（重定向保持全规则），`Get-ChildItem .dsh; Get-Content .env` 被拦（混合命令保持全规则）。
- R-09 fail 语义：规则判定对无法分类的命令采取 fail-closed（全规则）；guard 钩子内部异常采取 fail-open（记录日志、放行），防止防护 bug 死锁会话。验收：未知命令提及凭据目标被拦；人为注入的钩子异常被记录且不阻断会话。
- R-10 性能约束：guard 为同步钩子，纯静态分析，不 spawn 进程、不触碰 fs 服务；单次判定时间复杂度与命令文本/路径长度线性相关。验收：代码审查确认无异步 I/O 与子进程；规则矩阵测试整体毫秒级完成。
- R-11 测试体系：四层测试——单元（直接 import `lib/*` 测规则/词法/破坏性分支）、集成（mock ctx 驱动 guard 钩子全矩阵）、组合（`--dump-config` 断言 test/web 各恰一行、web 依赖为发布物形态、无重复）、名单驱动（遍历 `rules.js` 数据表生成正反用例）；覆盖率报告 + 行覆盖门禁 ≥ 80% 起步。验收：`npm test` 全绿；`node --test --experimental-test-coverage` 输出覆盖摘要；新增名单项无需手工补用例（名单驱动自动覆盖）。
- R-12 部署红线：test profile 源码直挂（`link:` 依赖，符号链接实时可见，重启加载）；web profile 只吃发布物（registry 版本 / 打包 tarball / `github:` 钉 ref），禁止任何指向源码目录的 `link:`/`file:`/junction/symlink 与源码路径 patch 行；任一 profile 禁止 bundle 层与用户 patch 层重复 insert 同一行。验收：test 的 `--dump-config` 恰一行且解析自 `dsh-guardrails` 包；web 的 `--dump-config` 恰一行且依赖为发布物形态，无源码依赖残留；两 profile 均无重复行。
- R-13 源码结构：`index.js` 薄入口（config 开关、guard 钩子装配、deny 消息、fail-open 容错）+ `lib/` 四模块（`rules` 名单数据、`path-check` 路径规则、`command` 命令文本、`destructive` 破坏性分析）；依赖方向单向，`lib/rules.js` 为名单与文本正则唯一维护点。验收：代码审查确认模块边界与依赖方向符合 `工程结构与测试体系.md`，任何名单变更只改 `rules.js`。
- R-14 验证脚本：`verify/run-verify.mjs` 一键全量——单测+集成 → 覆盖率摘要 → composition 断言（`--dump-config`）；冒烟（重启 test profile 后真实拦截行为）为手动步骤。验收：`npm run verify` 一次执行全部自动化检查并输出汇总。

## 约束

- C-01 纯静态分析：不得 spawn 进程、不得调用 fs 服务、不得访问网络；所有判定基于调用参数与命令文本。
- C-02 同步性：guard 钩子必须同步返回，不得引入异步等待。
- C-03 路径判定基于解析后路径：大小写不敏感、分隔符归一、`..` 折叠；不展开环境变量与 `~`（命令文本层用文本引用兜底）。
- C-04 名单硬编码：v1 不提供自定义名单配置，仅提供 R-03 的防御层开关（v2 为叶子级，见 DSR-006）；新增敏感目标通过代码变更交付。
- C-05 运行环境为 Windows；Linux/macOS 敏感清单与 `reg` 注册表类操作不纳入 v1，重访条件见 DSR-001。
- C-06 不拦截用户命令：拦截面严格限定在 AI 工具调用管线。
- C-07 deny 消息必须包含可执行指引（如"改用 git 命令""请用户手工处理"），帮助 AI 与用户理解替代路径。

## 非目标

- 不拦截 P1 审批区（`AGENTS.md`、`.github/workflows/**`、IaC、迁移、发布配置等）——由 DSH approval 机制承担逐项审批；guardrails 硬阻断会使其"永不修改"，语义不符。
- 不覆盖非文件入口（环境变量、命令行参数泄露、网络端点、剪贴板、进程内存、Socket、MCP/插件权限）——不在工具管线能力内。
- 不做凭据内容检测（文件内容熵检测、Secret 扫描）——只做路径/文件名判定。
- 不解析符号链接/Junction 的真实目标路径——现状为纯段运算，链接越界防护标记为已知限制。
- 不拦截注册表类命令文本（`reg`、`HKCU:` 等）与系统区之外的账户/权限放宽操作（`chmod`/`chown`/ACL 间接提权）。
- 不发布 npm、不为多机器设计安装器（发布流程见 部署.md，未到发布时机）。

## 验收条件

- AC-01 组合验证：test 与 web profile `--dump-config` 各恰一行 `id: guardrails / name: dsh-guardrails`，web 依赖为发布物形态（registry 或打包 tarball，非源码直挂）；两 profile 均无重复行。
- AC-02 规则矩阵：`npm test`（`node --test test/`）全绿，覆盖 R-04/R-05/R-07/R-08 的全部正反用例与 R-03 全部开关。
- AC-03 误伤消除：`Get-ChildItem .dsh`、`ls ~/.dsh`、`Test-Path .dsh`、列 `.git`、列 `.env`、glob `.dsh/**` 全部放行。
- AC-04 防护保持：读 `.env`/`.git/config`/`~/.ssh/id_rsa`、`rm -rf .`、`Get-ChildItem .dsh | Remove-Item`、重定向写 `.env` 全部拦截；对 `.dsh` 目录（含会话历史）的读/写不拦截。
- AC-05 R0 补漏：`.git-credentials`、浏览器资料、DPAPI 目录、`NTUSER.DAT`、`pagefile.sys`、`SAM` 各有一个读拦截用例；`.pub`、`.env.example` 放行。
- AC-06 W0 系统区：write/edit 指向 `C:\Windows\**` 与 `C:\Program Files\**` 被拦；read/grep/glob 指向同路径放行；写类命令文本提及系统区被拦。
- AC-07 配置开关：`credentials: false` 后凭据放行且其余类别不受影响；叶子级开关（DSR-006）——`env: { read: false }` 后 .env 读放行、写仍拦，`destructive: { cli: false }` 后 CLI 数据工具放行、机器级仍拦；`sessions` 键已移除（传入即挂载失败，见 DSR-003 重访注记）。
- AC-08 性能：测试套件总时长毫秒级；代码审查确认无异步 I/O、无子进程、无 fs 调用。
- AC-09 部署生效：test profile 重启后新规则生效（符号链接直挂）；改动后 `--dump-config` 复查无重复行、无源码解析残留。

## missing evidence 与延期项

- `missing evidence`：符号链接/Junction 真实路径解析行为（是否需在 v1 解析真实目标）；`reg`/`HKCU:` 命令文本的误伤面；跨平台清单（Linux/macOS）的优先级。
- 延期：P1 审批区拦截、非文件入口、内容检测、注册表类命令、符号链接解析、跨平台清单；重访条件在对应决策记录中定义。
- 假设：运行环境保持 Windows；DSH 工具管线与 guard 钩子契约不变化；`.dsh` 目录（含 `sessions/`）不属于敏感类别（用户决策，见 DSR-003 重访注记）。
