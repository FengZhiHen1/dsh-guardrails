# dsh-guardrails 需求

## 目标与范围

在 DSH Full Access 的受管 AI 工具调用中降低意外泄密和高后果破坏风险，以少量可解释的 Deny、必要的限时 Ask 和正常 Allow 支持日常开发。不依赖 Auto Review 做安全语义判定；用户手工命令不受本插件拦截。自 v4 起插件只防**灾难性删除**（不声称覆盖所有删除），分三级：**L1 直接拒绝**（物理设备/卷目标、宿主系统树、`.git` 元数据、销毁 git 历史的子命令）；**L2 计数**（可识别的命令行删除，≤20 放行、>20 拒绝）；**L3 其余放行**。源码与隔离 Runtime 验证通过，详见[验证记录](verification/2026-11-14-delete-gate.md)；live 激活已在验收环境复验，UI 显示、稳定环境部署与 Linux/跨平台实跑尚未完成。

## 灾难性删除标准（L1 / L2 / L3）

- **L1 直接拒绝（灾难性）**：物理设备/卷销毁（`\\.\PhysicalDrive*`、`format`、`mkfs.*`、`diskpart`、`dd`、`fdisk`、`parted`、`wipefs`、`shred`、`cipher /w`、`vssadmin delete`、`wbadmin delete`）；宿主系统树整树破坏；`.git` 元数据路径；销毁 git 历史的 git 子命令（见 R-15）。
- **L2 计数**：可识别的命令行删除——包括工作区之外的目标和 `move` 的源删除——枚举目标并计数；≤20 放行、>20 拒绝。工作区之外不因“在边界外”本身拒绝，同样只按 20 门禁处理（系统树/设备/.git 的 L1 除外）。
- **L3 放行**：其余一切，包括未建模程序、常规 git 操作、全部 `plugin_manager` 动作、`create_worktree`、`terminal_open`、`copy`。
- **保持诚实的边界**：目的是执行任意命令文本的通道（无法分析的 shell 脚本、动态命令文本、`env/xargs/sudo/start/source`、WSL 包装）在无法分析时拒绝；`run_code` 仍拒绝；灾难模式（`.git`/provider/设备）即使程序名未知也拒绝。

## 功能需求

| ID | 已确认需求 | 可观察验收 |
|---|---|---|
| R-01 | 以可安装 DSH bundle 交付，Profile 持久配置 | 目标组合唯一有效插件行，包导入与激活实测通过 |
| R-02 | `Deny > Ask > Allow`；Deny 区分绝对与纠正型 | 拒绝给出证据、目标、原因与可行下一步；审批不能覆盖 Deny |
| R-03 | 只绝对禁止高置信真实宿主块设备底层灾难破坏、宿主 OS 根/核心结构整体毁坏、真实 Git common-dir 主体整体破坏 | 镜像文件、普通数据卷、HOME、项目根、Linked Worktree `.git` 指针不因词面被同等禁止 |
| R-04 | 对 Profile 精确文件与内置敏感文件名单的直接内容读、导出/复制、写、清空、删、移走单次限时 Ask | 批准只放行当前调用；元数据与正常间接认证不因此审批 |
| R-05 | 普通未标记 `.env` 不自动保护；标记归 Profile，不信任工作树自声明 | 标记目标命中，相邻文件/目录与模板不因名称误伤 |
| R-06 | 正常非强制 `git worktree remove` Allow，由 Git 自身检查 | 仅高置信确认待删树内实际存在受保护文件时因该内容删除升级 Ask |
| R-07 | **L2 计数**：可识别的命令行删除（含工作区之外的目标、`move` 的源删除）统计未命中白名单的常规文件 + 链接条目，目录去重单独报告；`<=20` 完整枚举，`>20` 硬拒绝（可早停「至少 21」；`DEL-01`/`DEL-14`）并要求核实预期、分批删除 | 计数可靠；超限拒绝；不声称精确总数或并发原子 |
| R-08 | 纠正型 Deny 需可靠操作证据、高后果机制、任务可达的安全替代同时成立 | 命令关键词、目录名或文件数量不能单独替代可靠操作证据 |
| R-09 | Guardrails 自有审批有有限等待；`never`、拒绝、超时、取消、不可用均不执行；审批不等于删除授权，审批后重新计数 | 无迟到批准复活；重复调用重新审批；拒绝仍受数量门禁与未知拒绝约束 |
| R-10 | 高置信真实凭据的受管工具结果默认完整遮罩 | 不显示凭据前后缀，不因打码增 Ask；保持非秘密诊断与成功/失败语义 |
| R-11 | 高置信直接内联真实凭据且有扩散风险和可行替代时纠正型 Deny | 变量引用、占位符、示例和正常间接认证不因关键词拒绝 |
| R-12 | 支持 Windows/Linux 对应受管 Shell，并在检查服务不可用时安全拒绝 | 分平台验证故障/协议/身份缺失；解析层只报告动态 Unknown，adapter 无法解析的**执行语义**仍拒绝；未知**程序名**不再拒绝（L3 放行） |
| R-13 | **L3 放行与执行通道**：未建模程序（`Test-Path`/`Copy-Item`/`New-Item`/`whoami` 等）、`copy`、`create_worktree`、`terminal_open`、全部 `plugin_manager` 动作放行；语言运行时脚本（node/python/perl/ruby/php/deno/bun/uv）放行（内联代码开关仍拒绝）；shell 脚本文件在可证明时分析并计数；执行通道（无法分析的 shell 脚本、动态命令文本、WSL、`run_code`）仍拒绝；`terminal_send` 就地按平台方言分析，无法分析则拒绝 | 返回英文拒绝并要求更清晰、受支持的命令；已审查协调类 `tools` 走 allow-list；所有删除拒绝附带统一强提示 |
| R-14 | 文件级白名单：Python 字节码、pytest、mypy、Maven class、TS buildinfo；命中须「形态匹配 + 证据证明」双通过才减计数；Cargo 取消自动豁免（仅边界 marker） | 命中只减计数不减保护；伪装/未知条目照常计数；受保护文件与绝对 Deny 始终生效 |
| R-15 | **git 分级**：`git` 由 `assessGit` 分类，销毁历史的子命令（`stash clear/drop`、`gc --prune=now`、`filter-branch`、`filter-repo`、`push --force/-f/--delete/--mirror`、无路径 `reset --hard`、`reflog expire --expire=now --all`）立即拒绝（`DI-GIT-REFUSE`）；`clean`/`restore <paths>`/`worktree remove <path>` 经 `git-evidence` 计数（`DEL-GIT-*`），证据不可用 fail-closed；git allow 命令不进入通用文件扫描 | 常规 git 放行；销毁历史拒绝带强提示；>20/工作树不干净拒绝；证据缺失拒绝而非放行 |

## 约束与非目标

只对进入 DSH `ctx.tools` 的调用承诺防护，不提供 OS 沙箱或抗同身份对抗隔离。`run_code` 一律拒绝；`terminal_send` 的文本就地按平台方言分析、无法分析则拒绝。真正边界是「不经 `ctx.tools` 直接调用 runtime service」，该直连路径不在覆盖内。外部脚本内部、远端/容器后续操作、云 SDK 与内嵌 SQL 等不能借 Shell AST 宣称完整覆盖。

不新增 Trusted Disposable Scope、用户可配置清理目录 Profile 白名单、构建目录注册表、全盘秘密扫描、外部 DLP 或自动 `.env` 迁移。内置删除白名单是固定的文件级规则（形态匹配 + 证据），不是用户可配置项，也不做目录级整树豁免。凭据分离与运行时注入是推荐方式，不强制厂商；敏感内容审批提示应提供无明文替代，不能伪造脱敏文件正文。

Git/链式删除/云/数据库/容器/系统的候选逐命令矩阵、Secret Manager 厂商子命令及内置名单扩展未经确认不默认启用。删除数量是固定的 20 文件硬门禁（超限拒绝，可早停「至少 21」），不是可配置阈值；执行通道无法分析时显式拒绝，不把 agent 自报、dry-run 或审批当作删除授权；检查与执行间 FS 竞态是已知边界，不声称并发下原子执行。git 分级（R-15）由 `assessGit`/`git-evidence` 实现，证据缺失 fail-closed。

## 验收边界

AC-01：已确认规则的危险正例和正常反例成对通过，危险用例使用合成/隔离目标；删除计数 `<=20`/`>20`、未知拒绝、白名单命中与伪装/未知条目成对覆盖。

AC-02：同调用关联、提前短路、并发、取消、卸载、超时与迟到批准均不能绕过最终门禁。

AC-03：分别记录 Windows 与 Linux 的真实运行结果、解析资源与延迟测量，未运行平台明确缺证据。

AC-04：分别验证 Native/PTC 的 content、结构化 value、错误、额外上下文、日志和持久化出口；披露仍可能含明文的面。不承诺清除已记录参数、历史 transcript 或已经发送的数据。

AC-05：新包安装、自动设置页、实例激活与功能门禁独立留证；单测、历史版本部署或二进制存在不能替代这些结果。
