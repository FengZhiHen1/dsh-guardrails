# dsh-guardrails 需求

本文规定产品定位、防护范围、判定行为与可观察验收。

来源为 DSR-025 的定位与判定模型、DSR-026 与 DSR-027 的执行面决策、DSR-017 与 DSR-018 的凭据防护、DSR-019 的删除计数，以及 DSR-017 与 DSR-025 的灾难身份。

## 定位

**本插件是 DSH 受管工具调用上的一道多面安全网**，不是 OS 沙箱，也不是策略闸门。前提假设：使用它的 agent **善意但会犯错**。因此它默认放行，只兜住「不可逆且高后果」的操作，低误报优先。

判定原则一条：**不可逆且高后果 → 拒绝或确认；可逆或低后果 → 放行**。任何确认必须列出具体范围（R-09）。

## 三面防护范围

插件同时防三类后果，三面互不替代：任何一面被放松，都不意味着其余两面随之放松。

| 面 | 防的后果 | 可观察到的防护结果 |
|---|---|---|
| 数据破坏 | 不可逆的数据丢失、批量删除、git 历史被销毁 | 灾难身份被拒绝；批量删除与不可枚举的删除转确认并列出范围；可证明可重建的产物清理不计入删除计数，正常放行 |
| 凭据与敏感信息 | 凭据与敏感文件外泄、扩散、篡改 | 对受保护文件的内容操作转确认并列出文件；受管工具结果中的高置信凭据默认打码；内联真实凭据的扩散风险被纠正型拒绝 |
| 不可控执行 | 已识别的动态执行入口或其他风险线索涉及无法判定的副作用 | 对执行面尽力分析，按可见风险证据及可核对的范围处置 |

## 判定模型（可观察行为）

按「不可逆 × 后果 × 可重建性」判定，动作只有三档：拒绝 / 确认 / 放行。判定结果由一次调用的全部证据得出，不按命令名或目录名分类。

| 情形 | 动作 |
|---|---|
| 灾难身份：真实宿主设备或卷、宿主 OS 根与系统树、真实 Git common-dir 主体、销毁 git 历史的子命令 | 拒绝（不可确认、不可配置覆盖） |
| 可证明可重建的产物（文件级或目录级，需证据，不因名称相同而豁免） | 不计入删除计数（同一次调用另有命中时按最高档） |
| 普通删除，目标可枚举且非豁免条目在放行阈值内（R-07） | 放行 |
| 批量删除，非豁免条目超过放行阈值（R-07） | 确认，列出删除范围 |
| 删除目标不可枚举（动态目标、通配） | 能说明具体范围时确认，并列出不可枚举部分（R-09） |
| 受保护文件与凭据的内容操作：读、写、清空、导出或复制、删、移走 | 确认，列出涉及文件 |
| 命令或 HTTP 参数直接内联高置信真实凭据，且有扩散风险与可行替代 | 拒绝（纠正型） |
| 执行面（PTC 程序、脚本、内联代码和动态执行） | 同等操作与风险证据适用相同判定，覆盖缺口和检查故障按 R-17 与「失败语义（可观察）」处置 |
| 未命中任何规则 | 放行 |

拒绝分绝对与纠正型：绝对拒绝只用于灾难身份，不能被确认或配置覆盖。确认只放行当前调用，不构成删除授权。同一次调用内出现多个命中时，按「判定顺序」取最高档。

## 判定顺序

1. **灾难身份最先判定**：命中即拒绝，短路其余全部判定。放行与豁免的短路不适用于灾难身份——目标即使同时可证明可重建，也仍然拒绝。
2. **可重建豁免只减计数；非豁免条目在放行阈值内 → 不阻断**：二者都只作用于删除计数，不掩盖同一次调用内的确认或拒绝命中；放行短路只在灾难身份判定之后生效。
3. **需要确认的命中 → 核对范围**。批量删除、目标不可枚举、受保护内容操作与无法判定的执行风险，能说明具体范围时确认（R-09）。
4. **其余调用 → 放行**，覆盖缺口按 R-17 留下诊断。

同一次调用内多个结论并存时按 **拒绝 > 确认 > 放行** 取最高：放行结论不得掩盖同一次调用内的确认或拒绝命中。

## 功能需求

| ID | 已确认需求 | 可观察验收 |
|---|---|---|
| R-01 | 以可安装的 DSH bundle 交付，配置持久化在 Profile | 目标组合下唯一有效插件行；包导入与激活实测通过 |
| R-02 | 动作分拒绝 / 确认 / 放行三档；拒绝分绝对（仅灾难身份）与纠正型；三者互不覆盖 | 拒绝给出规则号、证据、目标、原因与可行的下一步；确认给出具体范围；确认不能覆盖绝对拒绝 |
| R-03 | 只绝对拒绝高置信**灾难身份**：真实宿主块设备或卷的底层破坏、宿主 OS 根与核心结构的整体毁坏、真实 Git common-dir 主体的整体破坏、销毁 git 历史的子命令 | 镜像文件、普通数据卷、HOME、项目根、Linked Worktree 的 `.git` 指针不因词面被同等拒绝；灾难拒绝不可被确认或配置覆盖 |
| R-04 | 对 Profile 精确文件与内置敏感文件名单的直接内容操作——读、导出或复制、写、清空、删、移走——单次限时确认；内置名单只覆盖高置信文件名（basename）与精确文件，不按目录段或后缀整类拦截 | 确认只放行当前调用；元数据列举与正常间接认证不因此触发确认 |
| R-05 | 普通未标记 `.env` 不自动保护；标记归 Profile，不信任工作树的自声明 | 被标记的目标命中保护；相邻文件、目录与模板不因名称误伤 |
| R-06 | 正常非强制 `git worktree remove` 不因回收工作树本身被拒绝；待删条目按 R-07 分档；工作树存在未提交或未跟踪改动、或处于分离 HEAD 时升级为确认；确认待删树内实际存在受保护文件时，因该内容删除升级为确认 | 阈值内的干净工作树回收直接放行；回收不要求加 `--force`；脏树或受保护内容触发确认而非静默删除 |
| R-07 | **删除分档**：可证明可重建的产物不计入计数；非豁免条目 ≤20 放行；`>20` 或目标不可枚举时确认并列范围；灾难身份拒绝 | 可重建批量清理放行；普通少量删除放行；批量与动态删除触发确认且范围可核对；不声称精确总数或并发原子 |
| R-08 | 纠正型拒绝需可靠操作证据、高后果机制与任务可达的安全替代同时成立 | 命令关键词、目录名或文件数量不能单独替代可靠操作证据 |
| R-09 | 确认必须列出**具体范围**（文件或目录清单、计数、受保护命中，以及无法枚举的部分）；插件自有确认有有限等待时间；`never`、拒绝、超时、取消、不可用均不执行；确认不等于删除授权，确认后重新盘存 | 无迟到批准复活；重复调用重新确认；不列范围的确认视为不合格 |
| R-10 | 受管工具结果中的高置信真实凭据默认完整打码 | 不显示凭据的前后缀；打码不额外增加确认或拒绝；保持非秘密诊断与成功/失败语义 |
| R-11 | 高置信直接内联真实凭据、且存在扩散风险与可行替代时纠正型拒绝 | 变量引用、占位符、示例与正常间接认证不因关键词被拒绝 |
| R-12 | 支持 Windows 与 Linux 对应的受管 Shell；检查服务不可用时按失败语义安全处理 | 分平台验证故障、协议与身份缺失；不因无法解析而放行含删除候选的调用 |
| R-13 | **默认放行**：命令执行面中不产生删除的未建模程序、`copy` 与常规 git 操作放行；只读命令不因未知选项、循环或成员访问被拒绝 | 只读命令不被误拒；`copy` 与常规 git 放行 |
| R-14 | **可重建豁免（证据制）**：能证明归属与可再生的产物（文件级与目录级）不计入删除计数；判据是证据而非名称；受保护文件与灾难身份始终生效 | 命中证据才放行；伪装成可重建的用户数据照常计数；不因目录名相同而豁免 |
| R-15 | **git 分级**：常规 git 操作放行；销毁 git 历史的子命令拒绝（灾难身份）；`clean`、`restore <paths>`、`worktree remove <path>` 经证据计数后按 R-07 分档 | 常规 git 放行；销毁历史被拒绝；批量或工作树不干净触发确认；证据缺失按失败语义处理 |
| R-16 | **拦截前门**：删除分析覆盖受管命令、终端发送、PTC 程序与目标组合中已接入的文件工具。文件工具的删除与移走源操作进入同一删除分档。MCP 及其他未接入工具沿用 DSH 权限流程 | 命令、程序和已接入文件工具中的等价删除按 R-07 分档。覆盖清单与目标组合的可用工具一致。未知工具本身不触发 Guardrails 拒绝 |
| R-17 | **执行面分析**：对 PTC 程序、Shell 脚本文件、内联代码与动态执行尽力分析；解释器脚本文件（`python`、`node`、`tsx`、`deno`、`bun` 等）正文不在覆盖范围，记录覆盖缺口并放行。相同的操作及风险证据适用同一判定。存在覆盖缺口且其他检查未发现风险证据时放行，并记录未覆盖部分 | 等价操作得到相同判定。无分析器的脚本在无其他风险证据时放行并留下覆盖诊断；解释器脚本文件正文不产生内容判定。无法判定的风险候选按已知范围处置，确认只作用于本次调用（R-09） |
| R-18 | **规则可解释与可配置**：规则元数据携带意图与严重度；每次拒绝或确认的对外输出至少含规则号、证据与具体范围；可按规则号放行（`rules.<id>.allowlist`）并支持一次性放行（`allowOnce`）；灾难身份规则不可被配置或确认覆盖；项目层配置只能收紧 | 规则号放行按规则生效；项目配置无法关闭灾难规则或放宽受保护项；拒绝与确认文案含规则号与证据 |
| R-19 | **数据-执行区分**：仅在实际执行位置识别删除；文档、注释与参数数据中的删除字样不触发 | `grep "rm -rf"` 一类只读或数据命令放行；真实执行位置仍被识别 |
| R-20 | **配置健壮**：配置非法或含未知键时降级为保护性默认，守卫与打码仍生效，不整体停摆 | 坏配置下防护仍工作；不因配置错误导致保护整体消失 |

## 约束与非目标

约束：

- 只对进入 DSH `ctx.tools` 的调用承诺防护；不提供 OS 沙箱，也不提供抗同身份对抗的隔离。
- 判定无状态：不引入跨调用状态或 journal；跨回合的删除时序不属判定面。
- 名单硬编码：识别集合随代码交付，不提供用户自加路径名单。
- 内置敏感名单为高置信 basename 与精确文件，用户 Profile 的精确路径经 `sensitiveFiles` 补充（R-04）；不接受通配、相对路径或目录级整类拦截。
- 敏感内容的确认提示应提供无明文的替代路径，且不得伪造或生成脱敏后的文件正文。

非目标：

- 不追求覆盖所有删除或所有副作用。
- 不把插件做成策略闸门（默认收紧）或沙箱。
- 不开放用户自加的可重建名单（识别集合内置，以证据为准）。
- 不新增 Trusted Disposable Scope、用户可配置的清理目录 Profile 名单、构建目录注册表、全盘秘密扫描、外部 DLP 或自动 `.env` 迁移。

覆盖边界：

- 真正的边界是「不经 `ctx.tools` 直接调用 runtime service」；该直连路径不在覆盖内。
- 脚本正文按已声明的覆盖范围尽力分析。未建模的执行语义、远端或容器内的后续操作、云 SDK 与内嵌 SQL 属于覆盖局限。
- 经 MCP 暴露的文件系统工具若删除文件，删除分析看不到该操作；这是已接受的范围边界。
- 检查与执行之间存在文件系统竞态：不声称并发条件下原子执行。
- `$DSH_HOME` 配置面与会话日志的读写不在拦截范围内；由此形成的自解除通道是已知边界。

显式延期（未经确认不默认启用）：

- Git、链式删除、云、数据库、容器与系统的候选逐命令矩阵。
- Secret Manager 厂商子命令。
- 内置名单的扩展。

建议（非约束）：凭据分离与运行时注入是推荐做法，不强制厂商；实现者有更优路径时可偏离并记录理由。

## 失败语义（可观察）

| 失败点 | 期望行为 |
|---|---|
| 配置非法或含未知键 | 降级为保护性默认，守卫与打码仍生效（R-20） |
| 覆盖缺口 | 有有效检查结果时按风险证据继续判定。其他检查无风险证据则放行并记录缺口（R-17） |
| 已识别的风险候选无法判定 | 能说明具体范围时确认，范围无法说明时拒绝（R-09） |
| 已进入目标盘存后，计数或关键取证失败 | 拒绝。可重建证明不足的条目照常计数 |
| 必检调用缺少本次可信结果，或检查内部异常 | 拒绝本次调用并记录故障 |
| git 证据不可用、超时或返回未知 | 不执行该删除，按拒绝处理并说明原因（R-15） |

## 验收边界

AC-01：已确认规则的危险正例与正常反例成对通过，危险用例使用合成或隔离目标。至少覆盖：可重建批量清理放行、普通少量删除放行、批量删除确认并列范围、动态删除确认并列已知范围、灾难身份拒绝、受保护文件确认并列文件、数据-执行区分（`grep "rm -rf"` 放行、`rm -rf ./src` 识别）。

AC-02：同一调用内的关联、提前短路、并发、取消、卸载、超时与迟到批准均不能绕过最终判定；不列范围的确认视为不合格。

AC-03：分别记录 Windows 与 Linux 的真实运行结果、解析资源与延迟测量；未运行的平台明确标注缺少证据。

AC-04：分别验证 Native 与 PTC 的 content、结构化 value、错误、额外上下文、日志与持久化出口；披露仍可能含明文的面。不承诺清除已记录的参数、历史 transcript 或已经发送的数据。

AC-05：新包安装、自动设置页、实例激活与功能门禁独立留证；单测、历史版本部署或二进制存在不能替代这些结果。
