# dsh-guardrails 需求

## 目标与范围

在 DSH Full Access 的受管 AI 工具调用中降低意外泄密和高后果破坏风险，以少量可解释的 Deny、必要的限时 Ask 和正常 Allow 支持日常开发。不依赖 Auto Review 做安全语义判定；用户手工命令不受本插件拦截。源码已重构并通过本轮测试，Linux 与完整部署验收尚未完成。

## 功能需求

| ID | 已确认需求 | 可观察验收 |
|---|---|---|
| R-01 | 以可安装 DSH bundle 交付，Profile 持久配置 | 目标组合唯一有效插件行，包导入与激活实测通过 |
| R-02 | `Deny > Ask > Allow`；Deny 区分绝对与纠正型 | 拒绝给出证据、目标、原因与可行下一步；审批不能覆盖 Deny |
| R-03 | 只绝对禁止高置信真实宿主块设备底层灾难破坏、宿主 OS 根/核心结构整体毁坏、真实 Git common-dir 主体整体破坏 | 镜像文件、普通数据卷、HOME、项目根、Linked Worktree `.git` 指针不因词面被同等禁止 |
| R-04 | 对 Profile 精确文件与内置高置信凭据的直接内容读、导出/复制、写、清空、删、移走单次限时 Ask | 批准只放行当前调用；元数据与正常间接认证不因此审批 |
| R-05 | 普通未标记 `.env` 不自动保护；标记归 Profile，不信任工作树自声明 | 标记目标命中，相邻文件/目录与模板不因名称误伤 |
| R-06 | 正常非强制 `git worktree remove` Allow，由 Git 自身检查 | 仅高置信确认待删树内实际存在受保护文件时因该内容删除升级 Ask |
| R-07 | 普通文件/缓存/生成目录/局部 Git 清理默认 Allow | 无生成物白名单、来源证明、普通清理全量扫描或跨调用备份许可状态机 |
| R-08 | 纠正型 Deny 需可靠操作证据、高后果机制、任务可达的安全替代同时成立 | Unknown、命令关键词、目录名或文件数量不能单独造成拒绝 |
| R-09 | Guardrails 自有审批有有限等待；`never`、拒绝、超时、取消、不可用均不执行 | 无迟到批准复活；重复调用重新审批，其他来源审批不受本计时器影响 |
| R-10 | 高置信真实凭据的受管工具结果默认完整遮罩 | 不显示凭据前后缀，不因打码增 Ask；保持非秘密诊断与成功/失败语义 |
| R-11 | 高置信直接内联真实凭据且有扩散风险和可行替代时纠正型 Deny | 变量引用、占位符、示例和正常间接认证不因关键词拒绝 |
| R-12 | 支持 Windows/Linux 对应受管 Shell，并在检查服务不可用时安全拒绝 | 分平台验证故障/协议/身份缺失；有效语法的动态 Unknown 不自动 Deny |

## 约束与非目标

只对进入 DSH `ctx.tools` 的调用承诺防护，不提供 OS 沙箱或抗同身份对抗隔离。PTC direct Node、外部脚本内部、远端/容器后续操作、云 SDK 与内嵌 SQL 等不能借 Shell AST 宣称完整覆盖。

不新增 Trusted Disposable Scope、清理目录 Profile 白名单、构建目录注册表、全盘秘密扫描、外部 DLP 或自动 `.env` 迁移。凭据分离与运行时注入是推荐方式，不强制厂商；敏感内容审批提示应提供无明文替代，不能伪造脱敏文件正文。

Git/链式删除/云/数据库/容器/系统的候选逐命令矩阵、Secret Manager 厂商子命令及内置名单扩展未经确认不默认启用。文件数量只作为独立风险规则已命中的 Ask/纠正型 Deny 的辅助说明，不构成单独门禁；研究值 1000 不是正式阈值。

## 验收边界

AC-01：已确认规则的危险正例和正常反例成对通过，危险用例使用合成/隔离目标。

AC-02：同调用关联、提前短路、并发、取消、卸载、超时与迟到批准均不能绕过最终门禁。

AC-03：分别记录 Windows 与 Linux 的真实运行结果、解析资源与延迟测量，未运行平台明确缺证据。

AC-04：分别验证 Native/PTC 的 content、结构化 value、错误、额外上下文、日志和持久化出口；披露仍可能含明文的面。不承诺清除已记录参数、历史 transcript 或已经发送的数据。

AC-05：新包安装、自动设置页、实例激活与功能门禁独立留证；单测、历史版本部署或二进制存在不能替代这些结果。
