# dsh-guardrails 文档入口

## 当前状态与阅读顺序

**定位已确认，代码未跟上。** 插件目标是**多面安全网**（数据破坏 / 凭据与敏感信息 / 不可控执行三面），判定按「不可逆 × 后果 × 可重建性」只取三档：拒绝 / 确认 / 放行。该目标由 [DSR-025](decisions/DSR-025-定位重定位与判定模型重构.md) 确认；代码仍按旧策略运行，目标契约尚未编码。

当前实现的可见行为（以代码为准）：

- 灾难身份——真实宿主设备或卷、宿主 OS 根与系统树、真实 Git common-dir 主体、销毁 git 历史的子命令——直接拒绝，不可覆盖。
- 可识别的命令行删除按 20 个非豁免条目计数：`≤20` 放行，`>20` 拒绝。
- 凭据与敏感文件的内容操作走一次性限时确认；受管工具结果中的高置信凭据默认打码。
- 执行面：`run_code` 与内联代码一律拒绝，语言运行时脚本放行。
- MCP 与未审查工具默认拒绝。
- 配置只有 `sensitiveFiles`、`builtinSensitiveAsk`、`askTimeoutMs` 三个键；配置非法时插件挂载失败。

验证状态：源码与隔离 Runtime 已按旧行为验证通过（[历史快照](verification/2026-11-14-delete-gate.md)）。UI 走查、稳定环境门禁、Linux 与跨平台实跑、并发竞态尚未完成。

阅读顺序：

1. [需求](需求.md)：产品定位、三面防护范围、三档判定、功能需求 `R-01…R-20` 与验收语义。
2. [技术细节入口](technical-details/README.md)：机制文档的阅读顺序与分类。
3. 目标契约按 [规则模型](technical-details/规则模型.md)「判定顺序」节 → [架构重构设计](technical-details/架构重构设计.md)「总体架构」节 → 语言层与 Shell 机制文档依次展开。

## 当前实现与目标设计的差异

| 维度 | 当前实现 | 目标契约 | 依据 |
|---|---|---|---|
| 判定模型 | 三级：灾难拒绝 / `≤20` 放行、`>20` 拒绝 / 其余放行 | 三档：拒绝 / 确认 / 放行 | DSR-025 |
| 批量删除 | `>20` 拒绝 | `>20` 确认并列范围 | DSR-025、需求 R-07 |
| 可重建豁免 | 只有文件级；目录名不豁免 | 文件级 + 目录级证据制；仍不按名豁免 | 需求 R-14、规则模型「删除分档细节」节 |
| 拦截前门 | 未审查工具默认拒绝 | 只分析命令执行面；MCP 与非命令工具放行 | DSR-022、需求 R-16 |
| 执行面 | `run_code` 与内联代码一律拒绝 | 尽力分析后按删除分档处置 | DSR-026、需求 R-17 |
| 语言运行时脚本 | 放行，不做分析 | 识别脚本入口后交 provider 分析 | DSR-026、需求 R-17 |
| 动态删除目标 | 不可枚举即拒绝 | 转确认并列已知范围 | DSR-023、DSR-025、需求 R-07 |
| 配置模型 | 3 个键；非法配置挂载失败 | 配置 A：per-rule 开关、规则号放行、一次性放行、项目层只能收紧；非法配置降级 | 规则模型「配置模型」节、需求 R-18/R-20 |
| 内部架构 | 双策略路径、正则重猜选项 | 类型化命令 IR + 单一策略决策点 + 证据适配器 | 架构重构设计「总体架构」节 |

## 已知偏差与 missing evidence

- **目标契约未编码**：需求、规则模型、架构重构设计、跨语言删除分析、可重建豁免五份文档描述的目标尚未编码；Shell 解析文档的 AST 接入、包装解包、有界事实提取与执行身份关联为当前实现，其前门分类与单一策略决策点为目标。当前行为按上表左列运行，不能据目标契约推断现行行为。
- **UI 未走查**：设置页的输入、保存成功/失败反馈、info 展开、明暗主题与窄屏未在浏览器中验证；Inspect 只证明注册与 schema，不证明视觉与交互。
- **平台实跑缺失**：Linux x64/arm64 未真实运行，未采集性能分位数；平台交付目标不等于已运行通过。
- **误伤与漏拦率缺失**：没有人工标注的真实语料回放；合成用例通过率不能当作历史误伤率。
- **遮罩出口未实测**：Native finalizer、结构化 value/meta/error/additionalContexts 等出口未逐一实测，不承诺这些出口零泄漏。
- **并发不原子**：检查与执行之间存在文件系统竞态，不声称并发条件下原子执行。
- **稳定环境门禁未复验**：发布前置验证门禁中的组合断言与功能冒烟只在历史记录中部分留证。

## 需求 ID 含义变更说明

- 现行需求 ID 是 `R-01…R-20`，含义以[需求](需求.md)「功能需求」节为准。
- 历史 DSR 中的同名 ID 是**当时旧义**：DSR-006 与 DSR-009 的 `R-03` 指配置 schema、`R-07` 指破坏性子族；DSR-012 的 `R-15` 指命令文本分析的词法语义。
- 现行同名 ID 的含义不同：`R-03` 是灾难身份，`R-07` 是删除分档，`R-15` 是 git 分级。
- 读历史决策时按上下文理解旧义，不得据旧引用推断现行需求；冲突时以需求、规则模型与「历史决策前向指针」节为准。历史 DSR 原文不改。
