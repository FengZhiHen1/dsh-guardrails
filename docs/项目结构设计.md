# dsh-guardrails 项目结构设计

本文定义模块职责、依赖方向和设计文档目录。结构从 R-01、R-16、R-17、R-19 和 DSR-027 推导。

## 目录与职责

| 位置 | 职责 | 依赖边界 |
|---|---|---|
| 包根 | `package.json` 声明包入口、运行时依赖、Bundle 与 `cordis.patch.yml`；Host 入口转发适配层 | 包入口只暴露公开接入点 |
| Client 入口（需要自定义设置时） | 按公开契约注册设置界面 | 与 Host 分别加载 |
| `src/core/` | 分析与取证数据契约、核心规则、纯判定、诊断数据和凭据遮罩 | 仅依赖自身与语言运行时标准库，可在裸 Node 测试 |
| `src/adapter/` | DSH 工具与执行上下文适配、配置、确认、调用关联、最终门禁和结果出口 | 通过 DSH 公开契约取得宿主信息，组合分析、取证和核心判定 |
| `src/adapter/analysis/` | 统一分析入口、语言语法实现、共享的外部命令语义，以及所需的解析进程和只读源码读取 | 依赖核心契约。语言实现向统一入口报告子执行单元，再由入口分派 |
| `src/adapter/evidence/` | 文件身份、目标盘存、挂载、Git 与可重建证据 | 依赖核心契约，通过适配层提供的只读接口取得目标数据 |
| `vendor/` | 随包分发的解析器资产及校验资料 | 由分析层加载 |
| `test/` | 目标行为单测、各语言共用语料、宿主集成和交付夹具 | 测试依赖被验证模块 |
| `docs/` | 需求、项目定调、机制、决策、待办和验证记录 | 各级索引规定文档归属 |

## 文档目录

`docs/` 为单一设计根目录。需求和两份定调文档置于根目录。`technical-details/` 承载机制，`decisions/` 保存重大决策，`verification/` 保存各次验证的证据。未完成事项登记在根目录 `TODO.md`。

执行分析的共用契约有一个权威位置。语言语法说明按机制组织。积累多篇独立语法说明后可建立子目录，并同步所属索引。

## 依赖方向

Host 适配层把输入与上下文交给分析模块。分析模块根据输入单元选择语法实现。Host 将操作事实交给取证模块，再把观察结果交给核心判定。分析与取证通过数据契约交换信息。核心判定无 I/O，取证模块无判定能力。DSH 工具名与运行时对象留在 Host 适配层。

使用同一规则计算处理各语言的操作事实。仅在语法、API 或执行上下文确实变化时调整分析实现。新增语言应沿用现有输入输出契约，并用等价操作验收接入。

## 实施顺序与门禁

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| 1. 固定数据契约 | 统一分析单元、目标表达、取证结果和策略输入输出 | 用来自需求的合成事实验证同等证据一致判定、诊断、未知与故障分流 |
| 2. 建立最小闭环 | 选一个经过验证的 DSH 工具，接通分析、取证、决策与门禁 | 在隔离 Runtime 验证本次调用关联、前置短路、取消及确认复核 |
| 3. 扩展入口和语言 | 接入有确证工具契约的入口与通过验证的语法实现 | 用同一组操作、缺口与故障用例核对跨语言一致性。实际注册的入口各有验证记录 |
| 4. 验证交付组合 | 核对 Bundle、配置、设置页、运行时版本及平台 | 交付声明中的实际组合通过发布门禁 |

阶段顺序按依赖划分。每个已接通的入口汇入同一策略。一次交付可声明的语言与工具覆盖由实际验收确定。

## 结构验收

- 在裸 Node 环境以合成证据验证核心规则。
- 核对模块依赖。语法解析不能申请确认。目标取证不能输出判定。核心不能调用 DSH 服务。
- 增加一种语言并用同一策略用例验证。已接入语言的判定用例保持一致。
