# dsh-guardrails 技术栈设计

本文规定技术选型、目标宿主锚点、兼容范围与交付约束。Node.js、DSH、PowerShell 与 Bash 的基线按目标确定；Python 与 JavaScript/TypeScript 的分析器按「语言语法权威」节的选型交付，交付前须满足「分析器定版条件」。

## 运行时与关键库

目标宿主锚点为 **DSH `0.2.2-rc.2`**：它是唯一声明的目标基线，验收以该版本的实际契约与官方文档为依据。运行时锚点如下：

| 项 | 目标锚点 | 依据 |
|---|---|---|
| DSH | `0.2.2-rc.2` | DSH 安装包 `@deepseek-ai/dsh` 的版本与官方文档 |
| Node.js | `>=24.9.0`，采用 ESM。该下限来自宿主声明，不是本包独立测得的支持下界 | 目标宿主安装包的 `engines.node` 与 `type` |
| 宿主包版本 | 目标宿主 `0.2.2-rc.2` 解析为 `@deepseek-ai/cordis ~4.1.0`、`@deepseek-ai/dsh-settings 0.2.2-rc.2`、`@deepseek-ai/schemastery ~3.19.0`；本包声明与这些已解析的目标版本对齐 | 目标宿主安装包解析到的版本 |
| 配置 schema | 使用官方 Schemastery `Config`；默认值在 schema 的 `.default()`，不在安装行 | DSR-018 与官方配置契约 |

兼容区间不从旧清单继承。本包对 Node 与各宿主包的 peer 范围、以及 `0.2.2-rc.2` 之外的 DSH 兼容区间，须由目标宿主实测支撑后才能写入包声明；兼容矩阵测量登记在 [TODO](TODO.md)。取得实测证据前，包声明只锚定上表目标版本。

## 语言语法权威

每种语言选一套主语法权威，辅助符号工具只补充事实。解析失败按统一故障分类处置。各语言遵守同一分析契约（DSR-027）：对外提交同一组操作事实，允许各语言使用不同解析器与局部语法结构。

| 语言 | 选型 | 理由 |
|---|---|---|
| PowerShell | 官方 `System.Management.Automation.Language.Parser.ParseInput`，由可信、惰性启动的持久 `pwsh` 辅助进程提供 | 与原生语法对齐，覆盖参数、重定向与作用域。依据 DSR-017 |
| Bash | 官方 `mvdan/sh` 的 `shfmt` typed JSON AST，固定 `v3.12.0` | 版本与协议受控，语法与执行语义同源。依据 DSR-017 |
| Python | CPython 标准库 `ast` 为语法权威；符号解析限定为[跨语言删除分析](technical-details/跨语言删除分析.md)「符号绑定与别名」定义的有界别名与局部摘要 | 标准库随运行时交付，无额外供应链；有界符号范围与操作映射需求匹配 |
| JavaScript/TypeScript | TypeScript Compiler API，提供语法与有界符号信息；符号范围同 Python 行，不做完整类型推断 | 同一 API 覆盖两种语法，符号能力与绑定表对齐 |

## 平台与交付约束

- PowerShell 分析需要可信 `pwsh`。辅助进程从受信运行环境启动，待审文本通过数据通道交给解析器，不执行待审脚本。
- `shfmt` 二进制随包分发，固定 `v3.12.0`，目标平台为 **Windows x64、Linux x64 与 Linux arm64**（DSR-017）。加载时核对资产校验元数据，调用过程中不下载，也不要求目标机安装 Go 或 Bash。升级版本须复验 typed JSON 契约。
- 第三方组件在公开分发前须具备可再分发的许可并固定版本。声明的交付平台以实际运行记录验证；文件存在或打包成功不代表平台已运行通过。
- 可选补丁入口使用目标 DSH 版本对应的 `@deepseek-ai/dsh-fs-patch` 公开解析接口，与目标宿主锚点版本对齐；接入与兼容验证见 [TODO](TODO.md)「官方文件工具组合验收」。

## 分析器定版条件

1. 用同一组正反例验证运行器入口、语法角色、删除识别、别名、动态目标与错误状态。
2. 用已标注样本复核符号与跨文件引用的准确性，记录启动成本、p50/p95 延迟与预算耗尽结果。
3. 核对支持的运行时版本、依赖固定方式、公开许可与交付形态。

三项条件满足并形成可追溯记录后，对应分析器方可声明为已交付，并同步更新依赖声明与验证证据。超出既定符号范围的工具——Python 侧的 Jedi、Astroid、Pyright 与 JavaScript/TypeScript 侧的 ts-morph——是后续评估项：按同一条件取得证据后再决定是否纳入；未纳入前操作映射不依赖它们。证据取得与交付验证登记在 [TODO](TODO.md)。
